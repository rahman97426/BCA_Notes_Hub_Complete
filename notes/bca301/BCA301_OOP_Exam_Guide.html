Q. What is OOP? What are its main features?
📅 2017·2018·2019·2020·2024
▼
OOP (Object Oriented Programming) organises software design around objects rather than functions.

1. Encapsulation: Binding data + functions inside a class. Data protected from outside. 2. Abstraction: Hide complexity; show only essential features (ATM example). 3. Inheritance: Derived class gets properties of base class. Promotes code reuse. 4. Polymorphism: One name, many forms — function overloading, virtual functions. 5. Data Hiding: Private/protected access specifiers restrict unauthorised access. 6. Message Passing: Objects communicate by calling member functions: obj.show();
Q. Explain characteristics of Constructor and Destructor.
📅 2014·2017·2018·2019·2020·2021
▼
Constructor Characteristics: • Same name as class, no return type • Called automatically on object creation • Can be overloaded (Default, Parameterized, Copy) • Cannot be virtual
Destructor Characteristics: • Same name with ~ prefix: ~ClassName() • No return type, no parameters • Cannot be overloaded — only ONE destructor per class • Called automatically when object goes out of scope class Demo { public: Demo() { cout << "Constructor called\n"; } ~Demo() { cout << "Destructor called\n"; } }; int main() { Demo d; } // Both called automatically
Q. What is a Friend Function? Why is it required?
📅 2017·2021·2022·2024
▼
A friend function is NOT a member of a class but can access its private and protected members.

Why required? • To access private members of two different classes simultaneously • Essential for overloading << and >> stream operators • Share data between classes without inheritance class Demo { int x = 10; // private public: friend void show(Demo d); // declaration }; void show(Demo d) { cout << d.x; } // accesses private x int main() { Demo d; show(d); } // Output: 10 Note: Declared inside class with friend; defined outside like a normal function.

Q. What is an operator function? Describe its syntax.
📅 2014
▼
An operator function redefines how an operator works with user-defined types. Uses keyword operator.

Syntax (member function): ReturnType operator symbol (parameters) { // body } Example: class Complex { int r, i; public: Complex(int a,int b){r=a;i=b;} Complex operator+(Complex c) { // + overloaded return Complex(r+c.r, i+c.i); } void show(){cout<<r<<"+i"<<i;} }; • Cannot change precedence/associativity • Cannot create new operators • At least one operand must be user-defined type
Q. Write syntax for overloading << and >> with friend function.
📅 2014·2018
▼
Stream operators MUST be friend functions because the left operand is cout/cin (stream object), not the class object.

class Distance { int m; public: Distance(int x=0){m=x;} friend ostream& operator<<(ostream& os, Distance& d) { os << d.m << "m"; return os; } friend istream& operator>>(istream& is, Distance& d) { is >> d.m; return is; } }; int main() { Distance d; cin >> d; // uses operator>> cout << d; // uses operator<< }
Q. What are the restrictions on operator overloading?
📅 2018
▼
1. Cannot overload: :: . .* ?: sizeof typeid 2. Cannot change precedence or associativity 3. Cannot change arity (number of operands) 4. Cannot create new operators (e.g., ** for power) 5. At least one operand must be a user-defined type 6. =, (), [], -> can ONLY be overloaded as member functions 7. = (assignment) is NOT inherited by derived classes
Q. Explain operator overloading. Type conversion: basic→class and class→basic with examples.
📅 2014·2018·2019·2022
▼
Operator Overloading gives additional meaning to operators for user-defined types.

Binary + overloading — Complex Numbers: #include<iostream> using namespace std; class Complex { float r, i; public: Complex(float a=0,float b=0){r=a;i=b;} Complex operator+(Complex c){ return Complex(r+c.r,i+c.i); } Complex operator-(Complex c){ return Complex(r-c.r,i-c.i); } Complex operator*(Complex c){ return Complex(r*c.r-i*c.i,r*c.i+i*c.r); } void show(){ cout<<r<<"+i"<<i<<endl; } }; int main(){ Complex c1(3,4),c2(1,2); (c1+c2).show(); // 4+i6 (c1-c2).show(); // 2+i2 (c1*c2).show(); // -5+i10 } Type Conversion 1 — Basic to Class (Conversion Constructor): class Distance { int m; public: Distance(int x){m=x;} // Conversion constructor void show(){ cout<<m<<"m\n"; } }; int main(){ Distance d = 50; // int auto-converted to Distance d.show(); // 50m } Type Conversion 2 — Class to Basic (Conversion Operator): class Distance { int m; public: Distance(int x){m=x;} operator int(){ return m; } // Class→int }; int main(){ Distance d(100); int x = d; // Object auto-converted to int cout<<x; // 100 } Conclusion: Operator overloading + type conversion makes user-defined types behave like built-in types.

Q. What is abstract class? What is its benefit?
📅 2017·2018·2019·2022·2024
▼
An abstract class has at least one pure virtual function (= 0). Objects CANNOT be created.

class Shape { public: virtual void draw() = 0; // pure virtual → abstract class }; class Circle : public Shape { public: void draw() { cout << "Drawing Circle"; } // MUST implement }; Benefits: • Provides common interface for all derived classes • Forces derived classes to implement pure virtual functions • Achieves runtime polymorphism • Better program design and organisation

Q. Why are virtual functions needed? Explain pure virtual functions.
📅 2017·2019·2020·2021
▼
Without virtual: base pointer always calls base class function (wrong).
With virtual: calls derived class function at runtime (correct = runtime polymorphism).

class Base { public: virtual void show() { cout << "Base\n"; } }; class Derived : public Base { public: void show() { cout << "Derived\n"; } }; int main() { Base* p = new Derived(); p->show(); // Prints "Derived" ← runtime polymorphism! } Pure Virtual: virtual void f() = 0; → no body in base, forces derived to implement A class with even ONE pure virtual function becomes abstract
Q. What is a virtual destructor? Why is it needed?
📅 2021·2024
▼
Problem: Without virtual destructor, deleting derived object via base pointer only calls base destructor → memory leak!

class Base { public: virtual ~Base() { cout << "Base destroyed\n"; } // virtual! }; class Derived : public Base { public: ~Derived() { cout << "Derived destroyed\n"; } }; int main() { Base* p = new Derived(); delete p; // Output: Derived destroyed → Base destroyed (correct order) } Rule: If a class has any virtual function, ALWAYS make destructor virtual
Q. Explain all types of inheritance with block diagram and C++ example for each.
📅 2014·2017·2018·2021·2022·2024 — Most Repeated!
▼
Inheritance = deriving a new class from an existing class. Promotes code reuse.

1. Single Inheritance — One derived from one base: class Animal { public: void eat(){cout<<"Eating\n";} }; class Dog : public Animal { public: void bark(){cout<<"Bark!\n";} }; int main(){ Dog d; d.eat(); d.bark(); } 2. Multiple Inheritance — One derived from multiple bases: class A { public: void fa(){cout<<"A\n";} }; class B { public: void fb(){cout<<"B\n";} }; class C : public A, public B { }; int main(){ C obj; obj.fa(); obj.fb(); } 3. Multilevel Inheritance — Chain A→B→C: class A { public: void fa(){cout<<"A\n";} }; class B : public A { public: void fb(){cout<<"B\n";} }; class C : public B { public: void fc(){cout<<"C\n";} }; // C can access fa(), fb(), fc() 4. Hierarchical — Multiple derived from one base: class Shape { }; class Circle : public Shape { }; // all inherit Shape class Square : public Shape { }; class Triangle : public Shape { }; 5. Hybrid Inheritance — Mix of types; uses virtual to solve diamond: class A { public: int x; }; class B : virtual public A { }; // virtual keyword solves diamond class C : virtual public A { }; class D : public B, public C { }; int main(){ D obj; obj.x=10; cout<<obj.x; } // No ambiguity! Conclusion: Inheritance is the core of OOP. Virtual base class solves the diamond problem in hybrid inheritance.
Q. Write a program showing constructors in inherited classes and virtual functions with dynamic binding.
📅 2022·2024
▼
Constructors in Inherited Classes: #include<iostream> using namespace std; class Base { public: Base(int x){ cout<<"Base constructor: "<<x<<endl; } ~Base(){ cout<<"Base destructor\n"; } }; class Derived : public Base { public: Derived(int x,int y) : Base(x) { // calls base constructor cout<<"Derived constructor: "<<y<<endl; } ~Derived(){ cout<<"Derived destructor\n"; } }; int main(){ Derived d(10,20); // Base constructor: 10 // Derived constructor: 20 // Derived destructor ← reversed on exit // Base destructor } Dynamic Binding with Virtual Functions: class Shape { public: virtual void area()=0; // pure virtual }; class Circle : public Shape { float r; public: Circle(float x){r=x;} void area(){ cout<<"Circle area: "<<3.14f*r*r<<endl; } }; class Rect : public Shape { float l,b; public: Rect(float x,float y){l=x;b=y;} void area(){ cout<<"Rect area: "<<l*b<<endl; } }; int main(){ Shape* p; Circle c(5); Rect r(4,6); p=&c; p->area(); // Circle area: 78.5 p=&r; p->area(); // Rect area: 24 }

📅 2014·2017·2018·2021·2022
▼
Exception Handling handles runtime errors without crashing the program.

try: Code that might throw an exception throw: Generates (throws) an exception catch: Catches and handles the exception int divide(int a, int b){ if(b==0) throw "Division by zero!"; return a/b; } int main(){ try{ cout << divide(10,2) << endl; // 5 cout << divide(10,0) << endl; // throws! } catch(const char* msg){ cout << "Error: " << msg; } cout << "Program continues\n"; }

A function template is one generic function that works for any data type.

Q. Explain virtual base class — how it solves diamond problem.
📅 2020·2022
▼
Diamond Problem: Two parents inherit same grandparent → derived gets two copies → ambiguity.

class A { public: int x; A(){x=10;} }; class B : virtual public A { }; // virtual solves it class C : virtual public A { }; // virtual here too class D : public B, public C { }; int main(){ D obj; cout << obj.x; // 10 — No ambiguity, only ONE copy of A } Key: Write virtual in B and C (not in D) This ensures ONE shared copy of grandparent A in D's memory

Q. Define exception handling. Write program using try-catch-throw with constructor & destructor. Explain file operations.
📅 2014·2017·2018·2021
▼
Exception with Constructor/Destructor (Key: Stack Unwinding): #include<iostream> using namespace std; class Resource { public: Resource(){ cout<<"Constructor: Resource acquired\n"; } ~Resource(){ cout<<"Destructor: Resource released\n"; } }; void riskyFunc(){ Resource r; // Constructor called throw "Error!"; // Exception — destructor STILL called! } int main(){ try{ riskyFunc(); } catch(const char* e){ cout<<"Caught: "<<e<<endl; } } // Output: // Constructor: Resource acquired // Destructor: Resource released ← stack unwinding guarantees this! // Caught: Error! Random Access File Operations: #include<fstream> int main(){ fstream f("data.txt", ios::in|ios::out|ios::binary); f.seekg(0, ios::end); // go to end long size = f.tellg(); // get file size cout<<"Size: "<<size<<" bytes\n"; f.seekg(5, ios::beg); // jump to byte 5 char ch; f.get(ch); cout<<"Byte at 5: "<<ch<<endl; f.close(); } seekg(n,ios::beg/cur/end) — move READ pointer seekp(n,...) — move WRITE pointer tellg() — current read position  ·  tellp() — current write position

Name(){} // Default Name(int x){} // Parameterized Name(Name& n){} // Copy No return type, same name as class

~Name() { /* cleanup */ } ~ tilde prefix, no parameters Only ONE destructor per class Make virtual if class has virtual functions

// Member (binary: 1 arg) T operator+(T o){} // Friend (binary: 2 args) friend T operator+(T a,T b){} // Stream (MUST be friend) friend ostream& operator<< (ostream& os, T& o){}

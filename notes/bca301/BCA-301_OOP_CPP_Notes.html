One-Liner Definitions

Class: user-defined data type (blueprint) that groups data and functions.
Object: an instance (variable) of a class.
Data hiding: keeping data private so outsiders cannot touch it directly.
Encapsulation: wrapping data and functions together in one unit (class).
Abstraction: showing only essential features and hiding complexity.
Message passing: objects talk to each other by calling member functions.
Constructor: special function with the same name as class, called automatically when an object is created.
Destructor: special function with ~ before class name, called automatically when an object is destroyed.
Inline function: body is substituted at the call place to save call overhead.
Friend function: non-member function that can access private and protected members.
Static member: one copy shared by all objects of the class.
Container class: class that holds a collection of objects (example: vector).
Proxy class: class that gives a limited interface to hide the real class.
Garbage collection: automatic memory cleanup; C++ does not have it, programmer uses delete.

Column 2: 4-Mark Short Answers

The scope resolution operator (::) links a member with its class, or accesses a global variable hidden by a local one. It is used to define a member function outside the class.

class A { public: void show(); };
void A::show() { cout << "Hello"; }

An inline function is declared with the keyword inline. The compiler replaces the function call with the function body, so function-call overhead is saved and speed improves. Use it only for small functions.

inline int square(int x) { return x * x; }

A static data member is declared with static. Only one copy exists for all objects, and it is created before any object. It is defined outside the class: int A::count = 0;. Benefit: useful for counting objects and sharing common data.

this is an implicit pointer available in every non-static member function. It holds the address of the object that called the function. Use: to return the current object (return *this;) or to separate member and parameter names.

C is a procedural language (functions only). C++ is object-oriented (classes, objects, overloading, inheritance). Key difference: C++ groups data and functions into a class.

// --- C style ---
#include <stdio.h>
void greet() { printf("Hello, C!\n"); }
int main() { greet(); return 0; }

// --- C++ style ---
#include <iostream>
using namespace std;
class Greeter {
public:
    void greet() { cout << "Hello, C++!" << endl; }
};
int main() { Greeter g; g.greet(); return 0; }

A token is the smallest unit of a C++ program that is meaningful to the compiler. The compiler splits the source code into tokens before processing.

  • Keywords: reserved words like int, class, for, return, virtual.
  • Identifiers: user-defined names like roll, Student, show.
  • Constants / Literals: 10, 3.14, 'A', true, "Hello".
  • Operators: +, -, *, <<, ::, ->, =.
  • Punctuators / Separators: {, }, ;, ,, (, ).

A proxy class is a class that acts as a stand-in or interface to another (real) class. It provides limited or controlled access to the real class and hides its implementation details.

  • Also called a wrapper, surrogate, or representative class.
  • Use case: lazy initialisation — load the heavy object only when actually needed.
  • C++ smart pointers (unique_ptr, shared_ptr) are real-life proxy classes for raw pointers.
  • Advantage: hides complexity, controls access, saves memory until needed.
class Image { public: void show() { cout << "Showing image\n"; } };
class ImageProxy {
    Image* real;
public:
    ImageProxy() { real = nullptr; }
    void show() {
        if (!real) real = new Image();   // lazy load
        real->show();
    }
};

Ambiguity in C++ occurs when the compiler cannot decide which function or member to call because two or more candidates match equally.

  • Multiple inheritance: two base classes have the same function name show(). Calling obj.show() is ambiguous.
  • Resolution 1: Use scope resolution operator: obj.A::show();
  • Resolution 2: Override the function in the derived class.
  • Resolution 3: Use a virtual base class to avoid duplicate copies.
  • Function overloading ambiguity: when implicit type conversion makes two overloaded functions equally good. Fix by using explicit casting.

Introduction

Programming paradigm means a style of writing programs. C++ supports both procedural and object-oriented style.

Definition

OOP is a method of programming in which a program is built from objects that contain both data and functions.

Points: Features of OOP
  • Class and Object: class is blueprint, object is instance.
  • Encapsulation: data and functions bound together.
  • Data hiding: private data is protected from outside use.
  • Abstraction: only necessary details are shown.
  • Inheritance: new class acquires properties of an old class (reusability).
  • Polymorphism: one name, many forms (overloading, virtual functions).
  • Dynamic binding: function to run is decided at run time.
  • Message passing: objects communicate through function calls.

Introduction

When an object is created it needs initial values. A constructor does this job automatically.

Definition

A constructor is a special member function with the same name as the class that initialises an object.

Points: Characteristics and Types
  • Same name as class, no return type (not even void).
  • Called automatically at object creation; normally in the public section.
  • Can be overloaded and can have default arguments; cannot be virtual or inherited.
  • Default constructor: no arguments. Student() { roll = 0; }
  • Parameterized constructor: takes arguments. Student(int r) { roll = r; }
  • Copy constructor: makes an object from another object. Student(const Student &s) { roll = s.roll; }
  • Destructor ~Student(): no arguments, no return type, one per class. If not written, the compiler creates an empty destructor.
  • Copy constructor is called when an object is initialised from another, passed by value or returned by value. Write your own when the class has pointers (deep copy).
  • If only a parameterized constructor exists and an object is made with no arguments, it is a compile-time error.
Program

Constructor, copy constructor and destructor together:

#include <iostream>
using namespace std;
class Distance {
    int feet, inches;
public:
    Distance(int f = 0, int i = 0) {          // parameterized + default values
        feet = f; inches = i;
        cout << "Constructor called\n";
    }
    Distance(const Distance &d) {             // copy constructor
        feet = d.feet; inches = d.inches;
        cout << "Copy constructor called\n";
    }
    void show() { cout << feet << " ft " << inches << " in\n"; }
    ~Distance() { cout << "Destructor called\n"; }
};
int main() {
    Distance d1(5, 8);
    Distance d2 = d1;
    d1.show();
    d2.show();
    return 0;
}
Conclusion

Constructors and destructors manage object creation and cleanup safely.

Introduction

Private members cannot be used outside the class, but sometimes an outside function needs them.

Definition

A friend function is a non-member function declared inside the class with the keyword friend, which can access private and protected members.

Points
  • Declared inside the class, defined outside without :: and without friend.
  • Not called with object and dot; objects are passed as arguments.
  • Can be a friend of more than one class (useful to work on two classes).
  • Needed for overloading << and >>.
  • Demerit: breaks data hiding, so use carefully.
Program

Friend function printing a private member:

#include <iostream>
using namespace std;
class Box {
    int width;
public:
    Box(int w) { width = w; }
    friend void printWidth(Box b);
};
void printWidth(Box b) { cout << "Width = " << b.width; }
int main() { Box b(10); printWidth(b); return 0; }
// Output: Width = 10
Conclusion

Friend functions give controlled outside access to private data.

Introduction

Normally each object of a class has its own separate copy of every data member. But sometimes we need data that is shared by ALL objects. Static members solve this.

Definition

A static data member is a variable shared by all objects of the class (only ONE copy exists). A static member function is a function that can be called without creating an object and can only access static members.

Points: Static Data Member
  • Declared with static inside the class and defined outside: int A::count = 0;
  • Only ONE copy regardless of how many objects are created.
  • Exists before any object is created and destroyed after all objects are destroyed.
  • Used for: counting objects, sharing common configuration, singleton pattern.
  • Static member function: declared as static void show(), called as ClassName::show().
  • Static function has NO this pointer — it does not belong to any single object.
  • A static function can only access static data members, not normal (instance) members.
  • Significance: saves memory, provides class-level (shared) state, accessible without an object.
Program

Counting student objects automatically using static member:

#include <iostream>
using namespace std;
class Student {
    int roll;
    static int count;          // one shared copy
public:
    Student(int r) { roll = r; count++; }
    ~Student()     { count--; }
    static void showCount() {  // no object needed
        cout << "Total Students: " << count << endl;
    }
};
int Student::count = 0;        // definition outside class
int main() {
    Student::showCount();      // 0
    Student s1(1), s2(2);
    Student::showCount();      // 2
    {
        Student s3(3);
        Student::showCount();  // 3
    }                          // s3 destroyed here
    Student::showCount();      // 2
    return 0;
}
Conclusion

Static members are essential for managing class-level shared state without using global variables.

An operator function defines the new meaning of an operator for a class. Syntax:

return_type operator op (arguments) { /* body */ }
// Example
Complex operator+(Complex c);

Both are friend functions defined outside the class. They return the stream by reference so chaining like cout << a << b; works.

friend ostream& operator<<(ostream &out, const ClassName &obj);
friend istream& operator>>(istream &in, ClassName &obj);

As a member function: one argument (left operand is the calling object). As a friend function: two arguments. For a unary operator: member = zero, friend = one.

  • Only existing operators can be overloaded; new symbols cannot be created.
  • ::, ., .*, ?:, sizeof cannot be overloaded.
  • Number of operands and precedence cannot change.
  • At least one operand must be a user-defined type.
  • =, (), [], -> can be overloaded only as member functions.

Column 3: 12-Mark Long Answers

Introduction

Normal operators work only on built-in types. Operator overloading lets them work on objects also.

Definition

Operator overloading means giving an operator an additional meaning for a user-defined type, without changing its original meaning.

Points
  • Done with an operator function: return_type operator op (args).
  • Member function: left operand is the calling object (c3 = c1 + c2; becomes c1.operator+(c2)).
  • Friend function: used when the left operand is not our object (example: cout << obj).
  • Unary operators: prefix is operator++(), postfix is operator++(int) (dummy int).
  • Restrictions: :: . .* ?: sizeof cannot be overloaded; operand count and precedence cannot change; at least one operand must be a class type.
Program

Complex numbers with +, -, *, <<, >>:

#include <iostream>
using namespace std;
class Complex {
    float re, im;
public:
    Complex(float r = 0, float i = 0) { re = r; im = i; }
    Complex operator+(Complex c) { return Complex(re + c.re, im + c.im); }
    Complex operator-(Complex c) { return Complex(re - c.re, im - c.im); }
    Complex operator*(Complex c) {
        return Complex(re * c.re - im * c.im, re * c.im + im * c.re);
    }
    friend ostream& operator<<(ostream &out, const Complex &c);
    friend istream& operator>>(istream &in, Complex &c);
};
ostream& operator<<(ostream &out, const Complex &c) {
    out << c.re << " + " << c.im << "i";
    return out;
}
istream& operator>>(istream &in, Complex &c) {
    in >> c.re >> c.im;
    return in;
}
int main() {
    Complex a(2, 3), b(4, 5);
    cout << "Sum  = " << a + b << endl;
    cout << "Diff = " << a - b << endl;
    cout << "Prod = " << a * b << endl;
    return 0;
}
Conclusion

Operator overloading makes object code short, readable and natural. It is compile-time polymorphism.

Introduction

Compiler converts basic types automatically, but for classes we must tell it how.

Definition

Type conversion means changing data from one type to another. For classes it is done by a constructor (basic to class) and a conversion function (class to basic).

Points
  • Basic to Class: use a constructor with one argument.
  • Class to Basic: use a conversion function operator type().
  • Conversion function rules: must be a member, no return type, no arguments.
Example

Meter class converting from and to float:

#include <iostream>
using namespace std;
class Meter {
    float m;
public:
    Meter() { m = 0; }
    Meter(float x) { m = x; }          // basic -> class
    operator float() { return m; }     // class -> basic
};
int main() {
    Meter a;
    a = 5.5;            // float to Meter (constructor called)
    float f = a;        // Meter to float (conversion function)
    cout << f;          // 5.5
    return 0;
}
Conclusion

Constructors convert to class type; conversion functions convert from class type.

Column 2: 4-Mark Short Answers

It is an "is-a" relationship. The derived class gets all accessible members of the base class and can add its own members or override base functions. The base class stays unchanged. Syntax: class Derived : public Base { };

Super, base and parent are different names for the original class that gives its properties. Derived, child, sub and inherited class are names for the new class that receives them. So Base = Super = Parent and Derived = Sub = Child.

Constructors: base class first, then derived class. Destructors: derived class first, then base class (reverse order). Arguments for a base constructor are passed with an initialiser list: Derived(int a, int b) : Base(a) { }.

When a derived class defines a function with the same name, same arguments and same return type as a base class function, the derived version replaces the base one for derived objects. With virtual, the correct version is chosen at run time.

Abstract class: contains at least one pure virtual function (= 0). Its object cannot be created. It forces derived classes to implement the function.

  • Pure virtual function: virtual void draw() = 0;
  • Virtual base class: base declared with virtual keyword in intermediate classes to avoid the diamond problem (duplicate copies in hybrid inheritance).
  • Both improve OOP design: abstract class gives a common interface; virtual base removes ambiguity.
// Abstract class
class Shape { public: virtual void draw() = 0; };   // can't create Shape object
class Circle : public Shape { public: void draw() { cout << "Circle\n"; } };

// Virtual base class (diamond fix)
class A { public: int x; };
class B : virtual public A { };
class C : virtual public A { };
class D : public B, public C { };  // only ONE copy of A::x

Column 3: 12-Mark Long Answers

Introduction

Writing the same code again and again wastes time. Inheritance gives reusability.

Definition

Inheritance is the process of creating a new class (derived) from an existing class (base) so that the derived class acquires the base class properties.

Points: Types of Inheritance
  • Single: one base, one derived. class B : public A {};
  • Multiple: more than one base, one derived. class C : public A, public B {};
  • Multilevel: chain A to B to C. class B : public A {}; class C : public B {};
  • Hierarchical: one base, many derived. class B : public A {}; class C : public A {};
  • Hybrid: combination of two or more types (ambiguity can come; solved by virtual base class).
Single:        A --> B
Multiple:      A --> C <-- B
Multilevel:    A --> B --> C
Hierarchical:  A --> B
               A --> C
Hybrid:        A --> B --> D
               A --> C --> D
Example (Multilevel)

An object of Topper can call name(), roll() and rank().

class Person  { public: void name() { cout << "Person\n"; } };
class Student : public Person  { public: void roll() { cout << "Student\n"; } };
class Topper  : public Student { public: void rank() { cout << "Topper\n"; } };
Conclusion

Inheritance gives code reuse, saves time and makes programs easy to extend.

Access specifiers control who can use a member.

private = only same class; protected = same class and derived classes; public = everywhere.

Points
  • Private members of base are never directly accessible in the derived class (use public / protected functions).
  • Default inheritance mode for a class is private.
  • Public inheritance is the most common ("is-a" relation).

With public inheritance, y is protected and z is public in B; x is not accessible.

Choose the inheritance mode to control how much of the base class is exposed.

Introduction

In hybrid inheritance, the final class may receive two copies of the same grand-base class. This is the diamond problem and causes ambiguity.

Definition

A virtual base class is a base class declared with the keyword virtual in the derived classes so that only one copy reaches the final class.

Points: Ambiguity and how to resolve it
  • If two base classes have a function with the same name, obj.show() is ambiguous.
  • Resolve 1: use the scope resolution operator, obj.A::show();
  • Resolve 2: override the function in the derived class.
  • Resolve 3: use a virtual base class for the diamond case.
Example

Without virtual, d.x gives an ambiguity error. With virtual, only one x exists.

#include <iostream>
using namespace std;
class A { public: int x; };
class B : virtual public A { };
class C : virtual public A { };
class D : public B, public C { };
int main() {
    D d;
    d.x = 10;                 // no ambiguity, only one copy of x
    cout << d.x;
    return 0;
}
Conclusion

Virtual base class removes duplication and ambiguity in hybrid inheritance.

Column 3: 12-Mark Long Answers

Introduction

When a base pointer points to a derived object, we want the derived function to run. Virtual functions do this.

Definition

A virtual function is a member function of the base class declared with virtual and redefined in the derived class.

Points
  • Steps: (1) declare virtual in base, (2) redefine in derived with same signature, (3) call through a base class pointer.
  • Dynamic binding: call is resolved at run time using the real object type. Without virtual, static binding happens at compile time.
  • Abstract class: has a pure virtual function (= 0); object cannot be created, pointers can.
  • Virtual destructor: write virtual ~Shape(){} so delete p; also runs the derived destructor (no memory leak).
Program

Base pointer calling the derived function:

#include <iostream>
using namespace std;
class Shape {
public:
    virtual void draw() { cout << "Drawing shape\n"; }
    virtual ~Shape() { }
};
class Circle : public Shape {
public:
    void draw() { cout << "Drawing circle\n"; }
};
int main() {
    Shape *p;
    Circle c;
    p = &c;
    p->draw();     // Drawing circle (dynamic binding)
    return 0;
}
Conclusion

Virtual functions give run-time polymorphism.

Introduction

Programs can fail at run time (divide by zero, file not found). We should handle these safely.

Definition

Exception handling is a mechanism to detect and handle run-time errors so that the program does not crash.

Points: Keywords and Points
  • try: block that contains code that may cause an error.
  • throw: sends (raises) the exception.
  • catch: block that receives and handles the exception.
  • Many catch blocks can follow one try; catch(...) catches all types.
  • When an exception is thrown, objects made inside try are destroyed (destructors are called) before catch runs.
  • User-defined exception: a class can be thrown. Needed when built-in types cannot describe the error (invalid age, low balance).
Program

Exception with constructor / destructor and a user-defined exception:

#include <iostream>
#include <string>
using namespace std;
class Test {
public:
    Test()  { cout << "Constructor\n"; }
    ~Test() { cout << "Destructor\n"; }
};
class MyException {
public:
    string msg;
    MyException(string m) { msg = m; }
};
int main() {
    try {
        Test t;
        int a = 10, b = 0;
        if (b == 0) throw "Division by zero";
        cout << a / b;
    }
    catch (const char *m) {
        cout << "Caught: " << m << endl;
    }
    try {
        int age = 15;
        if (age < 18) throw MyException("Age must be 18 or more");
    }
    catch (MyException &e) {
        cout << "User-defined exception: " << e.msg << endl;
    }
    return 0;
}
Conclusion

Exception handling separates error handling from normal code and makes programs reliable.

Introduction

Data in variables is lost when the program ends. Files store data permanently.

Definition

File handling is reading from and writing to disk files using stream classes from <fstream>.

Points
  • Stream classes: ifstream (input), ofstream (output), fstream (both).
  • Steps: create stream object, open file, read / write, close().
  • Sequential access: data read / written in order from the start (<<, >>, get(), put(), getline()).
  • Random access: any position reached directly: seekg(pos) / seekp(pos) move get / put pointer; tellg() / tellp() give the position.
  • Other functions: eof(), fail(), good(), close().
Program

Write, read and random access:

#include <iostream>
#include <fstream>
#include <string>
using namespace std;
int main() {
    // Write
    ofstream fout("student.txt");
    fout << "Aman 85" << endl;
    fout << "Riya 90" << endl;
    fout.close();

    // Read (sequential)
    ifstream fin("student.txt");
    string name; int marks;
    while (fin >> name >> marks)
        cout << name << " " << marks << endl;
    fin.close();

    // Random access
    ifstream f("student.txt");
    f.seekg(0, ios::end);              // go to end
    long size = f.tellg();             // position = file size
    cout << "File size = " << size << " bytes" << endl;
    f.seekg(0, ios::beg);              // back to start
    f.close();
    return 0;
}
Conclusion

File handling gives permanent storage and flexible access to data.

Introduction

A function like max(int, int) must be rewritten for float, char etc. Templates solve this.

Definition

A template lets us write one generic function or class that works for any data type.

Points
  • Need: removes code repetition, saves time, gives type-safe generic programming.
  • Normal to template: write template <class T> before the function and replace the data type with T.
  • Normal: int minimum(int a, int b) { return (a < b) ? a : b; }
  • Template: template <class T> T minimum(T a, T b) { return (a < b) ? a : b; }
  • Class template (generic class) works the same way for classes.
Program

Function template and class template:

#include <iostream>
using namespace std;
template <class T>
T minimum(T a, T b) { return (a < b) ? a : b; }

template <class T>
class Box {
    T v;
public:
    Box(T x) { v = x; }
    T get() { return v; }
};
int main() {
    cout << minimum(10, 20) << endl;        // int
    cout << minimum('a', 'z') << endl;      // char
    cout << minimum(3.5f, 2.1f) << endl;    // float
    Box<int> b1(5);
    Box<float> b2(2.5f);
    cout << b1.get() << " " << b2.get() << endl;
    return 0;
}
Conclusion

Templates give code reuse for different data types.

Introduction

Displaying data clearly requires proper formatting. C++ provides a convenient tool called manipulators for this.

Definition

Manipulators are special functions / objects used with << and >> operators to format the input and output of a program. They are used as if they are data items in an output or input expression.

Points: Types of Manipulators
  • Header file: <iomanip> for parameterised and <iostream> for non-parameterised manipulators.
  • endl: inserts a newline character and flushes the buffer. cout << "Hi" << endl;
  • setw(n): sets the field width for the NEXT output only. cout << setw(10) << "Aman";
  • setprecision(n): sets the number of decimal places. cout << setprecision(2) << 3.14159; → 3.14
  • setfill(c): sets the fill character for empty spaces in setw. cout << setfill('*') << setw(8) << 42; → ******42
  • left / right: sets alignment of output inside the field. cout << left << setw(10) << "Hi";
  • hex / oct / dec: prints integers in hexadecimal / octal / decimal base.
  • fixed: prints floating numbers in fixed notation (not scientific). cout << fixed << setprecision(2) << 3.14159;
  • scientific: prints in scientific notation. cout << scientific << 3.14159; → 3.14e+00
  • boolalpha: prints bool as true / false instead of 1 / 0.
  • flush: flushes the output buffer without a newline.
  • ws: skips leading whitespace on input.
Program

Demonstrating important manipulators together:

#include <iostream>
#include <iomanip>
using namespace std;
int main() {
    // setw and setfill
    cout << setfill('-') << setw(20) << "" << endl;
    cout << setfill(' ') << setw(10) << left << "Name"
         << setw(5) << "Age" << endl;
    cout << setfill('-') << setw(20) << "" << endl;
    cout << setfill(' ') << setw(10) << left << "Aman"
         << setw(5) << 21 << endl;

    // setprecision + fixed
    cout << fixed << setprecision(2) << 3.14159 << endl;  // 3.14

    // hex and oct
    cout << hex << 255 << endl;    // ff
    cout << oct << 255 << endl;    // 377
    cout << dec << 255 << endl;    // 255

    // boolalpha
    cout << boolalpha << true << " " << false << endl;  // true false
    return 0;
}
Conclusion

Manipulators make C++ I/O professional, readable and easy to format without changing the data itself.

Introduction

OOP models real-world relationships. Two fundamental relationships used in class design are generalization and aggregation.

Definition

Generalization is an IS-A relationship (base to derived, implemented by inheritance). Aggregation is a HAS-A relationship (an object contains another object but both can exist independently).

Points: Generalization vs Aggregation
  • Generalization (IS-A): a derived class IS-A type of the base class. Implemented by inheritance. Example: Dog IS-A Animal.
  • Aggregation (HAS-A, weak): one class USES another. If the outer class is deleted, the inner object still exists. Example: Department HAS-A Teacher (Teacher exists even if Department is deleted). Implemented with a pointer.
  • Composition (HAS-A, strong): the inner object CANNOT exist without the outer. Example: House HAS-A Room (Room does not exist without House). Implemented by value (not pointer).
  • Association: a general relationship where two classes use each other (has-a but neither owns the other).
  • Generalization promotes code reuse through inheritance.
  • Aggregation promotes code flexibility (loose coupling).
  • Generalization uses : public Base syntax; aggregation uses a pointer or reference data member.
Generalization:        Animal (base)
                        |
                      Dog (derived)  -- Dog IS-A Animal

Aggregation (weak):   Department -----> Teacher
                      (Department HAS-A Teacher; Teacher exists without Department)

Composition (strong): House []----> Room
                      (Room does not exist without House)
Example

Generalization via inheritance and aggregation via pointer:

#include <iostream>
using namespace std;

// Generalization (inheritance / IS-A)
class Animal {
public:
    void eat() { cout << "Animal eating\n"; }
};
class Dog : public Animal {    // Dog IS-A Animal
public:
    void bark() { cout << "Dog barking\n"; }
};

// Aggregation (HAS-A, weak) — Teacher exists independently
class Teacher {
public:
    string name;
    Teacher(string n) { name = n; }
};
class Department {
    Teacher* t;   // pointer = aggregation
public:
    Department(Teacher* tp) { t = tp; }
    void show() { cout << "Dept teacher: " << t->name << endl; }
};

int main() {
    Dog d; d.eat(); d.bark();          // generalization
    Teacher t("Rahul");
    Department dept(&t);
    dept.show();                        // aggregation
    return 0;
}
Conclusion

Generalization and aggregation are key OOP design concepts that model IS-A and HAS-A relationships for clean, reusable, and flexible code.

  • Constructor: same name as class; no return type; called automatically; usually public; can be overloaded; can have default arguments; cannot be inherited or virtual.

A copy constructor creates a new object as a copy of an existing object of the same class. Syntax: ClassName(const ClassName &obj). It is called when an object is initialised with another object, passed by value or returned by value. Its argument must be a reference, otherwise it would call itself endlessly. Encapsulation means binding data and the functions that use it into one unit. In C++ it is implemented using a class: data members are kept private and member functions are public, so data is reached only through those functions. This also gives data hiding and security.

Polymorphism means "one name, many forms". Compile-time (static): function overloading and operator overloading. Run-time (dynamic): virtual functions with a base class pointer. Example: add(int,int) and add(float,float) share one name.

  • Use the scope resolution operator, example obj.A::show();
  • Override the function in the derived class.
  • Use a virtual base class when the same grand-base class comes through two paths.

If a base pointer holds a derived object and the base destructor is not virtual, delete p; runs only the base destructor, which causes a memory leak. Declaring virtual ~Base() makes delete p; call the derived destructor first, then the base. Rule: any class with virtual functions should have a virtual destructor.

    }
    catch (const char *m) {
        cout << "Caught: " << m << endl;
    }
    try {
        int age = 15;
        if (age < 18) throw MyException("Age must be 18 or more");
    }
    catch (MyException &e) {
        cout << "User-defined exception: " << e.msg << endl;
    }
    return 0;
}

    fin.close();

    // Random access
    ifstream f("student.txt");
    f.seekg(0, ios::end);              // go to end
    long size = f.tellg();             // position = file size

    f.seekg(0, ios::beg);              // back to start
    f.close();
    return 0;
}

Last Minute Cheat Sheet

One-liner Definitions

  • Class = blueprint; Object = instance.
  • Encapsulation = wrap data + functions; Abstraction = hide complexity; Data hiding = private data.
  • Inheritance = reuse; Polymorphism = one name, many forms.
  • Constructor = same name as class, no return type; Destructor = ~Name.
  • Friend = non-member with access to private data.
  • Static = one shared copy; this = address of the calling object.
  • Virtual function = run-time choice; Pure virtual = = 0; Abstract class = has a pure virtual function.
  • Template = generic code for any type.
  • Exception = run-time error handled with try / catch / throw.
  • Stream = flow of data; ifstream read, ofstream write, fstream both.

Important Syntax

class A { private: int x; public: A(int a){x=a;} ~A(){} };   // class
void A::show() { }                                          // outside definition
Complex operator+(Complex c);                               // operator function
friend ostream& operator<<(ostream&, const A&);             // insertion
class B : public A { };                                     // single inheritance
class C : public A, public B { };                           // multiple
class D : virtual public A { };                             // virtual base
virtual void f();    virtual void g() = 0;                  // virtual / pure virtual
template <class T> T f(T a, T b) { }                        // template
try { throw 10; } catch (int e) { }                         // exception
ofstream fout("a.txt");  ifstream fin("a.txt");             // files
Student *p = new Student(1);  delete p;                     // dynamic object

Common Mistakes

  • Writing a return type for a constructor or destructor.
  • Forgetting the semicolon after the class closing brace };
  • Defining a friend function with A:: or the word friend outside the class.
  • Using a base class pointer to call derived-only functions.
  • Forgetting virtual in the base class, so the base function runs.
  • Trying to create an object of an abstract class.
  • Forgetting to close the file or to check that it opened.
  • Writing a catch with the wrong type, so the exception is not caught.
  • Creating an object with no arguments when only a parameterized constructor exists (compile error).
  • Passing the copy constructor argument by value instead of by reference.

Memory Tricks

  • OOP features = "EAPI": Encapsulation, Abstraction, Polymorphism, Inheritance.
  • Access specifiers = "PPP": Private (class default), Protected, Public.
  • Constructor types = "DPC": Default, Parameterized, Copy.
  • Inheritance types = "SMMHH": Single, Multiple, Multilevel, Hierarchical, Hybrid.
  • Cannot overload: Dot ., Scope ::, Ternary ?:, sizeof, Star-dot .*.
  • Exception = "TCT": Try, Catch, Throw.
  • Order rule: Constructors go Base to Derived; Destructors go Derived to Base.
  • Binary operator arguments: member = 1, friend = 2 (friend has no this).
  • Private base members are never directly usable in derived; protected can be used in derived but not outside.

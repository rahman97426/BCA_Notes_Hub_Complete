4 MARKSQ1. What is a System? Write its characteristics.📅 2014,2016,2017,2018,2021
Definition: A system is a set of interrelated components working together to achieve a common goal. It accepts input, processes it, and produces output with feedback control. Characteristics (Trick: O-I-I-I-C-E-B): Organization: System is a group of components Interaction: Components interact with each other Interdependence: Components depend on each other Integration: All parts work together as a whole Central Objective: Every system has a specific goal Environment: System exists in an environment Boundary: System has a boundary separating it from environment
🧠 Trick: O-I-I-I-C-E-B = "Old Indians Identify Issues, Creating Easy Boundaries"
4 MARKSQ2. What is Prototype? Explain its types.📅 2014,2015,2018,2022,2023,2025
Definition: A prototype is a sample/working model of the system used to understand requirements and get feedback from users before building the final system. Two Types: Throwaway Prototype: Built for requirement gathering only. Once feedback is collected, it is discarded and final system built from scratch. Evolutionary Prototype: Continuously improved and refined based on user feedback until it becomes the final delivered system. Benefits: Better understanding of user requirements Early feedback from users reduces risk Improves accuracy of final system
4 MARKSQ3. What is JAD? State its advantages.📅 2015,2016,2021,2022,2023
Definition: JAD (Joint Application Development) is a technique where users, managers and analysts work together in structured workshop sessions to define requirements and design the system. Benefits of JAD: Better communication between all stakeholders Fast requirement gathering — all parties in one session High user satisfaction — users feel involved in design Reduced development time — fewer meetings later Better quality system — meets real user needs
🧠 JAD = Users + Analysts + Managers → Better System
4 MARKSQ4. What is SRS? Write its contents.📅 2015,2017,2021,2022,2023
Definition: SRS (System Requirements Specification) describes WHAT the system should do — NOT HOW. It acts as a CONTRACT between users and developers. Contents of SRS: Introduction — purpose, scope Overall description of system Functional requirements — what system must do Non-functional requirements — performance, security, reliability Constraints, Assumptions, External interfaces, Acceptance criteria Importance:Contract between users and developers | Basis for design and testing | Reduces misunderstanding
🧠 KEY: SRS=WHAT | SDS=HOW | Test Doc=HOW TO TEST | User Manual=HOW TO USE
4 MARKSQ5. What is Feasibility Study? Name its types.📅 2015,2016,2021,2022,2023,2025
Definition: Feasibility Study checks whether the proposed system is practical, economical and beneficial. It determines if the project is worth pursuing before investing time and money. Four Types (Trick: T-O-E-L): Technical Feasibility: Is the required technology available? (hardware, software, expertise) Operational Feasibility: Will system work in organization? (user acceptance, training) Economic Feasibility: Is it cost-effective? If Benefits > Costs → Feasible ✅ Legal Feasibility: Is it legally acceptable? (laws, regulations, privacy)
🧠 T-O-E-L = "Total Overall Exam Life" | Feasible system: Practical + Acceptable + Affordable + Legal

4 MARKSQ7. What are Coupling and Cohesion? (Short Note)📅 2015,2022,2023,2025
Coupling — Definition: Coupling = degree of interdependence BETWEEN modules. LOW Coupling = GOOD DESIGN. Types (Low→High): D-S-C-E-C-C = Data, Stamp, Control, External, Common, Content(Worst) Cohesion — Definition: Cohesion = degree elements WITHIN a module belong together. HIGH Cohesion = GOOD DESIGN. Types (Low→High): C-L-T-P-C-S-F = Coincidental(Worst), Logical, Temporal, Procedural, Communicational, Sequential, Functional(Best)

4 MARKSQ8. Explain Top-Down and Bottom-Up Design.📅 2014,2016,2018,2021,2023
Top-Down Design: Starts from WHOLE system and breaks it DOWN into smaller modules until detail level is reached. Flow: System → Modules → Sub-modules (High to Low) Easy to manage and control | Used in early stages Bottom-Up Design: Starts from SMALL modules and builds UP to form larger modules and complete system. Flow: Sub-modules → Modules → System (Low to High) Good for reusable modules | Ensures reliability at lower level
🧠 Top-Down = Break Down ↓ | Bottom-Up = Build Up ↑
4 MARKSQ9. What is DFD? Explain its symbols.📅 2014,2016,2017,2018,2021,2025
Definition: DFD (Data Flow Diagram) is a graphical representation showing how data flows in a system between processes, data stores and external entities. Four Symbols (MUST memorize!): Rectangle/Square = External Entity (Source or destination of data) Circle/Oval = Process (Transforms input into output) Arrow = Data Flow (Direction and name of data movement) Open Rectangle = Data Store (Stores data — labeled D1, D2) DFD Levels:Level 0 (Context) → Level 1 (Major processes) → Level 2 (Sub-processes)

12 MARKSQ1. What is SDLC? Explain all 7 phases with diagram.📅 EVERY YEAR 2014–2025 ⭐
A. Definition: SDLC (System Development Life Cycle) is a structured process used to design, develop, implement and maintain information systems. It provides a systematic framework to build quality systems within budget and time.
SDLC has EXACTLY 7 phases. Trick: P-I-A-L-P-I-M = "Please Identify And Let People Implement Maintenance"
B. Seven Phases of SDLC: Phase 1 — Project Identification & Selection: Recognize business problems and opportunities Evaluate projects on: Strategic fit, Feasibility, Cost, Risk, Priority Output: Problem Statement, Project Proposal
Phase 2 — Project Initiation & Planning: Define project scope, objectives and major deliverables Estimate cost and time, prepare Gantt chart and risk plan Output: Project Charter, Feasibility Report, Project Plan, Cost Estimate
Phase 3 — Analysis: Study current system and gather requirements from users Analyze data, processes and controls. Evaluate feasibility (T-O-E-L) Output: SRS Document, Feasibility Report, Process Models
Phase 4 — Logical Design: Design system architecture — technology INDEPENDENT Create DFDs, ER Diagrams, Data Dictionary Output: DFD, ER Diagram, Logical Data Dictionary, Process Specs
Phase 5 — Physical Design: Select hardware and software. Design database physically Design file structures, user interface and I/O formats Output: Database Design, File Structures, I/O Design
Phase 6 — Implementation: Develop software, install hardware, test the system, train users Changeover: Direct / Parallel / Phased / Pilot Output: Working System, Test Reports, User Training, Documentation
Phase 7 — Maintenance: Corrective: Fix errors after go-live Adaptive: Modify for environment changes (new OS, hardware) Perfective: Improve performance or add new features Preventive: Make changes to prevent future problems Output: Maintenance Reports, Change Requests, Updated System C. SDLC Diagram (DRAW THIS IN EXAM):
SDLC CYCLE DIAGRAM: [1. Project [2. Project [3. Analysis] Identification]───Planning]───────────────────────────────┐ ▲ │ │ ▼ [7. Maintenance]◀──[6. Implementation]◀──[5. Physical]◀──[4. Logical │ Design] Design] │ └─────── FEEDBACK LOOP (Maintenance may loop back to earlier phases)
D. Logical vs Physical Design: Logical Design = WHAT system will do (technology-independent) | Physical Design = HOW system is built (technology-dependent) E. Conclusion: SDLC provides systematic process to develop quality IS through proper planning, analysis, design, implementation and maintenance. Ensures projects are completed on time, within budget and meeting user requirements.

Feasibility Trick: T-O-E-L = "Total Overall Exam Life" → Technical, Operational, Economic, Legal
B. Four Types of Feasibility Study: 1. Technical Feasibility — "Is technology AVAILABLE?" Checks data protection laws — IT Act, GDPR Checks copyright and intellectual property issues Checks government regulations and standards Example: Does system comply with data privacy laws? C. Conclusion: A feasible system must be: Practical ✓ Acceptable ✓ Affordable ✓ Legal ✓ Feasibility study helps organizations make informed decisions before investing in system development.
12 MARKSQ4. What is Coupling? Explain all 6 types. What is Cohesion? Explain all 7 types.📅 2015,2016,2022,2023,2025
PART A — COUPLING: Definition: Coupling is the degree of interdependence between modules. It measures how much one module depends on another. Good Design = LOW Coupling
Coupling Trick (Low→High): D-S-C-E-C-C = "Don't Share Code Everywhere, Creates Confusion"
Types of Coupling (Low to High): 1. Data Coupling (BEST): Modules communicate through SIMPLE DATA PARAMETERS only. Example: pass "student_marks" to calculate grade module. Most independent. 2. Stamp Coupling: Modules pass COMPOSITE DATA STRUCTURE (record/object). Example: pass entire "student_record" to module. 3. Control Coupling: One module passes CONTROL FLAG/SWITCH to another. Example: pass "print_flag=true" to control behavior. 4. External Coupling: Modules depend on SAME EXTERNAL FORMAT or device. Example: two modules both read from same CSV file format. 5. Common Coupling: Modules share GLOBAL VARIABLES/DATA. Example: both access global variable "total_marks". 6. Content Coupling (WORST): One module DIRECTLY ACCESSES internals of another. Completely breaks independence. PART B — COHESION: Definition: Cohesion is the degree to which elements inside a module belong together. Good Design = HIGH Cohesion
Cohesion Trick (Low→High): C-L-T-P-C-S-F = "Can Lions Tame Parrots? Colorful Song Fragments!"
Types of Cohesion (Low to High): 1. Coincidental (WORST): No relationship — random functions grouped. Example: Print+Update+Email in one module. 2. Logical: Grouped by logical category. Example: all input operations in one module. 3. Temporal: Functions performed at SAME TIME. Example: initialization module. 4. Procedural: Follow a sequence but not closely related. 5. Communicational: Functions operate on SAME DATA. Example: read, update, display student record. 6. Sequential: OUTPUT of one is INPUT to next. Example: Read→Validate→Process→Store (pipeline). 7. Functional (BEST): Module performs ONE SINGLE WELL-DEFINED FUNCTION. Example: "Calculate_Tax()" does only tax calculation. C. Summary: Coupling: Data(Best)→Stamp→Control→External→Common→Content(Worst)
Cohesion: Coincidental(Worst)→Logical→Temporal→Procedural→Communicational→Sequential→Functional(Best) D. Golden Rule: GOOD DESIGN = LOW COUPLING + HIGH COHESION — Modules are independent AND each does one job well.

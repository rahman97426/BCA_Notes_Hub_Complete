4 MARKS Q1. Define System. Write its important terms. 📅 2014, 2016, 2018, 2021, 2023 ▶
DEFINITION: A system is a set of interrelated components working together to achieve a common goal. It accepts input, processes it, and produces output with feedback control.
IMPORTANT TERMS (I-P-O-F-E-B-I-S-G): Input: Data or resources given to system (ATM: Card + PIN) Process: Converts input to output (ATM: Verify & Check Balance) Output: Result produced (ATM: Cash / Balance Statement) Feedback: Output used to control system (ATM: SMS Receipt) Environment: External elements affecting system Boundary: Limits separating system from environment Interface: Point where system interacts with others Subsystem: Smaller system within bigger system
EXAMPLE — ATM SYSTEM: Input=Card+PIN → Process=Verify → Output=Cash → Feedback=SMS
Trick: I-P-O-F = "I Prefer Organic Food"
CONCLUSION: Every system has input, process, output and feedback. Understanding this helps design better IS.
4 MARKS Q2. What is Prototype? Explain its types. 📅 2014, 2015, 2018, 2022, 2023, 2025 ▶
DEFINITION: A prototype is a sample/working model of the system used to understand requirements better and get feedback from users before building the final system.
TWO TYPES: Throwaway Prototype: Built ONLY for requirement gathering. Once feedback collected, it is DISCARDED. Final system built from scratch. Evolutionary Prototype: Continuously IMPROVED and REFINED based on user feedback until it becomes the final system.
BENEFITS: Better understanding of user requirements Early feedback reduces risk Improves accuracy of final system Reduces development cost
EXAMPLE: Before building mobile banking app, developer shows demo version → users give feedback → final app built
CONCLUSION: Prototyping is essential when requirements are unclear. It bridges gap between user expectations and final product.
4 MARKS Q3. What is JAD? State its advantages. 📅 2015, 2016, 2021, 2022, 2023 ▶
DEFINITION: JAD (Joint Application Development) is a technique where users, managers and analysts work together in structured workshop sessions to define requirements and design the system.
PARTICIPANTS: Users + Analysts + Managers → Work together → Better System
BENEFITS OF JAD: Better communication between all stakeholders Fast requirement gathering — all in one session High user satisfaction — users feel involved Reduced development time — fewer follow-up meetings Better quality system — meets real user needs
EXAMPLE: Bank wants new online system → JAD workshop with bank staff, IT analysts, managers → requirements finalized in 2 days
JAD = "Join All Data-providers → Design faster"
CONCLUSION: JAD reduces time and cost of requirement gathering while improving system quality through collaboration.

4 MARKSQ2. What are the 4 types of Maintenance?📅 2014,2019,2024▶
DEFINITION: Maintenance is the last phase of SDLC where the system is updated, improved and kept running effectively after implementation.
4 TYPES (C-A-P-P): Corrective: Fix errors/bugs found after go-live. Example: bug fix after deployment Adaptive: Modify system for environment changes. Example: OS upgrade compatibility Perfective: Improve performance or add new features. Example: faster search algorithm Preventive: Make changes to prevent future problems. Example: code refactoring
Trick: C-A-P-P = "Computers Always Prevent Problems"
CONCLUSION: Maintenance ensures system remains effective, efficient and up-to-date throughout its life.

4 MARKSQ3. What is Cost-Benefit Analysis?📅 2016,2019,2023▶
DEFINITION: CBA (Cost-Benefit Analysis) compares total costs of system with total benefits to decide if project is economically feasible.
COSTS: Hardware Cost | Software Cost | Development Cost | Training Cost | Maintenance Cost | Operating Cost
BENEFITS: Increase in Profit | Better Service | Time Saving | Accuracy Improvement | Better Control | Competitive Advantage
DECISION RULE: If Total Benefits > Total Costs → Economically FEASIBLE ✅
If Total Benefits < Total Costs → NOT Feasible ❌
Benefits > Costs = Go ahead! | Benefits < Costs = Reconsider!

12 MARKSQ1. What is Coupling? Explain all 6 types. What is Cohesion? Explain all 7 types.📅 2015,2016,2022,2023,2025▶
A. COUPLING — DEFINITION: Coupling = degree of interdependence BETWEEN modules. Measures how much one module depends on another. GOOD DESIGN = LOW Coupling (modules are independent)
B. 6 TYPES OF COUPLING (Low → High: D-S-C-E-C-C): 1. Data Coupling (BEST): Modules share only SIMPLE DATA parameters. Example: pass "student_marks" to grade module. Most independent. 2. Stamp Coupling: Pass COMPOSITE DATA STRUCTURE (record/object). Example: pass entire "student_record" to another module. 3. Control Coupling: One module passes CONTROL FLAG to another. Example: pass "print_flag = true" to control behavior. 4. External Coupling: Both depend on SAME EXTERNAL FORMAT or device. Example: two modules both read from same CSV file format. 5. Common Coupling: Modules share GLOBAL VARIABLES. Example: both access global variable "total_marks". 6. Content Coupling (WORST): One module DIRECTLY ACCESSES internals of another. Completely breaks independence. Should NEVER be used.
C. COHESION — DEFINITION: Cohesion = degree elements WITHIN a module belong together and serve one purpose. GOOD DESIGN = HIGH Cohesion (module does ONE job well)
D. 7 TYPES OF COHESION (Low → High: C-L-T-P-C-S-F): 1. Coincidental (WORST): NO relationship — random functions grouped together. Example: Print report + Update database + Send email in one module. 2. Logical: Functions grouped by LOGICAL CATEGORY. Example: All input operations in one module. 3. Temporal: Functions executed at the SAME TIME. Example: Initialization module (open file, init variables, connect DB). 4. Procedural: Functions follow a SEQUENCE but not closely related. 5. Communicational: Functions operate on SAME DATA. Example: Read, Update, Display student record — all work on student data. 6. Sequential: OUTPUT of one function is INPUT to next (PIPELINE). Example: Read → Validate → Process → Store. 7. Functional (BEST): Module performs ONE SINGLE WELL-DEFINED function. Example: "Calculate_Tax()" does ONLY tax calculation. Perfect cohesion.
E. SUMMARY TABLE:
ConceptMeaningGood ValueTrick
CouplingBetween modulesLOW (Data=Best)D-S-C-E-C-C
CohesionWithin moduleHIGH (Functional=Best)C-L-T-P-C-S-F
GOLDEN RULE: GOOD DESIGN = LOW COUPLING + HIGH COHESION
F. CONCLUSION: Low coupling ensures modules are INDEPENDENT. High cohesion ensures each module does ONE JOB WELL. Together they create systems that are easy to maintain, test and modify.

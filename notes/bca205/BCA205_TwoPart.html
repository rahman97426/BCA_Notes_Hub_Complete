Q1
What is CPU scheduling? How does the CPU scheduler select processes from the Ready state for execution? Illustrate with a neat process state diagram.
⭐⭐⭐ 💡 Always draw Process State Diagram — guaranteed marks!
5 M
▼
📌 CPU scheduling is the process by which the OS decides which process in the Ready Queue gets the CPU next. It is needed in multiprogrammed systems where many processes compete for one CPU.
📖 Definition: CPU Scheduling is the activity of selecting a process from the Ready Queue and allocating the CPU to it. The short-term scheduler performs this selection. The dispatcher then performs the actual context switch.
How the Scheduler Selects from Ready Queue:
  1. All ready-to-run processes wait in the Ready Queue.
  2. The short-term scheduler picks one using a scheduling algorithm (FCFS, SJF, Round Robin, Priority).
  3. The dispatcher removes the process from the queue and gives it the CPU (context switch).
  4. If preemptive scheduling: scheduler can take CPU away when time quantum expires or higher priority process arrives.
Process State Diagram:
New
→ admitted →
Ready
→ dispatch →
Running
→ exit →
Terminated
Running → I/O wait → Waiting → I/O done → Ready   |   Running → preempted → Ready
Key Scheduling Algorithms:
  • FCFS — First Come First Served (arrival order). Simple, but convoy effect.
  • SJF — Shortest Job First. Optimal avg waiting time.
  • Round Robin — Fixed time quantum. Best for time-sharing.
  • Priority — Highest priority runs first. Fix starvation with Aging.
✍️ Conclusion: CPU scheduling is essential in multiprogrammed OS to keep the CPU utilised and ensure fair access. The scheduler's goal is to maximise CPU utilisation and minimise waiting time. Formula: TAT = CT − AT, WT = TAT − BT.

Q3
What is Deadlock? Explain the necessary conditions for deadlock and discuss the methods of deadlock prevention, avoidance, detection and recovery with suitable examples.
⭐⭐⭐ 💡 Write all 4 Coffman conditions by name — each is worth marks!
5 M
▼
📌 Deadlock is one of the most critical problems in multiprogrammed systems. It causes all involved processes to freeze permanently, wasting CPU time and resources.
📖 Definition: Deadlock is a state in which a set of processes are each waiting for a resource held by another process in the same set. No process can proceed — they are permanently blocked.
4 Necessary Conditions (Coffman Conditions):
  1. Mutual Exclusion — At least one resource is held in non-shareable mode.
  2. Hold and Wait — A process holding a resource is waiting to acquire more.
  3. No Preemption — Resources cannot be forcibly taken; released voluntarily only.
  4. Circular Wait — A cycle: P0 waits for P1's resource, P1 waits for P2's, ..., Pn waits for P0's.
⚠️ ALL 4 must hold simultaneously for deadlock. Remove ANY ONE → no deadlock!
Handling Deadlock:
MethodApproachExample
PreventionRemove one of the 4 conditions permanently. E.g. Break Circular Wait by imposing resource ordering — processes must request resources in increasing numeric order.Resource numbering system
AvoidanceOS checks safety before granting each request. Grant only if resulting state is SAFE. Uses Banker's Algorithm. Need = Max − Allocation. Safe sequence exists → state is safe.Banker's Algorithm
DetectionAllow deadlock to occur, then detect it using a wait-for graph (cycle = deadlock) or Banker's-like detection algorithm for multiple instances.Wait-for graph cycle detection
RecoveryAfter detection: (a) Process termination — abort all or one at a time until cycle breaks. (b) Resource preemption — forcibly take resources from a victim process.Kill deadlocked process
💡 Example: Two students each need a compiler AND a printer. Student A holds compiler, waits for printer. Student B holds printer, waits for compiler. Neither can proceed → deadlock!
✍️ Conclusion: Deadlock is a serious resource-management problem. Prevention is safest but wastes resources. Avoidance (Banker's Algorithm) is practical for systems where max needs are known. Detection+Recovery is used when others are impractical.
Q4
Using Linux basic commands, explain step by step how to create a directory, create and edit a file inside it, display the file contents, copy the file, rename it. Write the Linux command used at each step.
⭐⭐ 💡 Write each step with exact command syntax — 1 mark per step!
5 M
▼
📌 Linux provides powerful command-line tools for file and directory management. The following steps demonstrate a complete workflow — creating a directory, working with files inside it, and performing file operations.
Step-by-Step Linux Commands:
Step 1
Create a Directory
$ mkdir myproject
mkdir (Make Directory) creates a new directory named myproject.
Step 2
Navigate into the Directory
$ cd myproject
cd (Change Directory) moves into myproject. Verify with: pwd
Step 3
Create and Edit a File using vi editor
$ vi notes.txt
Opens vi editor. Press i to enter Insert mode → type your content → press Esc → type :wq → Enter to save and quit.
Step 4
Display File Contents
$ cat notes.txt
cat (Concatenate) displays the full content of the file on screen.
Step 5
Copy the File
$ cp notes.txt backup.txt
cp (Copy) creates an exact copy of notes.txt named backup.txt in the same directory.
Step 6
Rename the File
$ mv backup.txt final_notes.txt
mv (Move) renames backup.txt to final_notes.txt. Same command is used for moving files to another location.
Verify
List all files created
$ ls -l
ls -l shows all files with permissions, size, and date — confirming all operations succeeded.
✍️ Conclusion: These 6 commands — mkdir, cd, vi, cat, cp, mv — cover the complete file lifecycle in Linux. They are the most commonly used commands in any Linux session and appear in Q1 fill-in questions almost every year.

4M 📌 Teacher Q6 | AKU PYQ 2016,2017,2019,2022,2023 What is the critical-section problem? State its three requirements. ▼
📖 Critical Section: A segment of code where a process accesses shared resources (variables, files, buffers). Must not be executed by more than one process at the same time — else race condition occurs and data gets corrupted.
Three Requirements for a Correct Solution:
  1. Mutual Exclusion — If process Pi is in its CS, NO other process can be in its CS at the same time. (Only one at a time)
  2. Progress — If no process is in CS and some want to enter, the decision cannot be postponed indefinitely. (No deadlock)
  3. Bounded Waiting — There must be a LIMIT on how many times others can enter before a waiting process gets its turn. (No starvation)
💡 Example: Two ATMs updating the same bank account simultaneously without control can give wrong balance — a race condition. The "update balance" code is the critical section.
✍️ All three conditions must be satisfied simultaneously. Semaphores using wait() and signal() provide a clean, OS-level solution to the critical-section problem.
4M 📌 Teacher Q8 | Class Test 2026 Q3 | AKU PYQ 2016,2017,2019,2021,2022,2023 What is deadlock? State the 4 necessary conditions with examples. ▼
📖 Deadlock: A state where a set of processes are permanently blocked — each waiting for a resource held by another in the same set. No process can proceed.
4 Necessary Conditions (Coffman Conditions) — ALL must hold:
  1. Mutual Exclusion — Resource used by only one process at a time. (Printer can only serve one job)
  2. Hold and Wait — Process holds a resource and waits for more. (Holds compiler licence, waits for printer)
  3. No Preemption — Resource can only be released voluntarily. (Cannot forcibly take printer from process)
  4. Circular Wait — P0 waits for P1's resource → P1 waits for P2's → ... Pn waits for P0's. (Circle of waiting)
💡 Example: Student A holds compiler, waits for printer. Student B holds printer, waits for compiler. Neither can finish → Deadlock!
✍️ REMOVE ANY ONE CONDITION → Deadlock becomes impossible. This is the basis of Deadlock Prevention.

12M 🔥 Teacher Q6 & Q7 | AKU PYQ 2016,2017,2019,2022,2023 Explain semaphores (binary and counting) with examples. Solve the Producer-Consumer problem using semaphores. ▼
📌 When multiple processes share data, uncontrolled access causes race conditions. Semaphores provide a clean, OS-supported solution for process synchronisation.
📖 Semaphore: An integer variable accessed only through two ATOMIC operations: wait(S)/P() — decrements S, blocks if S < 0; signal(S)/V() — increments S, wakes a blocked process. The atomicity guarantees no race condition on the semaphore itself.
Types of Semaphore:
TypeValuesUseExample
Binary Semaphore (Mutex)0 or 1 onlyMutual exclusion — only one process in critical sectionProtecting a shared counter variable
Counting SemaphoreAny integer ≥ 0Control access to resource with multiple instancesManaging N database connections
Critical Section Solution using Semaphore:
mutex = 1 (binary semaphore, initialised to 1)

Process Pi:
wait(mutex); ← enter critical section
// ... critical section code ...
signal(mutex); ← exit critical section
Producer-Consumer Problem (Bounded Buffer):
📖 Producer adds items to a buffer; Consumer removes them. Buffer has N slots. Need to prevent producer adding to full buffer and consumer removing from empty buffer.
Three Semaphores needed:
  • empty = N (counts free slots, starts at N = buffer capacity)
  • full = 0 (counts filled slots, starts at 0)
  • mutex = 1 (binary, mutual exclusion for buffer access)
PRODUCER:
wait(empty); ← wait if buffer full
wait(mutex); ← enter critical section
add item to buffer
signal(mutex); ← exit critical section
signal(full); ← signal one more slot filled

CONSUMER:
wait(full); ← wait if buffer empty
wait(mutex); ← enter critical section
remove item from buffer
signal(mutex); ← exit critical section
signal(empty); ← signal one more slot free
Classical Synchronisation Problems:
  1. Producer-Consumer: Bounded buffer (above)
  2. Readers-Writers: Multiple readers can read simultaneously; writers need exclusive access
  3. Dining Philosophers: 5 philosophers, 5 forks; naive solution can deadlock. Fix: asymmetric fork pickup order
💡 Real Example: A print spooler is producer-consumer. Multiple apps add print jobs (produce); the printer driver removes and prints them (consume). Semaphores ensure two apps never corrupt the job queue simultaneously.
✍️ Conclusion: Semaphores are the standard OS synchronisation mechanism. Binary semaphores handle mutual exclusion; counting semaphores control resource pools. The three conditions — Mutual Exclusion, Progress, Bounded Waiting — must ALL be satisfied. Always write these three by name in exam answers on this topic.
12M 🔥 Teacher Q8,Q9,Q10 | Class Test 2026 Q3 | AKU PYQ 2016,2017,2019,2021,2022,2023 Explain deadlock prevention, avoidance (Banker's Algorithm), detection and recovery. ▼
📌 Deadlock handling is one of the most exam-important topics. Four strategies exist, each with different trade-offs between safety and resource utilisation.
📖 Deadlock: Set of processes permanently blocked, each waiting for a resource held by another in the same set. 4 conditions: Mutual Exclusion, Hold & Wait, No Preemption, Circular Wait (all must hold simultaneously).
1. Deadlock Prevention (Remove one of 4 conditions):
  1. Break Mutual Exclusion: Make resources shareable where possible.
  2. Break Hold & Wait: Process must request ALL resources before starting, OR release all before new request.
  3. Break No Preemption: Forcibly take resources from a process if it requests unavailable ones.
  4. Break Circular Wait: Impose total ordering on resource types. Each process requests only in increasing order. ← Most practical!
2. Deadlock Avoidance — Banker's Algorithm:
📖 OS acts like a bank manager — grant resource only if system remains in SAFE STATE after granting. Need = Max − Allocation. Safe State = a safe sequence exists where all processes can finish.
Worked Example: 5 processes, 3 resource types (A,B,C). Available=(3,3,2)
ProcessAllocationMaxNeed=Max-Alloc
P00,1,07,5,37,4,3
P12,0,03,2,21,2,2
P23,0,29,0,26,0,0
P32,1,12,2,20,1,1
P40,0,24,3,34,3,1
Avail=(3,3,2). P1 Need(1,2,2)≤(3,3,2)✓→run P1→Avail=(5,3,2)

P0 Need(7,4,3)≤(7,4,3)✓→run P0→Avail=(7,5,3)

SAFE STATE ✓ Safe Sequence: P1→P3→P0→P2→P4
3. Deadlock Detection:
  • Single instance per resource type: Build a wait-for graph. A CYCLE in the graph = deadlock.
  • Multiple instances: Run a Banker's-like detection algorithm using a Request matrix. Processes that cannot finish = deadlocked.
4. Deadlock Recovery:
  1. Process Termination: (a) Abort ALL deadlocked processes — drastic but clean. (b) Abort ONE at a time until cycle breaks — less drastic but slower.
  2. Resource Preemption: Forcibly take resources from a victim process, rollback its state, and restart it later. Ensure same process is not always victim (to prevent starvation).
✍️ Conclusion: Prevention is safest but reduces utilisation. Avoidance (Banker's) is practical when max needs are known. Detection+Recovery is used when avoidance is too costly. In AKU exams: always write all 4 Coffman conditions by name, always write the safe sequence when solving Banker's Algorithm. These steps alone can earn 6-8 marks out of 12.

12M 🔥 Teacher Q13 & Q14 | AKU PYQ 2016,2017,2018,2019,2021,2022,2023 | 2023 LRU numerical verified Explain virtual memory and demand paging. Explain page replacement algorithms FIFO, LRU, Optimal with a solved numerical. ▼
📌 Virtual memory is one of the most important OS innovations — it allows programs larger than physical RAM to run, by loading only the needed portions on demand.
📖 Virtual Memory: Technique that lets a process execute even when not completely loaded in RAM. Logical address space can be larger than physical RAM. Implemented via demand paging.
Demand Paging: Load a page into RAM ONLY when it is actually referenced. Uses valid-invalid bit in page table (1=in RAM, 0=not in RAM → PAGE FAULT). Page Fault Steps:
  1. Reference page; valid bit=0 → PAGE FAULT trap.
  2. Check if legal address → if illegal, abort process.
  3. Find a free frame (or select victim using replacement algorithm).
  4. Read page from disk into frame.
  5. Update page table (set frame number, valid bit=1).
  6. Restart the instruction that caused the fault.

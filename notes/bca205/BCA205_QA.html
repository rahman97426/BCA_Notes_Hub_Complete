Unit 1 — Introduction, OS Services & CPU Scheduling
Unit 1
Q1
What is an Operating System? What services does it provide?
PYQ 2019 Q2(a) | 2021 | Repeated 12-mark
▼
📌 An OS is system software that acts as an intermediary between the user and hardware. It manages CPU, memory, I/O devices, and file storage.
📖 Definition: An Operating System is system software that manages hardware resources and provides services to programs and users.
Services Provided:
1. Program Execution — loads program into memory and runs it.
2. I/O Operations — performs I/O on behalf of user programs (for safety).
3. File-System Manipulation — create, delete, open, close, read, write files.
4. Communication — processes exchange data via shared memory or message passing.
5. Error Detection — monitors CPU, memory, I/O for errors continuously.
6. Resource Allocation — distributes CPU time, memory, I/O among programs.
7. Accounting — tracks resource usage per user/job.
8. Protection & Security — controls access and defends against attacks.
💡 Example: When you save a Word document → OS uses file-system service. When you print → OS uses I/O service. Both happen invisibly.
✍️ Conclusion: The OS is indispensable — without it, no program can run, no file can be saved, and no device can be used safely.
Q2
What is multiprogramming? How does it differ from time-sharing?
PYQ 2021 Q1(a,c) | 2023 Q1 | 4-mark type
▼
📌 Both multiprogramming and time-sharing aim to keep the CPU busy, but they differ in purpose and switching speed.
Multiprogramming:
• Keeps several jobs in main memory simultaneously.
• When running job waits for I/O, CPU switches to another ready job.
• Goal: maximise CPU utilisation (batch-oriented).

Time-Sharing:
• Switches so rapidly (using time quanta) that every user feels they have a dedicated CPU.
• Goal: minimise response time for interactive users.
• Example: 30 students sharing one AKU lab server — all feel instant response.
✍️ Conclusion: Multiprogramming = efficiency. Time-sharing = interactivity. Together they form the foundation of all modern OS.
Q3
What are system calls? Explain their types with examples.
PYQ 2021 Q3 | 2025 Q3 | 12-mark
▼
📌 User programs run in user mode and cannot touch hardware directly. A system call is the only safe gateway to request OS services.
📖 Definition: A system call is a programmatic interface that lets a user program request a privileged service from the OS kernel, causing a mode switch from user mode to kernel mode.
Types of System Calls:
1. Process Control — fork(), exec(), exit(), wait(). Create, run, terminate processes.
2. File Management — open(), read(), write(), close(), delete(). Manage files.
3. Device Management — ioctl(), read/write device. Request/release devices.
4. Information Maintenance — getpid(), time(). Get/set system attributes.
5. Communication — pipe(), socket(), send(), receive(). IPC.

How it works: Program calls open() → TRAP fires → CPU switches to kernel mode → OS performs service → returns result to user mode.
💡 Example: A C program calling fopen() internally invokes the open() system call. The program never talks to the disk directly — the kernel does it.
✍️ Conclusion: System calls are the backbone of the user-kernel boundary. Every file operation, process creation, and I/O request ultimately goes through a system call.
Q4
Explain CPU Scheduling algorithms: FCFS, SJF, Priority, Round Robin with examples.
PYQ 2014 Q3 | 2022 Q3 | 2023 Q7 — MOST REPEATED 12-mark
▼
📌 In a multiprogrammed OS, many processes compete for the CPU. The short-term scheduler decides who gets it next.
Scheduling Criteria:
• CPU Utilisation — keep CPU busy (maximise)
• Throughput — processes completed per time unit (maximise)
• TAT = Completion Time − Arrival Time (minimise)
• WT = TAT − Burst Time (minimise)
• Response Time — time to first response (minimise)
FCFS — First Come First Served. Non-preemptive. Runs in arrival order like a ticket queue. Problem: Convoy Effect — long job blocks all short jobs behind it.

SJF — Shortest Job First. Non-preemptive. Shortest burst runs next. Gives optimal minimum average waiting time. Problem: starvation of long jobs.

Priority — highest priority process runs first. Problem: starvation of low-priority jobs. Fix: Aging (gradually raise priority of waiting jobs).

Round Robin — each process gets a fixed time quantum, then joins the back of the queue. Best for interactive/time-sharing. Too large quantum → FCFS; too small → overhead.

Unit 2 — Process Management
Unit 2
Q1
Explain the different states of a process. What is the purpose of the PCB?
PYQ 2019 Q3 | 2021 Q1(e,f) | 12-mark
▼
📌 A process is a program in execution. As it runs it moves through different states. The OS tracks each process using a PCB (Process Control Block).
5 Process States:
1. New — process is being created.
2. Ready — in memory, waiting for CPU.
3. Running — CPU is currently executing it.
4. Waiting/Blocked — waiting for I/O or an event to complete.
5. Terminated — finished execution; resources being freed.

Transitions: New→Ready (admitted) | Ready→Running (scheduler dispatch) | Running→Waiting (I/O request) | Waiting→Ready (I/O done) | Running→Terminated (exit)
PCB (Process Control Block) contains:
1. Process state (New/Ready/Running/Waiting/Terminated)
2. Program counter — next instruction address
3. CPU registers — all register values
4. Scheduling info — priority, queue pointers
5. Memory management info — page tables, base/limit registers
6. Accounting info — CPU time used
7. I/O status — devices allocated, open files
💡 Example: Opening two browser tabs creates two processes. While one waits for a slow website (Waiting state), the other responds to your typing (Running state).
✍️ Conclusion: Process states and PCB are the foundation of multiprogramming. Without them the OS could not safely switch between processes.
Q2
What is the critical-section problem? Explain semaphores and the Producer-Consumer problem.
PYQ 2016/17 Q1(c) | 2022 Q4 | 2023 Q3 — Repeated every year
▼
📌 When multiple processes access shared data concurrently, results can be corrupted. This is called a race condition. The critical-section problem is the challenge of preventing it.
📖 Critical Section: Code segment where a process accesses shared resources that must not be accessed simultaneously by another process.
3 Requirements for a Correct Solution:
1. Mutual Exclusion — if Pi is in CS, no other process may enter its CS.
2. Progress — if no process is in CS, the decision of who enters next cannot be postponed indefinitely.
3. Bounded Waiting — limit on how many times others can enter before a waiting process gets its turn (no starvation).
Semaphore Solution:
A semaphore is an integer variable with two atomic operations:
• wait(S) / P() — decrements S; if S < 0, process blocks.
• signal(S) / V() — increments S; wakes a blocked process if any.

Producer-Consumer Problem:
3 semaphores: empty (free slots), full (filled slots), mutex (mutual exclusion).

Producer: wait(empty) → wait(mutex) → add item → signal(mutex) → signal(full)
Consumer: wait(full) → wait(mutex) → remove item → signal(mutex) → signal(empty)
💡 Example: A print spooler is producer-consumer: apps add print jobs (produce), printer driver removes and prints them (consume). Semaphores ensure no conflict.
✍️ Conclusion: Semaphores are the standard OS synchronisation tool. Always remember the 3 requirements: Mutual Exclusion, Progress, Bounded Waiting.
Q3
What are the necessary conditions for deadlock? Explain the Banker's Algorithm.
PYQ 2016 Q2(d) | 2019 Q2(b) | 2021 Q5 | 2023 Q4 — Most Repeated
▼
📖 Deadlock: A situation where a set of processes are permanently blocked — each waiting for a resource held by another in the same set, so none can ever proceed.
4 Necessary Conditions (Coffman Conditions):
1. Mutual Exclusion — at least one resource held in non-shareable mode.
2. Hold and Wait — process holding a resource waits to acquire more.
3. No Preemption — resource cannot be forcibly taken; released voluntarily only.
4. Circular Wait — cycle: P0 waits for P1's resource, P1 for P2's, ..., Pn waits for P0's.

ALL 4 must hold simultaneously for deadlock to occur.
Banker's Algorithm (Deadlock Avoidance):
Key formula: Need = Max − Allocation

Grant a request ONLY IF the resulting state is SAFE (a safe sequence exists where all processes can finish).

Safety Check: Find a process whose Need ≤ Available → 'run' it → add its Allocation back to Available → repeat until all processes finish = SAFE STATE.

Example: Available=(3,3,2). P1 Need=(1,2,2) ≤ (3,3,2) → run P1 → Available grows. Continue: P3→P0→P2→P4. Safe sequence = P1→P3→P0→P2→P4.
Deadlock Prevention — remove one of the 4 conditions:
• Break Circular Wait: impose total ordering on resource types, request only in increasing order.
• Break Hold & Wait: request all resources before execution starts.

Deadlock Recovery:
• Process termination: abort all deadlocked processes, or one by one until cycle breaks.
• Resource preemption: forcibly take resources from a victim process.
✍️ Conclusion: Prevention guarantees no deadlock but reduces utilisation. Banker's Algorithm avoids deadlock at runtime by only granting safe requests.
Q4
Differentiate between user-level and kernel-level threads. Explain IPC.
PYQ 2021 Q4 | 2025 Q4 | 2018 Q4 | Repeated
▼
📖 Thread: Lightweight process — basic unit of CPU utilisation within a process. Has its own thread ID, PC, registers, stack, but SHARES code, data, and OS resources with other threads.
User-Level Threads:
• Managed by thread library in user space; kernel unaware.
• Fast to create/switch (no kernel call needed).
• Problem: one blocking call blocks entire process.

Kernel-Level Threads:
• Managed directly by OS; each thread scheduled independently.
• One thread blocking does NOT block others.
• Slower to create/switch (requires kernel call).
• Used by: Windows, Linux.

Multithreading Models: Many-to-One | One-to-One | Many-to-Many
Inter-Process Communication (IPC):

Model 1 — Shared Memory:
• Region of memory shared between cooperating processes.
• Very FAST (direct memory access).
• Processes must synchronise access themselves (e.g. semaphores).

Model 2 — Message Passing:
• Processes use send() and receive() primitives.
• No shared memory needed; safer and easier to implement.
• Slower (kernel overhead for every message).
• Better for distributed systems.
💡 Example: A word processor uses threads: one for typing (foreground), one for spell-check (background) — same process, shared document. Two chat apps on different computers use message-passing IPC.
✍️ Conclusion: Threads give a process the ability to do many things concurrently at low cost. IPC lets separate processes cooperate — essential for complex software systems.

Unit 3 — Memory Management
Unit 3
Q1
Explain paging. What is the need of a page table? Explain TLB.
PYQ 2014 Q4 | 2021 Q6 | 2018 Q7(c) | Repeated
▼
📌 Paging solves the external fragmentation problem entirely by using fixed-size memory blocks.
📖 Paging: Non-contiguous memory scheme. Physical memory → fixed-size frames. Logical memory → same-sized pages. Pages load into any available frames — no contiguity needed.
Address Translation:
Logical address = page number (p) + offset (d)
Page table maps: page number → frame number
Physical address = frame number + offset d

Advantages:
✓ No external fragmentation
✓ Any free frame can hold any page
✓ Easy sharing of pages between processes

Minor Disadvantage: slight internal fragmentation in last page only.
Page Table: Without it, CPU cannot translate logical addresses to physical addresses. Each process has its own page table stored in main memory.

TLB (Translation Lookaside Buffer):
• Looking up the page table requires an extra memory access — slow!
• TLB is a small, super-fast hardware associative cache of recent page→frame mappings.
• TLB HIT → frame number given instantly (no extra memory access).
• TLB MISS → go to full page table in memory, then update TLB.
• Modern CPUs achieve TLB hit rate >98% → paging is fast enough to be practical.
💡 Example: A 12 KB process with 4 KB pages needs 3 pages. Even if free frames are at positions 5, 19, 40 in RAM — paging places them there without any problem.
✍️ Conclusion: Paging is the foundation of virtual memory in virtually every modern OS. The TLB makes paging fast enough by eliminating the extra memory access for most translations.
Q2
Explain virtual memory and demand paging. What happens when a page fault occurs?
PYQ 2016/17 Q2(a) | 2023 Q2(c) — Repeated identical wording
▼
📖 Virtual Memory: Technique that lets a process execute even when not completely loaded in physical RAM. Logical address space can be much larger than physical memory.
Demand Paging: Load a page into memory ONLY when it is actually referenced — not in advance.

Each page-table entry has a valid-invalid bit:
• valid (1) = page is in a frame in RAM
• invalid (0) = page is NOT currently in memory → causes a PAGE FAULT
Page Fault Handling Steps:
1. Process references a page; valid-invalid bit = 0 → PAGE FAULT TRAP fires.
2. OS checks: is this a legal address for this process? If illegal → abort process.
3. Find a free frame in RAM (or select a victim frame using a replacement algorithm).
4. Schedule a disk read to bring the required page into that frame.
5. Update page table: set frame number, set valid bit = 1.
6. Restart the instruction that caused the page fault.
💡 Example: Opening a 2 GB video editor does NOT load all 2 GB at once. Only the pages you actually use — current menus, current timeline frame — are loaded on demand. This is why startup is fast.
✍️ Conclusion: Demand paging allows programs much larger than physical RAM to run, increases multiprogramming degree, and reduces startup time — at the cost of occasional page-fault delays.
Q3
Explain FIFO, LRU and Optimal page replacement. Solve: ref string 7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1 with 3 frames using LRU.
PYQ 2023 Q6 — 12 marks VERIFIED NUMERICAL | 2018 Q3 | 2022 Q5
▼
📖 When a page fault occurs and no free frame is available, the OS must choose a victim page to remove. The rule for choosing is the page replacement algorithm.
FIFO — Replace the page loaded FIRST (oldest in memory). Simple queue. Problem: Belady's Anomaly — adding more frames can INCREASE page faults.

LRU — Replace the page NOT USED for the LONGEST TIME in the past. Practical approximation of Optimal. No Belady's Anomaly.

Optimal (MIN) — Replace the page NOT NEEDED for the LONGEST TIME in the future. Gives minimum page faults. Impossible in practice (needs future knowledge) — used only as a benchmark.

Q4
Discuss fragmentation and thrashing. How is thrashing controlled?
PYQ 2018 Q1(j) | 2019 Q2(c) | 2022 Q2(b) | 2019 Q1(c)
▼
Internal Fragmentation: Wasted space INSIDE an allocated block. Occurs when a process gets a block larger than it needs. Example: 4.1 KB process in a 5 KB partition wastes 0.9 KB.

External Fragmentation: Wasted space BETWEEN allocated blocks. Total free memory may be enough, but scattered in small non-contiguous pieces. Fix: Compaction (shuffle memory) or use Paging.
Thrashing: A condition where the system spends MORE TIME swapping pages in/out than actually executing instructions. CPU utilisation drops sharply even as more processes are added.

Cause: Too many processes in memory → each gets too few frames → constant page faults → OS busy paging → CPU idle → OS admits even more processes (makes it worse).

Control Methods:
1. Working-Set Model — track pages each process used recently (working set). Only run a process if enough frames for its working set are available.
2. Page-Fault Frequency (PFF) — monitor each process's fault rate. Give more frames if rate too high; take frames away if too low.
✍️ Conclusion: Fragmentation wastes memory space. Thrashing wastes CPU time. Paging eliminates external fragmentation; working-set model prevents thrashing.

Explain file permissions in Linux. How do chmod, chown and chgrp work?
Syllabus-core | chmod Q in PYQ 2014/2016/2017
▼
📌 Linux is multiuser. Every file/directory has permissions controlling who can read, write, and execute it — the core of Linux security.
Permission Format: -rwxr-xr--
• First char: - (file), d (dir), l (link)
• Next 9: three groups of rwx for Owner | Group | Others

Octal Notation:
r=4, w=2, x=1. Add values per group:
• rwx = 7 | rw- = 6 | r-x = 5 | r-- = 4 | --- = 0

ModeOctalMeaning
rwxr-xr-x755Owner: full | Group/Others: read+execute
rw-r--r--644Owner: read+write | Group/Others: read only
rwx------700Owner: full | Group/Others: no access
Commands:
• chmod 755 file — change permissions
• chmod u+x file — add execute for owner (symbolic)
• chown abdul file.txt — change owner to 'abdul'
• chgrp students file.txt — change group to 'students'
• chmod 750 assignment — owner rwx, group r-x, others ---
✍️ Conclusion: chmod, chown, chgrp together form the complete access-control system of Linux — essential for any multiuser environment.
Q2
Explain I/O redirection and pipes. What are filters? Also explain hard vs soft links.
PYQ 2023 Q1(j) | 2016/17 Q1(g) | Repeated short Q
▼
I/O Redirection:
• > redirect stdout to file (overwrite): ls > filelist.txt
• >> redirect stdout (append): echo hi >> notes.txt
• < redirect stdin from file: sort < names.txt
• 2> redirect stderr: command 2> errors.txt
Pipes ( | ): Connect one command's stdout directly to next command's stdin. No temporary file needed.
Example: grep 'error' system.log | sort | uniq | wc -l
→ find error lines → sort → remove duplicates → count. All in one line!

Filters: Commands that read stdin, transform data, write to stdout.
Common filters: grep, sort, uniq, wc, cut, awk
Hard Link:
• Second directory entry pointing to the SAME inode as the original.
• Deleting original does NOT delete data — hard link still works.
• Cannot cross file systems. Created: ln original hardlink

Soft (Symbolic) Link:
• Separate file storing only the PATH to target.
• If original deleted/moved → soft link BREAKS (dangling).
• CAN cross file systems. Created: ln -s original softlink
✍️ Conclusion: Pipes and redirection make Linux powerful — small commands combine into sophisticated pipelines. Hard links are robust; soft links are flexible shortcuts.

Unit 5 — vi Editor, Shell & Linux Features
Unit 5
Q1
What is shell? How many types of shell are used in UNIX? Describe them.
PYQ 2014 Q6 | 2016 Q6 | 2017 Q6 | 2018 Q6 | 2019 Q6 — 5 YEARS IN A ROW
▼
📖 Shell: A command-line interpreter between the user and the OS kernel. It reads commands, interprets them, and instructs the kernel to carry them out. Also a scripting language.
Types of Shell:

1. Bourne Shell (sh) — developed by Stephen Bourne, 1977. The FIRST UNIX shell. Simple, portable. Basis of all shell scripting syntax. Prompt: $

2. C Shell (csh) — by Bill Joy (UC Berkeley). C-like syntax. Introduced command history (!!) and aliases. Prompt: %

3. Korn Shell (ksh) — by David Korn (Bell Labs). Best of Bourne + C shells. Better scripting. Prompt: $

4. Bash (Bourne Again Shell) — DEFAULT on almost all modern Linux. Superset of Bourne shell. Adds: command-line editing, history, job control, tab completion. Prompt: $
Shell Features:
• Redirection: >, >>, <, 2>
• Pipes: | connects commands
• Aliases: alias ll='ls -l'
• Job control: & (background), Ctrl+Z (suspend), bg, fg, jobs
• Shell scripts: files of commands with #!/bin/bash shebang
• Variables, if-else, for/while loops
💡 Example: The terminal prompt user@machine:~$ is Bash. Every command you type is interpreted by Bash before the kernel acts on it. First UNIX shell = Bourne shell (always asked in exams!).
✍️ Conclusion: Shell is the most important tool for any Linux user. Bash is the shell to know for AKU exams — most commonly asked and used in all lab practicals.

Q3
Discuss the features, drawbacks and components of Linux.
PYQ 2016 Q3 | 2017 Q3 | 2019 Q2(d) | 2021 Q2(e) | 2022 Q2(d) | 2025 Q7 — 6 years
▼
Features of Linux:
1. Multiuser — multiple users work simultaneously with full isolation.
2. Multitasking — many processes run concurrently.
3. Open Source — full source code freely available to study, modify, distribute.
4. Portable — runs on any hardware from tiny embedded to supercomputers.
5. Secure — strong permission model + rapid community security patching.
6. Hierarchical File System — everything under one root (/) tree, including devices.
7. Networking — built-in TCP/IP, internet-ready.
Advantages:
✓ Free of cost — no licence fee
✓ Stable and reliable — servers run years without reboot
✓ Highly customisable — modify kernel itself
✓ Huge community support

Disadvantages / Drawbacks:
✗ Steep learning curve for beginners from Windows
✗ Some proprietary hardware lacks Linux drivers
✗ Fewer commercial games and apps than Windows
✗ Fragmentation — hundreds of distributions cause confusion
5 Components of Linux:
1. Kernel — core; manages CPU, memory, devices, file system. Only part that talks to hardware directly.
2. Shell — command-line interpreter between user and kernel (Bash etc.).
3. File System — hierarchical structure (ext4, NTFS, FAT); everything under root /.
4. System Libraries — functions programs use to request kernel services (e.g. glibc).
5. System Utilities / Applications — ls, ps, useradd, gcc, Firefox, etc.
✍️ Conclusion: Linux dominates servers, cloud, Android, and supercomputers because of stability, security, and zero cost. Remember: 5 components + 7 features = full marks!

Unit 6 — Linux Utilities & UNIX Administration
Unit 6
Q1
Discuss the role of the UNIX System Administrator. What are the main responsibilities?
PYQ 2016 Q7(c) | 2017 Q7(c) | 2022 Q7 — Repeated exactly same question
▼
📌 A UNIX/Linux System Administrator (sysadmin) manages, maintains, and secures the OS and all services running on it. The sysadmin has root (superuser) access — they can do anything on the system.
Main Responsibilities:
1. User Account Management — create, modify, delete accounts and groups.
Commands: useradd, usermod, userdel, passwd, groupadd

2. Software Management — install, update, remove packages.
Commands: apt install, apt remove, yum install

3. File System Management — partition, format, mount/unmount drives, monitor disk.
Commands: mkfs, mount, umount, df, du. Config: /etc/fstab

4. System Monitoring — CPU, memory, processes, logs.
Commands: top, ps, free, dmesg, journalctl

5. Backup & Restoration — schedule and test regular backups.
Tools: tar, rsync, cpio
Types: Full | Incremental | Differential

6. Network Configuration — IP addresses, DNS, firewall rules.

7. Security — strong password policies, file permissions, intrusion monitoring, system patching.

8. Booting the System — Boot sequence: BIOS/UEFI → GRUB → Kernel → init/systemd → login prompt.
Installing Linux — Steps:
1. Choose installation method: bootable USB, DVD, or network (PXE) install.
2. Choose installation class: Minimal (server), Full Desktop, or Custom.
3. Pre-installation checks: hardware compatibility, free disk space, backup existing data.
4. Installation: partition disk, format, copy system files, select packages.
5. Boot configuration: install GRUB bootloader, set boot order.
💡 Example: A college lab admin's daily tasks: adding student accounts each semester, running weekly tar backups of /home, checking logs for failed logins, updating kernel for security patches.
✍️ Conclusion: The sysadmin is the most critical role in any Linux environment. Their work keeps the system running, users working, and data safe.
Q2
Explain absolute vs relative pathnames. Hard links vs soft links. Backup types.
PYQ 2016/17 Q1(i,j) | 2019 Q1(f) | 2022 | Repeated short Q
▼
Absolute Pathname: Starts from root /. Works from any location.
Example: /home/abdul/notes.txt

Relative Pathname: Starts from current working directory.
Example: (if in /home/abdul) just notes.txt refers to same file.

Special: . = current directory | .. = parent directory
Commands: pwd (print current dir) | man (manual pages/help)
Hard Link vs Soft Link:

Backup Types:
1. Full Backup — copy of ALL data. Simplest to restore; slowest and largest to create.
2. Incremental Backup — only data changed since the LAST BACKUP OF ANY KIND. Fastest to create; restoration needs full + all incrementals in order.
3. Differential Backup — all data changed since the LAST FULL BACKUP. Middle ground.

Tools: tar (archive), rsync (copy only changed files), cpio

⚠️ Golden rule: ALWAYS TEST that a backup can actually be restored — untested backup = no backup!
✍️ Conclusion: Absolute paths are safe and unambiguous. Hard links are robust. Differential backup gives the best balance of speed and easy restoration.

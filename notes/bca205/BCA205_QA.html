Q4 4M ⭐ ⭐ AKU VVI Q3★★ | Class Test 2026 Q1(5M)… What is a Process? Explain the 5 process states with state transition diagram. ▼
💡 One-Line: Process = Program in execution. 5 states = New→Ready→Running→Waiting→Terminated (NRRWT).
🧠 NRRWT = Never Run Races Without Training | PCB = Process's Aadhar Card
📘 Introduction / Definition
A process is a program in execution. Includes Program Counter (PC), CPU registers, stack, heap, and data. OS keeps a PCB for each process.
Process Definition
A process is a program in execution. Includes Program Counter (PC), CPU registers, stack, heap, and data. OS keeps a PCB for each process.
PCB Contents
PID (unique ID), Process State, Program Counter, CPU Registers, Memory limits, Open files list, Scheduling info.
State 1 – New
Process being created. fork() system call used. Just entered the system.
State 2 – Ready
Loaded in memory. Waiting for CPU. Sitting in Ready Queue.
State 3 – Running
Currently executing on CPU. Only ONE process runs per CPU at a time.
State 4 – Waiting/Blocked
Waiting for IO (disk read, keyboard input). NOT using CPU at all.
State 5 – Terminated
Finished execution. exit() called. OS reclaims all resources.
State Transitions
New→Ready (admitted) | Ready→Running (CPU dispatched) | Running→Waiting (IO request) | Waiting→Ready (IO done) | Running→Terminated (exit)
💡 Example
Example: You open Chrome = New state. OS loads it = Ready. You click = Running. Chrome downloads = Waiting. You close = Terminated.
🔴 Conclusion
Conclusion: Every process goes through NRRWT. PCB is its identity card. Context switch = save current PCB + load next = overhead (wasted time).

Q6 12M ⭐ ⭐⭐ CLASS TEST 2026 Q1(5M) | AKU VVI Q4★★… What is CPU Scheduling? Explain FCFS, SJF, Priority and Round Robin with Gantt charts and examples. ▼
💡 One-Line: CPU Scheduling = pick process from Ready Queue for CPU. TT=CT-AT, WT=TT-BT. RR = BEST for time-sharing!
🧠 FSP-R: FCFS=Convoy, SJF=Starvation, Priority=Starvation, RR=BEST! | TT=CT-AT | WT=TT-BT
📘 Introduction / Definition
CPU Scheduling = deciding which process from Ready Queue gets CPU next. Done by Short-Term Scheduler in milliseconds.
Introduction
CPU Scheduling = deciding which process from Ready Queue gets CPU next. Done by Short-Term Scheduler in milliseconds.
Goals
↑ CPU Utilization (keep busy) | ↑ Throughput (more jobs/hour) | ↓ TT = CT-AT (turnaround) | ↓ WT = TT-BT (waiting)
Process State (From Ready to Running)
Scheduler selects from Ready Queue → Dispatcher gives CPU → Process moves Ready→Running. If IO needed: Running→Waiting. Quantum expires: Running→Ready.
1. FCFS – First Come First Served
Rule: First arrived = first served. NON-PREEMPTIVE. P1(24ms), P2(3ms), P3(3ms) all at t=0.
FCFS Gantt
P1(0-24) → P2(24-27) → P3(27-30). WT: P1=0, P2=24, P3=27. Avg WT = 17ms. Problem = CONVOY EFFECT!
2. SJF – Shortest Job First
Rule: Shortest burst time first. NON-PREEMPTIVE. Gives MINIMUM average waiting time!
SJF Gantt
Order: P2(3ms)→P3(3ms)→P1(24ms). Gantt: P2(0-3)→P3(3-6)→P1(6-30). Avg WT = (0+3+6)/3 = 3ms. Problem = STARVATION. Fix = Aging!
3. Priority Scheduling
Rule: Highest priority (lowest number) runs first. Can be preemptive or non-preemptive. Problem = Starvation. Fix = Aging.
4. Round Robin – BEST
Rule: Fixed TIME QUANTUM (10-100ms) in circular rotation. PREEMPTIVE. Most fair!
RR Gantt
Quantum=4ms. P1(24ms),P2(3ms),P3(3ms). Gantt: P1(0-4)→P2(4-7)→P3(7-10)→P1(10-14)→...→P1(26-30). Avg WT = (4+7+6)/3 = 5.67ms.
Comparison Table
FCFS: Simple, no preempt, convoy effect. SJF: Min wait, no preempt, starvation. Priority: flexible, starvation. Round Robin: fair, preemptive, NO STARVATION = BEST TIME-SHARING!
💡 Example
Example: FCFS = Hospital queue (long patient first = others wait hours). RR = ATM machine (fixed time per person, fair to all).
🔴 Conclusion
Conclusion: Round Robin = BEST for time-sharing. Fair, preemptive, no starvation. SJF = minimum avg wait but starvation. FCFS = simplest but convoy effect kills performance!

Q7 4M ⭐ ⭐ AKU VVI Q6★ | Q7★… What is Critical Section? Explain its 3 requirements. What is a Semaphore? ▼
💡 One-Line: CS = code accessing shared resource (only 1 at a time). 3 rules = MBP. Semaphore = integer for sync (P=lock, V=unlock).
🧠 CS rules = MBP = Mutual exclusion, Bounded waiting, Progress | P()=Red Light=Stop | V()=Green Light=Go
📘 Introduction / Definition
Code segment accessing shared resources (variables, files). Only ONE process inside CS at a time. Prevents race conditions.
Critical Section
Code segment accessing shared resources (variables, files). Only ONE process inside CS at a time. Prevents race conditions.
M – Mutual Exclusion
Only one process in CS at any time. No two processes simultaneously.
B – Bounded Waiting
Every process must eventually enter CS. No infinite waiting forever.
P – Progress
If CS is empty and some process wants to enter, it MUST be allowed. No unnecessary delay.
Race Condition Example

Integer variable for process synchronization. Two atomic operations: wait()/P() and signal()/V().
wait(S) / P(S)

signal(S) / V(S)
S = S+1. Wake up blocked process (UNLOCK). Green Traffic Light = GO!

Binary (Mutex): 0 or 1 only. Like one bathroom key. Counting: 0 to N. Like N parking spaces.
💡 Example

🔴 Conclusion
Conclusion: CS prevents race conditions using MBP rules. Semaphore: P()=lock=S-1, V()=unlock=S+1. Binary=mutex(0/1). Counting=resource pool(0 to N).
Q8 4M ⭐ ⭐ AKU VVI Q8★★ | Class Test 2026 Q3(5M)… What is Deadlock? Explain the four necessary conditions with examples. ▼
💡 One-Line: Deadlock = processes stuck forever, each holding resources waiting for others. 4 conditions = MH-NC (ALL must hold).
🧠 MH-NC = Monkeys Hold Noodles Carefully | Remove ANY ONE condition = NO DEADLOCK!
📘 Introduction / Definition
A set of processes permanently blocked. Each holds resources AND waits for resources held by others. Nobody can move. System freezes!
Deadlock Definition
A set of processes permanently blocked. Each holds resources AND waits for resources held by others. Nobody can move. System freezes!
Example
P1 holds Printer (needs Scanner). P2 holds Scanner (needs Printer). Both wait forever = DEADLOCK!
Condition 1: Mutual Exclusion
Resource used by ONLY one process at a time. Example: Only one person can use a printer at once.
Condition 2: Hold and Wait
Process holds one resource AND waits for more without releasing. Example: P1 holds Printer, waits for Scanner.
Condition 3: No Preemption
Resources CANNOT be forcibly taken. Must be released voluntarily. Cannot snatch a pen from someone writing!
Condition 4: Circular Wait
Cycle of waiting: P1 waits for P2, P2 waits for P3, P3 waits for P1. A closed loop!
KEY RULE
ALL 4 conditions must hold SIMULTANEOUSLY. Remove ANY ONE = NO DEADLOCK possible!
💡 Example
Example: Three friends: Raju holds cycle (wants bat) → Sham holds bat (wants helmet) → Babu holds helmet (wants cycle). All stuck forever = DEADLOCK!
🔴 Conclusion
Conclusion: Deadlock occurs only when ALL 4 Coffman conditions (MH-NC) hold simultaneously. Eliminate any ONE condition = no deadlock. This is the basis of ALL deadlock prevention!
Q9 12M ⭐ ⭐⭐ CLASS TEST 2026 Q3(5M) | AKU VVI Q8★★… Explain Deadlock completely: 4 conditions, prevention, avoidance (Banker's), detection and recovery. ▼
💡 One-Line: 4 conditions=MH-NC. 4 methods=Prevention(break condition)+Avoidance(Banker's)+Detection(RAG)+Recovery(kill/preempt). Need = Max minus Allocation.
🧠 MH-NC conditions | PADR = Prevention, Avoidance, Detection, Recovery | Banker's KEY: Need = Max - Allocation
📘 Introduction / Definition
Deadlock is a critical OS problem where processes freeze permanently. OS must detect/prevent it to keep system running.
Introduction
Deadlock is a critical OS problem where processes freeze permanently. OS must detect/prevent it to keep system running.
Definition
Set of processes permanently blocked. Each holds resources AND waits for others' resources. No process can proceed.
4 Conditions (MH-NC)
ALL must hold simultaneously: Mutual Exclusion + Hold&Wait + No Preemption + Circular Wait. Remove ANY ONE = NO DEADLOCK!
Method 1: Prevention
Break one of 4 conditions: No ME (use spooler) | No H&W (request all at start) | Allow Preemption (OS takes resources) | No Circular Wait (order resources, request in increasing order).
Method 2: Avoidance
Banker's Algorithm: Before giving resource, check if SAFE STATE exists. Safe = all processes can finish in some sequence.
Banker's Formula
Need[i] = Max[i] - Allocation[i]. Find process where Need ≤ Available → simulate finish → release resources → repeat. If all finish = SAFE!
Banker's Example
Available={A=3,B=3,C=2}. P1 Need={1,2,2}. Check: 1≤3,2≤3,2≤2 = YES! Run P1. Available increases. Continue for all. Safe Sequence = P1→P3→P4→P0→P2.
Method 3: Detection
Allow deadlock. Use Resource Allocation Graph (RAG). If CYCLE exists = DEADLOCK! Run detection periodically (every hour or when CPU drops suddenly).
Method 4: Recovery
Process Termination: Kill ALL deadlocked processes (expensive) OR kill ONE at a time till cycle breaks. Resource Preemption: Forcibly take resource, give to other, rollback victim to checkpoint.
Comparison
Prevention = safest but wasteful resources | Avoidance (Banker's) = practical, needs max info | Detection = cheap but deadlock already happened | Recovery = after detection only.
💡 Example
Example: Banker's: P1 needs {1,2,2} and Available={3,3,2}. Since 1≤3, 2≤3, 2≤2, P1 can run. After P1, available increases. Safe sequence found = grant request!
🔴 Conclusion
Conclusion: Deadlock is dangerous. 4 Coffman conditions (MH-NC) must ALL hold. We handle via Prevention, Avoidance (Banker's), Detection (RAG), Recovery (kill/preempt). Most real systems use Prevention + Detection together. KEY FORMULA: Need = Max - Allocation!

Q10 4M ⭐ ⭐ AKU VVI Q12★★★… Explain Paging with diagram. How does address translation work? ▼
💡 One-Line: Paging = fixed-size pages→frames. Page table maps page→frame. TLB=fast cache. No external fragmentation!
🧠 Paging = Book pages (equal size, any shelf). Physical = Frame[p] × Size + Offset. TLB = fast shortcut!
📘 Introduction / Definition
Logical memory (program) divided into fixed-size PAGES. Physical memory (RAM) divided into same-size FRAMES. OS keeps PAGE TABLE mapping pages to frames.
Paging Definition
Logical memory (program) divided into fixed-size PAGES. Physical memory (RAM) divided into same-size FRAMES. OS keeps PAGE TABLE mapping pages to frames.
Key Advantage
NO External Fragmentation! Pages can go in ANY free frame. Only internal fragmentation in last page.
Logical Address
Generated by CPU. Divided into: Page Number (p) + Page Offset (d).
Physical Address
Frame[p] × Frame_Size + Offset(d). Translated by MMU (Memory Management Unit).
TLB
Translation Lookaside Buffer = hardware cache for page table entries. Makes address translation FAST! TLB hit = direct access, no delay.
Page Table
One per process. Maps each page number to its frame number in RAM. Stored in memory.
💡 Example
Example: Page size=4KB. Logical address=8192. Page no = 8192/4096 = 2. Offset = 8192 mod 4096 = 0. If Page 2 → Frame 5, Physical = 5×4096 + 0 = 20480.

📘 Introduction / Definition
When RAM is full and new page needed, existing page must be replaced. Algorithm decides WHICH page to remove.
Need for Page Replacement
When RAM is full and new page needed, existing page must be replaced. Algorithm decides WHICH page to remove.
FIFO Algorithm
Replace the OLDEST loaded page. Simple queue. Put new at back, remove from front.
FIFO Problem
BELADY'S ANOMALY: More frames can give MORE page faults! Counter-intuitive! Very unreliable.
LRU Algorithm
Replace page NOT used for LONGEST TIME. Looks backward at history. Best practical choice!
LRU Advantage
NO Belady's Anomaly! Page faults always ≤ FIFO faults. Based on past usage (good predictor of future).
Optimal Algorithm
Replace page not needed for LONGEST FUTURE TIME. Best possible (minimum faults) but IMPOSSIBLE online (need future knowledge). Used as benchmark only.

Conclusion: LRU = BEST practical page replacement. FIFO = simple but Belady's Anomaly problem. Optimal = benchmark only, impossible in practice. Always prefer LRU!

Q1. Define an Operating System. Explain its functions, objectives and major services.
12 Marks
📘 Introduction:
An Operating System (OS) is system software that sits between the user and the computer hardware. It manages all resources (CPU, memory, I/O devices, files) and provides services to programs and users.
📗 Definition:
An OS is a program that manages computer hardware and software resources and provides a convenient environment for the execution of user programs.

  • Convenience — make the system easy to use
  • Efficiency — use resources effectively
  • Ability to evolve — support new technologies and features
  • Reliable and secure — prevent unauthorized access
  • Good environment — for program execution
🔶 Major Services (8 Services):
  • 1. Program execution    2. I/O operations

  • 5. Error handling      6. Resource allocation
  • 7. Security and protection    8. User interface

Q3. What is a process? Explain the process states and Process Control Block (PCB) with a suitable diagram.
12 Marks
📘 Introduction:
In a multiprogramming OS, multiple programs run at the same time. Each running program is called a process. The OS manages processes using a special data structure called PCB.
📗 1. Process:
A process is a program in execution. It is an active entity that has its own address space, resources, and execution context. A program becomes a process when it is loaded into memory and starts executing.
🔶 2. Process States:
A process can be in one of the following states:
  • New — process is being created
  • Ready — process is ready to execute
  • Running — process is currently executing
  • Waiting/Blocked — process is waiting for an event
  • Terminated — process has finished execution
📊 Process State Diagram:
         Admit           Dispatch         Exit
  New ──────────► Ready ──────────► Running ──────────► Terminated
                    ▲                  │
                    │ Event            │ I/O Request
              Event │ Completion       │ or Event Wait
             Completion                ▼
                    └──────────── Waiting (Blocked)
🔶 3. Process Control Block (PCB):
PCB is a data structure maintained by the OS for every process. It stores all information about the process.

Contents of PCB:
  • 1. Process ID (PID)
  • 2. Process state
  • 3. Program counter (PC)
  • 4. CPU registers
  • 5. CPU scheduling information
  • 6. Memory management information
  • 7. I/O status information
  • 8. Accounting information
🔴 Conclusion:
A process goes through different states during its execution. PCB helps the OS to manage and control each process effectively by storing all its information.
⭐ MEMORY TRICK: Process States: "New Ready Running Waiting Terminated"
Remember: "Never Rest, Run Well, Try" (N-R-R-W-T)
PCB Contents: PID + State + PC + Registers + Memory + I/O + Accounting

In modern operating systems, processes can be divided into smaller units called threads. Threads help achieve better CPU utilization and concurrency within a process.
📗 1. Thread:
A thread is the smallest unit of CPU utilization. It is a lightweight process. A thread shares the same address space and resources of a process. It was proposed by researchers to improve concurrency.
🔶 2. Types of Threads:
  • User Level Threads (ULT) — managed by user level thread library, fast but blocking
  • Kernel Level Threads (KLT) — managed by OS, can run in parallel on multiple CPUs
  • Multi-threading Models:

    • One-to-One — one user thread to one kernel thread
    • Many-to-Many — many user threads to many kernel threads

Q6. What is the critical-section problem? Explain its requirements and solutions.
12 Marks
📘 Introduction:
In a concurrent system, multiple processes share data and resources. The critical-section problem is to design a protocol so that when one process is executing its critical section (CS), no other process can execute its CS for the same shared data.
📗 2. Critical Section:
A critical section is a part of the program where shared resources (data/files/variables) are accessed and modified. Example: updating a shared variable, writing in a file, accessing a printer.
🔶 3. Requirements (3 Conditions — Must satisfy ALL):
  • 1. Mutual Exclusion: Only one process can execute in its critical section at a time.
  • 2. Progress: If no process is in CS, the selection of next process must not be postponed indefinitely.
  • 3. Bounded Waiting: After a process requests to enter CS, there is a limit on the number of times other processes can enter their CS before its request is granted.
📊 4. Structure of a Process with CS:
do { Entry Section (Request to enter CS) Critical Section (Access shared resource) Exit Section (Release resource) Remainder Section (Other work) } while (true);
🔶 5. Solutions to Critical Section Problem:
  • 1. Peterson's Solution — software based, works for 2 processes
  • 2. Semaphores (Dijkstra) — most widely used
  • 3. Monitors — high level synchronization
  • 4. Message Passing (send/receive)
  • 5. Hardware Instructions (Test and Set, Compare and Swap)
🔴 Conclusion:
Proper synchronization avoids race condition and ensures safe access to shared resources. All solutions must satisfy Mutual Exclusion, Progress, and Bounded Waiting.
⭐ MEMORY TRICK: 3 Requirements: MPB
M = Mutual Exclusion   P = Progress   B = Bounded Waiting
Remember: "Must Pass Bound" (MPB)

Q7. What is a semaphore? Explain binary and counting semaphores with suitable examples.
12 Marks
📘 Introduction:
A semaphore is a synchronization tool used to control access to shared resources. It was proposed by E.W. Dijkstra. It is an integer variable that can only be accessed through two atomic operations: wait(S) and signal(S).
📗 1. Semaphore:
A semaphore is a synchronization tool (variable) used to control access to shared resources. It is an integer variable that can only be accessed through two atomic operations: wait(P) and signal(V).
🔶 2. Semaphore Operations:
wait(S) or P(S):
wait(S) { while (S <= 0); // busy wait S = S - 1; }
signal(S) or V(S):
signal(S) { S = S + 1; }
🔶 3. Binary Semaphore:
  • Value can be only 0 or 1
  • Used for mutual exclusion (to allow only one process at a time)
  • Also called a mutex
  • Example: controlling access to a critical section
Semaphore S = 1; // binary semaphore wait(S); // critical section signal(S); // V(S)
→ Only one process can enter CS at a time.
🔶 4. Counting Semaphore:
  • Value can be any non-negative integer
  • Used to control access to multiple instances of a resource
  • If S = n, then at most n processes can access the resources simultaneously
  • Example: Suppose there are 3 printers. Initialize S = 3.
Semaphore S = 3; // counting semaphore wait(S); // request a printer // use printer signal(S); // release printer
🔶 Key Differences:
BasisBinary SemaphoreCounting Semaphore
Value0 or 10, 1, 2, … n
UseMutual exclusionMultiple resource access
ExampleCritical sectionPrinters, memory blocks
CalledMutexGeneral semaphore
🔴 Conclusion:
Semaphore is an integer variable with atomic wait and signal operations. Binary semaphore allows only one process. Counting semaphore allows multiple processes (up to n). Used for process synchronization and resource management.
⭐ MEMORY TRICK: wait(S) = P = Probeer = TRY (decrements S)
signal(S) = V = Verhoog = INCREMENT (increments S)
Binary S = 0 or 1 (like ON/OFF switch)
Counting S = 0 to n (like tickets available)

Q8. What is deadlock? Explain the four necessary conditions for deadlock with examples.
12 Marks
📘 Introduction:
Deadlock is a critical issue in OS. Understanding its necessary conditions helps in designing prevention, avoidance and recovery techniques.
📗 1. Deadlock:
A deadlock is a situation in which two or more processes are waiting for resources that will never be released, so they remain blocked forever. It occurs when each process holds one or more resources and waits for resources held by other processes.
✅ 2. Example of Deadlock:
  • Process P1 holds Resource R1 and waits for R2
  • Process P2 holds Resource R2 and waits for R1
  • Both are waiting indefinitely → deadlock
📊 Resource Allocation Graph (Deadlock):
    P1 ──requests──► R2 (held by P2)
    ↑                      │
   R1 (held by P1) ◄──requests── P2
   → P1 and P2 are in DEADLOCK!
🔶 3. Four Necessary Conditions (ALL must be true for deadlock):
  • 1. Mutual Exclusion: At least one resource is non-shareable (only one process can use it). Example: Printer, Tape drive.
  • 2. Hold and Wait: A process holding one or more resources waits for additional resources. Example: P1 holds R1 and requests R2.
  • 3. No Preemption: Resources cannot be forcibly taken away from a process. Resource is released only by the process itself. Example: Resource is released only by process.
  • 4. Circular Wait: A circular chain of processes exists where each process waits for a resource held by the next process. Example: P1 → P2 → P3 → P1.
🔴 Conclusion:
Deadlock is a critical issue in OS. Understanding its necessary conditions helps in designing prevention, avoidance and recovery techniques. If ANY ONE condition is removed, deadlock will NOT occur.
⭐ MEMORY TRICK: 4 Conditions: MHNC
M = Mutual Exclusion   H = Hold and Wait
N = No Preemption     C = Circular Wait
Remember: "My Hungry Nephew Cries" (MHNC)

Q9. Explain deadlock prevention, avoidance, detection and recovery techniques.
12 Marks
📘 Introduction:
Deadlock handling can be done by prevention, avoidance, detection and recovery. In practice, a combination of these techniques is used to make the system efficient and reliable.
🔶 1. Deadlock Prevention:
Prevention ensures that at least one of the four necessary conditions never holds.
Methods:
  • Mutual Exclusion — Make resources shareable (e.g., spooling)
  • Hold and Wait — Request all resources at once before execution
  • No Preemption — Allow preemption of resources (if process requests new resource, release held resources)
  • Circular Wait — Impose a strict ordering on resource types (e.g., R1→R2→R3)
Disadvantage: Less resource utilization, not always practical.
🔶 2. Deadlock Avoidance:
  • Avoids deadlock by checking in advance whether the system will remain in a safe state
  • Uses additional information about maximum resource requirements
  • Main algorithm: Banker's Algorithm
  • If a request keeps the system in a safe state → grant it, otherwise → deny it
Safe State: System can allocate resources without deadlock.
Unsafe State: May lead to deadlock, but not always.
🔶 3. Deadlock Detection:
  • Allow deadlock to occur, then detect it
  • Methods:
    • Wait-for Graph (WFG): Node=process, Edge Pi→Pj means Pi is waiting for Pj. If cycle exists → deadlock
    • Resource Allocation Matrix: Maintain Allocation, Request and Available matrices. Use detection algorithm to find deadlocked processes
🔶 4. Deadlock Recovery:
After detection, system must recover.
Methods:
  • Process Termination:
    • Abort all deadlocked processes (high cost)
    • Abort one process at a time (choose victim)
  • Resource Preemption:
    • Take resources from some processes and give to others
    • Use rollback to previous state
    • Avoid starvation by proper victim selection
🔶 Comparison Table:
TechniqueWhen AppliedMain IdeaAdvantageDisadvantage
PreventionBefore deadlockBreak one of 4 conditionsSimple conceptLow resource utilization
AvoidanceBefore deadlockKeep system in safe stateBetter resource useNeeds extra info (Max requirement)
DetectionAfter deadlockFind deadlock using WFG/matricesWorks in real systemsOverhead of detection
RecoveryAfter detectionTerminate or preempt processesRemoves deadlockMay lose data
🔴 Conclusion:
Deadlock handling can be done by prevention, avoidance, detection and recovery. In practice, a combination of these techniques is used to make the system efficient and reliable.
⭐ MEMORY TRICK: PADR = Prevention → Avoidance → Detection → Recovery
Remember: "Please Avoid Deadly Results" (PADR)
Prevention = Stop BEFORE | Avoidance = Check BEFORE | Detection = Find AFTER | Recovery = Fix AFTER

Q10. Explain the Banker's Algorithm for deadlock avoidance with a suitable example.
12 Marks
📘 Introduction:
Banker's Algorithm is a deadlock avoidance algorithm. It checks whether a resource request can be granted without leaving the system in an unsafe state.
📗 1. Banker's Algorithm:
Banker's Algorithm is a deadlock avoidance algorithm. It checks whether a resource request can be granted without leaving the system in an unsafe state. It uses the following information:
  • Available — Number of available resources
  • Max — Maximum resources required by each process
  • Allocation — Resources currently allocated
  • Need — Remaining resources (Need = Max − Allocation)
🔶 2. Algorithm Steps:
  • 1. Initialize Available, Max, Allocation and Need matrices
  • 2. When a process Pi requests resources:
    • a. Check if Request[i] ≤ Need[i] (otherwise error)
    • b. Check if Request[i] ≤ Available (otherwise Pi must wait)
    • c. Temporarily allocate the resources and check if resulting state is safe
    • d. If safe → grant the request. If not safe → Pi must wait
🔶 3. Safety Algorithm:
  • 1. Set Work = Available and Finish[i] = false for all processes
  • 2. Find a process Pi such that Finish[i] = false and Need[i] ≤ Work
  • 3. If found → Work = Work + Allocation[i] and Finish[i] = true
  • 4. Repeat step 2 until all processes finish
  • 5. If all Finish[i] = true → system is in safe state. Otherwise → unsafe state
✅ 4. Example:
Assume 3 processes (P0, P1, P2) and 3 resource types (A, B, C).
🔶 Matrices:
ProcessMax (A,B,C)Allocation (A,B,C)Need (A,B,C)Available (A,B,C)
P07 5 30 1 07 4 33 3 2 (initial)
P13 2 22 0 01 2 2
P29 0 23 0 26 0 0
✅ 5. Find Safe Sequence:
  • Initial Work = (3, 3, 2)
  • P1 can execute (Need = 1,2,2 ≤ Work = 3,3,2) → Work = (3,3,2) + (2,0,0) = (5,3,2)
  • P2 can execute (Need = 6,0,0 ≤ Work = 5,3,2? No) → Skip
  • P0 can execute (Need = 7,4,3 ≤ Work = 5,3,2? No) → Skip
  • After P1: Work = (5,3,2). P2 (Need=6,0,0 > 5,3,2) No. Check again...
  • Actually: P1→P0→P2 works → Safe Sequence: P1 → P0 → P2
🔴 Conclusion:
Banker's Algorithm is an efficient deadlock avoidance technique. By checking for safe state before allocation, it ensures that the system never enters a deadlock.
⭐ MEMORY TRICK: Banker's Key Formula: Need = Max − Allocation
Safe State = All processes can finish in SOME order
If Request ≤ Need AND Request ≤ Available → Try to allocate → Check safety

Q12. Explain paging and segmentation. Differentiate between paging and segmentation.
12 Marks
📘 Introduction:
Paging and segmentation are non-contiguous memory allocation techniques used to eliminate fragmentation and allow efficient use of memory.
📗 1. Paging:
Paging is a memory management scheme in which the logical memory is divided into fixed size blocks called pages and the physical memory is divided into fixed size blocks called frames. Pages are mapped to frames using a page table.
📊 Paging Diagram:
 Logical Address    Page Table    Physical Memory
   Page 0    ──►  [0 → Frame 5] ──►  Frame 5
   Page 1    ──►  [1 → Frame 2] ──►  Frame 2
   Page 2    ──►  [2 → Frame 7] ──►  Frame 7
   Page 3    ──►  [3 → Frame 1] ──►  Frame 1
📗 2. Segmentation:
Segmentation is a memory management scheme in which a process is divided into variable size segments such as code, data, stack, etc. Each segment has a base address and a limit. It is more logical and user oriented than paging.
📊 Segmentation Diagram:
 Logical Addr    Segment Table     Physical
  Segment: Code  [Base=1000,Lim=4000] → 1000-5000
  Segment: Data  [Base=5000,Lim=2000] → 5000-7000
  Segment: Stack [Base=8000,Lim=1000] → 8000-9000
🔶 Difference between Paging and Segmentation:
BasisPagingSegmentation
DivisionFixed size pagesVariable size segments
Based onPhysical memoryLogical view (program)
SizeAll pages are of same sizeSegments are of different size
AddressUses page number and offsetUses segment number and offset
FragmentationNo external fragmentation (only internal)May have external fragmentation
VisibilityNot visible to userVisible to user (code, data, stack etc.)
ExamplePage size = 4 KBCode=4KB, Data=2KB, Stack=1KB
🔶 Key Points:
  • Paging is transparent to user
  • Segmentation is more flexible
  • Both are non-contiguous allocation
  • Paging eliminates external fragmentation
  • Segmentation supports protection and sharing easily
🔴 Conclusion:
Both paging and segmentation are important memory management techniques. Paging is simpler and eliminates external fragmentation. Segmentation is more logical and user-friendly. Modern OS use a combination of both.

Q13. What is virtual memory? Explain demand paging and its advantages.
12 Marks
📘 Introduction:
Virtual memory is a memory management technique that allows the execution of processes larger than the actual physical memory. It uses secondary storage (disk) as an extension of main memory.
📗 1. Virtual Memory:
Virtual memory is a memory management technique that gives the appearance of a very large memory to the process, even though the physical memory is smaller. It uses secondary storage (disk) as an extension of main memory.
🔶 2. Demand Paging:
In demand paging, a page is loaded into memory only when it is needed (on demand). If a page is not in memory, a page fault occurs and the required page is brought from the disk.
  • Pages are loaded only when needed
  • Reduces memory usage
  • Uses page table with valid-invalid bits
  • If valid bit = 0 → page fault → load from disk

🔶 3. Advantages of Virtual Memory:
  • Improves memory utilization
  • Allows large programs to run
  • Reduces I/O (only needed pages are loaded)
  • Increases degree of multiprogramming
  • Better response time
  • No need to load entire process in memory
🔶 4. Page Fault:
A page fault occurs when the required page is not in the memory. The OS handles it by loading the page from disk into memory. High page fault rate → poor performance (called thrashing).
🔴 Conclusion:
Virtual memory is a powerful technique that allows processes larger than physical memory to run. Demand paging is the most common implementation. It improves performance, but excessive page faults can slow the system down.
⭐ MEMORY TRICK: Virtual Memory = Big RAM illusion using Disk
Demand Paging = Load page ONLY when NEEDED (lazy loading)
Page Fault = Page NOT in RAM → load from DISK → restart instruction

Q18. Explain file permissions in UNIX. Describe chmod, chown and chgrp commands with examples. Also explain hard links and soft links.
12 Marks
📘 Introduction:
Permissions control access to files. chmod, chown, chgrp manage permissions, ownership and group. Hard link and soft link are two types of links in UNIX.
📗 1. File Permissions:
  • Each file has 3 types of permissions: Read (r), Write (w), Execute (x)
  • Shown for: User (u), Group (g), Others (o)
  • Example: -rwxr-xr-- means Owner=rwx, Group=r-x, Others=r--
  • Octal: r=4, w=2, x=1 → 755 means rwxr-xr-x
📊 Permission Format:
 -  rwx  r-x  r--
 ↑   ↑    ↑    ↑
type owner group others

r=4, w=2, x=1
755 = rwxr-xr-x (Owner: all, Group: read+exec, Others: read+exec)
644 = rw-r--r-- (Owner: read+write, Group: read, Others: read)
🔶 2. chmod command:
  • Changes file permissions
  • Syntax: chmod mode file
  • Example: chmod 755 file.txt → rwxr-xr-x
  • Owner: rwx, Group: r-x, Others: r-x
🔶 3. chown command:
  • Changes file owner
  • Syntax: chown user file
  • Example: chown rahman file.txt
🔶 4. chgrp command:
  • Changes group of a file
  • Syntax: chgrp group file
  • Example: chgrp students file.txt
🔶 5. Hard Link:
  • Another name for the same file (inode)
  • Syntax: ln file.txt link1
  • Both point to same data
  • Deleting original does NOT delete data
🔶 6. Soft Link (Symbolic Link):
  • A link to a file (different inode)
  • Syntax: ln -s file.txt link2
  • Points to file path (like shortcut)
  • If original deleted → link broken
🔴 Conclusion:
Permissions control access to files. chmod, chown, chgrp manage permissions, ownership and group. Hard link shares inode; soft link is a reference to another file.
⭐ MEMORY TRICK: chmod 755 = rwxr-xr-x | chmod 644 = rw-r--r--
r=4, w=2, x=1 → add them: 7=rwx, 6=rw-, 5=r-x, 4=r--
Hard link = SAME inode (like twin) | Soft link = DIFFERENT inode (like shortcut)

Q19. What is I/O redirection and piping in UNIX? Explain >, >>, < and | with suitable examples. Also explain the concept of filters.
12 Marks
📘 1. Introduction:
I/O redirection and piping are features of UNIX shell that allow us to change the standard input and output of a command. Filters are programs that read input, process it and produce output.
📗 2. I/O Redirection:
By default, a command takes input from keyboard (standard input) and gives output on screen (standard output). Redirection allows us to change this default behavior.
🔶 3. Types of Redirection Operators:
OperatorNamePurposeExample
>Output RedirectionSends output to a file (overwrites existing file)ls > file.txt
>>Append RedirectionSends output to a file (appends at end)ls >> file.txt
<Input RedirectionTakes input from a file (instead of keyboard)sort < data.txt
|PipeSends output of one command to another command (piping)ls | more
✅ 4. Examples:
  • ls > list.txt → create file with output
  • ls >> list.txt → add output to file
  • sort < names.txt → take input from file
  • cat file.txt | more → pipe output to another command
  • ps | grep bash → find bash process
  • cat file.txt | wc → count words
  • ls -l | sort → sort the output
  • who | grep rahman → search user
🔶 5. Filters:
  • A filter is a program that reads input, processes it and produces output
  • Common filters: sort, grep, wc, head, tail, cut, tr, awk etc.
  • Filters are used with pipes to perform complex operations
  • Example: ls -l | grep txt (shows only files with .txt)
🔶 Key Points:
  • > overwrites, >> appends
  • < takes input from file
  • | connects two commands
  • Filters process text data
  • Useful for automation and scripting
🔴 Conclusion:
I/O redirection and piping make UNIX powerful by allowing flexible input and output handling. Filters are essential for text processing and are widely used in shell scripting.
⭐ MEMORY TRICK: Redirection: > overwrite | >> append | < input | | pipe
Remember: "> = shoot output to file | >> = add more | < = take from file | | = connect"
Filters: sort, grep, wc, head, tail, cut, tr, awk

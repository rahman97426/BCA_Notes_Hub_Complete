Section A: Unit 1 — Introduction to OS

OS Definition | Types | Functions | Objectives

8M ★★ Q1 | Sec A Define an Operating System. Explain its functions, objectives, and major services.
📝 EXAM ANSWER — Write Exactly This in Copy:

Definition: An Operating System (OS) is system software that acts as an interface between the user and computer hardware. It manages all hardware resources (CPU, memory, I/O devices, files) and provides services to user programs and users.

Example: Windows 11, Linux (Ubuntu), Android, macOS, iOS, UNIX

Objectives of OS:

  1. Convenience: Make computer easier to use — user does not need to know hardware details.
  2. Efficiency: Manage resources efficiently — maximize CPU utilization, minimize waste.
  3. Ability to Evolve: Allow development of new system functions without interfering with existing ones.

Major Functions of OS (PIFCERP):

  1. Process Management: Creates, schedules and terminates processes. Allocates CPU time using scheduling algorithms (FCFS, SJF, RR).
  2. I/O Operations: Controls input/output devices through device drivers. Handles keyboard, mouse, printer, disk.
  3. File Management: Creates, reads, writes, deletes files and directories. Manages file permissions and directory structure.
  4. Communication: Allows processes to exchange data — same machine (shared memory, pipes) or network (sockets).
  5. Error Detection: Monitors CPU, memory, I/O for errors. Takes corrective action (App crash = OS handled it).
  6. Resource Allocation: Distributes CPU, memory, I/O among multiple processes efficiently.
  7. Protection & Security: Prevents unauthorized access. User authentication (passwords, biometrics). File permissions.

Major OS Services:

  • Program Execution — loads and runs programs
  • I/O Operations — handles all device communication
  • File System Manipulation — file create/read/write/delete
  • Error Detection — handles hardware and software errors
  • Resource Allocation — CPU, memory, disk allocation
  • Accounting — tracks resource usage (billing in shared systems)
Conclusion: The OS is the most essential software in a computer. Without OS, hardware cannot be used. It acts as manager, translator and security guard of the entire computer system.

8M ★★ Q2 | Sec A Explain different types of Operating Systems: Batch, Multiprogramming, Multitasking, Time-Sharing, Real-Time and Distributed OS.
📝 EXAM ANSWER — Write Exactly This in Copy:

1. Batch Operating System:

  • Jobs collected and processed in batches without user interaction.
  • Operator groups similar jobs together and submits to computer.
  • Disadvantage: No user interaction. Long waiting time.
  • Example: Early IBM mainframes, Payroll processing.

2. Multiprogramming OS:

  • Multiple programs kept in memory simultaneously.
  • When one program waits for I/O, CPU switches to another.
  • Goal: Maximize CPU utilization — CPU never idle!
  • Example: UNIX — antivirus runs while Word is open.

3. Multitasking OS:

  • Multiple tasks executed simultaneously with CPU switching rapidly.
  • Extension of multiprogramming with time-sharing concept.
  • User can switch between applications smoothly.
  • Example: Modern Windows — browser + music + chat simultaneously.

4. Time-Sharing OS:

  • CPU time divided into fixed intervals called time slices (quantum).
  • Each user/process gets one slice in circular rotation.
  • So fast that every user feels the computer is dedicated to them.
  • Goal: Minimize response time.
  • Example: IRCTC handles lakhs of users simultaneously.

5. Real-Time OS (RTOS):

  • Hard Real-Time: Deadline miss = Complete system failure. Ex: Pacemaker, missile guidance, aircraft autopilot, nuclear reactor.
  • Soft Real-Time: Deadline miss = Performance degradation, not failure. Ex: Video streaming, gaming, ATM.
  • Algorithms: Rate Monotonic (RM), Earliest Deadline First (EDF).

6. Distributed OS:

  • Multiple computers connected over a network work as a single unified system.
  • Resources shared across network. Users see a single coherent system.
  • Example: Google's distributed computing, cloud computing.

Section B: Unit 2 — Process Management

Process | PCB | States | CPU Scheduling | Threads

12M ★★★ Q3 | Sec B What is a process? Explain the process states and Process Control Block (PCB) with a suitable diagram.
📝 EXAM ANSWER — Write Exactly This in Copy:

Process: A process is a program in execution. It is more than just code — it includes the program counter, CPU registers, stack, heap and data section. The OS manages processes through PCB.

Components of a Process:

  • Text Section: Program code (instructions)
  • Data Section: Global variables
  • Stack: Function parameters, return addresses, local variables
  • Heap: Dynamically allocated memory
  • Program Counter (PC): Address of next instruction to execute

PCB — Process Control Block: Data structure maintained by OS for each process. Acts as the process's identity card.

PCB Contents:

  1. Process ID (PID): Unique identifier for each process.
  2. Process State: Current state (New/Ready/Running/Waiting/Terminated).
  3. Program Counter: Address of next instruction.
  4. CPU Registers: Accumulator, index registers, stack pointer values.
  5. Memory Management Info: Base/limit registers, page table pointers.
  6. Open Files List: Files currently opened by process.
  7. Scheduling Information: Priority, queue pointers, scheduling algorithm data.
  8. I/O Status Information: Allocated I/O devices, pending I/O requests.

Five Process States:

  1. New: Process is being created. fork() system call invoked.
  2. Ready: Process is in memory and waiting to be assigned the CPU.
  3. Running: Process instructions are currently being executed on CPU.
  4. Waiting/Blocked: Process waiting for I/O operation or event to occur.
  5. Terminated: Process has finished execution. exit() called. Resources reclaimed.

Context Switch: When CPU switches from one process to another. Save current PCB → Load next PCB. Pure overhead — no useful work during switch!

Types of Schedulers:

  • Long-term (Job) Scheduler: Controls multiprogramming degree. New → Ready. Slow.
  • Short-term (CPU) Scheduler: Selects from ready queue. Most important. Milliseconds.
  • Medium-term (Swapper): Swaps processes in/out of memory.
Conclusion: PCB is the identity card of a process. The five-state model describes the complete process lifecycle. Context switching enables multitasking but adds overhead.

12M ★★★ Q4 | Sec B Explain CPU scheduling. Describe FCFS, SJF, Priority and Round Robin scheduling algorithms with suitable examples.
📝 EXAM ANSWER — Write Exactly This in Copy:

CPU Scheduling: The process of selecting a process from the ready queue and allocating the CPU to it. Done by the Short-term Scheduler in milliseconds.

Scheduling Criteria: CPU Utilization (↑ maximize), Throughput (↑), Turnaround Time (↓ minimize), Waiting Time (↓), Response Time (↓).

Formulae: Turnaround Time (TT) = Completion Time − Arrival Time | Waiting Time (WT) = TT − Burst Time

1. FCFS — First Come First Served:

  • Rule: Process arriving first gets CPU first. Non-preemptive.
  • Problem: Convoy Effect — long process blocks all short ones behind it.
P1(BT=24), P2(BT=3), P3(BT=3), all arrive at t=0
Gantt: |————P1(0–24)————|—P2(24–27)—|—P3(27–30)—|
WT: P1=0, P2=24, P3=27 → Avg WT = (0+24+27)/3 = 17ms

2. SJF — Shortest Job First:

  • Rule: Process with shortest burst time runs first. Non-preemptive (basic).
  • Gives minimum average waiting time among non-preemptive algorithms.
  • Problem: Starvation — long processes may never run. Fix: Aging.
SJF Order: P2(3ms) → P3(3ms) → P1(24ms)
Gantt: |—P2(0–3)—|—P3(3–6)—|————P1(6–30)————|
WT: P2=0, P3=3, P1=6 → Avg WT = (0+3+6)/3 = 3ms ← MUCH BETTER!

3. Priority Scheduling:

  • Rule: Process with highest priority (lowest priority number) runs first.
  • Can be preemptive or non-preemptive.
  • Problem: Starvation of low-priority processes. Fix: Aging (increase priority with waiting time).
  • Example: P1(Priority=3), P2(Priority=1), P3(Priority=2) → Order: P2 → P3 → P1

4. Round Robin (RR) — Best for Time-Sharing:

  • Rule: Each process gets a fixed time quantum (10–100ms) in circular rotation. Preemptive.
  • Advantages: Fair, No starvation, Best for time-sharing/interactive systems.
  • Disadvantage: High context switch overhead if quantum too small.

8M ★★ Q5 | Sec B What is a thread? Explain the types of threads and differentiate between a process and a thread.
📝 EXAM ANSWER — Write Exactly This in Copy:

Thread: A thread is the smallest unit of CPU execution within a process. Multiple threads in the same process share the same memory space, code and data. Threads are also called Lightweight Processes (LWP).

Types of Threads:

1. User Level Threads (ULT):

  • Managed by user-space libraries (e.g., POSIX Pthreads). OS is not aware of them.
  • Fast creation and context switching.
  • Disadvantage: If one thread makes a blocking system call, ALL threads in the process block.
  • Example: Java threads (Green threads), POSIX pthreads.

2. Kernel Level Threads (KLT):

  • Directly managed by the OS kernel.
  • If one thread blocks, others can continue running independently.
  • Slower creation but more reliable and better parallelism.
  • Example: Windows threads, Linux clone().

3. Hybrid Threads:

  • Combination of ULT and KLT. Many user threads mapped to many kernel threads.
  • Best performance and flexibility.
  • Example: Solaris OS.

Advantages of Threads: Responsiveness, Resource Sharing, Economy (cheaper than processes), Scalability (use multiple CPUs).

Section C: Unit 2 — Synchronization

Critical Section | Semaphores | Classical Problems

8M ★★ Q6 | Sec C What is the critical-section problem? Explain its requirements and solutions.
📝 EXAM ANSWER — Write Exactly This in Copy:

Process Synchronization: When multiple processes access shared data concurrently, we must ensure correct execution to maintain data consistency.

Race Condition: Multiple processes access and modify shared data simultaneously → result depends on execution order → incorrect results!

Example: P1 reads balance=5000, P2 reads balance=5000. P1 adds 1000→6000. P2 adds 2000→7000. Should be 8000! This is a race condition.

Critical Section: The segment of code that accesses shared resources (shared variables, files, I/O devices). Only ONE process must be in the critical section at a time.

Structure of Critical Section Solution:

ENTRY SECTION        ← Request permission to enter
  CRITICAL SECTION   ← Access shared resource here
EXIT SECTION         ← Release permission
  REMAINDER SECTION  ← Non-critical code

Three Requirements for CS Solution:

  1. Mutual Exclusion: Only one process can be in the critical section at any given time.
  2. Progress: If no process is in the CS, any process requesting entry must be allowed to enter without indefinite delay. Selection cannot be postponed indefinitely.
  3. Bounded Waiting: A limit must exist on the number of times other processes can enter CS after a process has requested entry. No process waits forever.

Solutions:

  • Software Solutions: Peterson's Algorithm — uses two variables (turn, flag[]).
  • Hardware Solutions: test_and_set(), compare_and_swap() instructions.
  • OS Solutions: Semaphores (most important!), Mutex locks, Monitors.
Conclusion: The critical section problem ensures data consistency in concurrent systems. The three requirements (mutual exclusion, progress, bounded waiting) must all be satisfied for a correct solution.

8M ★★ Q7 | Sec C What is a semaphore? Explain binary and counting semaphores with suitable examples.
📝 EXAM ANSWER — Write Exactly This in Copy:

Semaphore: A semaphore is an integer variable used for process synchronization. It supports two atomic operations: wait() and signal().

Operations:

  • wait(S) / P(S): S = S − 1; if S < 0 → block the process (LOCK the resource)
  • signal(S) / V(S): S = S + 1; if S ≤ 0 → wake up one blocked process (UNLOCK)

Both operations must be atomic — cannot be interrupted during execution!

1. Binary Semaphore (Mutex):

  • Value is either 0 (locked) or 1 (unlocked) only.
  • Used for mutual exclusion — ensuring only one process in critical section.
  • Initialized to 1.
mutex = 1   (initially unlocked)
Process P1:  wait(mutex) → mutex=0 → Enter CS → signal(mutex) → mutex=1
Process P2:  wait(mutex) → mutex=-1 → BLOCKED! Waits until P1 signals.
When P1 signals: P2 wakes up → enters CS

2. Counting Semaphore:

  • Value ranges from 0 to N (unrestricted integer).
  • Used when N instances of a resource are available.
  • Tracks count of available resource instances.
Example: Parking lot with 10 spaces. semaphore = 10
Car enters: wait(S) → S decreases (9,8,7...0)
Car leaves: signal(S) → S increases
If S = 0: Next car BLOCKS until someone leaves!

Producer-Consumer Problem using Semaphores:

Semaphores: mutex=1 (critical section), full=0, empty=N (buffer size)
Producer:  wait(empty) → wait(mutex) → ADD item → signal(mutex) → signal(full)
Consumer:  wait(full)  → wait(mutex) → REMOVE item → signal(mutex) → signal(empty)

Semaphore vs Mutex:

Value range0 or 1 only0 to N (any integer)

Conclusion: Semaphores are a versatile synchronization mechanism. wait() = lock, signal() = unlock. Binary semaphore ensures mutual exclusion. Counting semaphore manages resource pools.

Section D: Unit 2 — Deadlock

Deadlock | 4 Conditions | Prevention | Avoidance | Banker's

12M ★★★★ Q8 | Sec D What is deadlock? Explain the four necessary conditions for deadlock with examples.
📝 EXAM ANSWER — Write Exactly This in Copy:

Deadlock: A deadlock is a situation in which a set of processes are permanently blocked because each process holds some resources and waits for resources held by other processes in the same set. No process can proceed — complete standstill!

Simple Example:

Process P1 holds Resource R1 (Printer) and waits for R2 (Scanner).
Process P2 holds Resource R2 (Scanner) and waits for R1 (Printer).
Both wait forever → DEADLOCK!

Four Necessary Conditions for Deadlock (Coffman Conditions, 1971):

ALL FOUR conditions must hold simultaneously for deadlock to occur. Remove ANY ONE → No Deadlock!

1. Mutual Exclusion:

  • At least one resource must be held in a non-sharable mode.
  • Only ONE process can use the resource at a time.
  • Example: Only one person can use a printer at a time. If another wants it, they must wait.

2. Hold and Wait:

  • A process must be holding at least one resource AND waiting to acquire additional resources currently held by other processes.
  • Example: Process holds the Scanner (holds) and is waiting for the Printer (wait).

3. No Preemption:

  • Resources cannot be forcibly taken away from a process holding them.
  • A resource can only be released voluntarily by the process holding it after it completes its task.
  • Example: You cannot snatch a pen from someone who is writing — they must give it up themselves.

4. Circular Wait:

  • A set of processes {P1, P2, ..., Pn} must exist such that P1 waits for P2, P2 waits for P3, ..., Pn waits for P1.
  • A circular chain of waiting is formed!
  • Example: P1 wants R2 (held by P2), P2 wants R3 (held by P3), P3 wants R1 (held by P1) → CYCLE!
Conclusion: Deadlock is a serious problem in concurrent systems. All four Coffman conditions must hold simultaneously for deadlock to occur. Eliminating even one condition prevents deadlock. This forms the basis of deadlock prevention strategies.

12M ★★★ Q9 | Sec D Explain deadlock prevention, avoidance, detection and recovery techniques.
📝 EXAM ANSWER — Write Exactly This in Copy:

Deadlock Handling Methods (4 approaches):

METHOD 1 — DEADLOCK PREVENTION:

Ensure at least one of the four Coffman conditions NEVER holds in the system.

  • Eliminate Mutual Exclusion: Make resources sharable where possible (e.g., use print spooler instead of direct printer access). Not always feasible.
  • Eliminate Hold and Wait: A process must request ALL needed resources at once before starting. OR must release all held resources before requesting more. Leads to low resource utilization.
  • Allow Preemption: If a process holding resources requests another that cannot be immediately allocated, release all currently held resources. Process restarts when all resources available.
  • Eliminate Circular Wait: Assign a total ordering to all resource types. Processes must request resources in strictly increasing order. Breaks the circular chain.

METHOD 2 — DEADLOCK AVOIDANCE (Banker's Algorithm):

  • Before granting a resource request, check if resulting state is a SAFE STATE.
  • Safe State: All processes can eventually finish in some sequence (safe sequence).
  • Need matrix: Need[i][j] = Max[i][j] − Allocation[i][j]
  • Grant request ONLY IF resulting state is safe. Otherwise, make process wait.

METHOD 3 — DEADLOCK DETECTION:

  • Allow deadlock to occur. Detect it using Resource Allocation Graph (RAG).
  • If RAG contains a cycle → Deadlock exists (for single-instance resources).
  • Run detection algorithm periodically (every hour, or when CPU utilization drops).
  • Detection algorithm uses Available, Allocation, and Request matrices.

METHOD 4 — DEADLOCK RECOVERY:

  • Process Termination:
    • Abort all deadlocked processes (expensive — loses work).
    • Abort one process at a time until deadlock cycle broken (less expensive).
  • Resource Preemption:
    • Forcibly take a resource from one process and give it to another.
    • Preempted process is rolled back to a safe earlier state (checkpoint).
    • Same process should not always be the victim (starvation!).

Conclusion: Prevention is safest but most restrictive. Avoidance (Banker's) is practical but needs advance resource declarations. Detection+Recovery is used when deadlocks are rare. In practice, most systems use prevention + detection.

12M ★★★★ Q10 | Sec D Explain the Banker's Algorithm for deadlock avoidance with a suitable example.
📝 EXAM ANSWER — Write Exactly This in Copy:

Banker's Algorithm: Developed by Dijkstra. Used for deadlock avoidance. Before granting any resource request, the OS checks whether the resulting state is a SAFE STATE. If safe → grant. If unsafe → make process wait.

Safe State: A state where there exists at least one safe sequence in which all processes can finish their execution. If no safe sequence exists → Unsafe State (may lead to deadlock).

Data Structures Used:

  • Available[j]: Number of available instances of resource type j.
  • Max[i][j]: Maximum demand of process i for resource type j.
  • Allocation[i][j]: Resources currently allocated to process i.
  • Need[i][j]: Remaining resources needed by process i. Need = Max − Allocation

Safety Algorithm Steps:

  1. Initialize Work = Available, Finish[i] = false for all i.
  2. Find process i where Finish[i]=false AND Need[i] ≤ Work.
  3. If found: Work = Work + Allocation[i]; Finish[i] = true. Go to step 2.
  4. If all Finish[i]=true → Safe State! Otherwise → Unsafe State.

Example:

Resources: A(10), B(5), C(7) | Available: A=3, B=3, C=2

        | A   B   C  | A   B   C  | A   B   C  
  P0    | 0   1   0  | 7   5   3  | 7   4   3  
  P1    | 2   0   0  | 3   2   2  | 1   2   2  ← Need(1,2,2) ≤ Avail(3,3,2) ✓ → Run P1
  P2    | 3   0   2  | 9   0   2  | 6   0   0  
  P3    | 2   1   1  | 2   2   2  | 0   1   1  
  P4    | 0   0   2  | 4   3   3  | 4   3   1  

Step 1: P1 runs. Work = (3,3,2) + (2,0,0) = (5,3,2). Finish[1]=true.
Step 2: P3 needs(0,1,1) ≤ Work(5,3,2) ✓ → Run P3. Work=(5,3,2)+(2,1,1)=(7,4,3). Finish[3]=true.
Step 3: P4 needs(4,3,1) ≤ Work(7,4,3) ✓ → Run P4. Work=(7,4,3)+(0,0,2)=(7,4,5). Finish[4]=true.
Step 4: P0 needs(7,4,3) ≤ Work(7,4,5) ✓ → Run P0. Work=(7,5,5). Finish[0]=true.
Step 5: P2 needs(6,0,0) ≤ Work(7,5,5) ✓ → Run P2. Finish[2]=true.

SAFE SEQUENCE: P1 → P3 → P4 → P0 → P2 ✅ SAFE STATE → Grant request!
Conclusion: Banker's Algorithm ensures the system never enters an unsafe state by checking safety before every resource allocation. It is the most important deadlock avoidance algorithm. Need = Max − Allocation is the key formula.

8M ★★ Q11 | Sec E Explain memory management and discuss different memory allocation techniques.
📝 EXAM ANSWER — Write Exactly This in Copy:

Memory Management: The OS function that controls and coordinates the use of primary memory (RAM). It allocates memory to processes when needed and reclaims it when done.

Goals: Efficient utilization, Protection (processes don't interfere), Sharing (share common code), Relocation (run process anywhere in memory).

Logical vs Physical Address:

  • Logical (Virtual) Address: Generated by CPU. User/programmer sees this. Starts from 0 for each process.
  • Physical Address: Actual RAM location. Hardware uses this. MMU translates logical → physical.

Swapping: Moving an inactive process from RAM to disk (swap out) to free memory. Brings it back when needed (swap in). Increases multiprogramming degree.

Contiguous Memory Allocation:

  • Fixed Partition: Memory divided into fixed-size partitions. Simple but causes Internal Fragmentation (allocated > required).
  • Variable Partition: Partitions created exactly as needed. Causes External Fragmentation (total free enough but not contiguous).

Fit Strategies for Variable Partition:

  • First Fit: Allocate first hole that is large enough. Fast!
  • Best Fit: Allocate smallest suitable hole. Less waste but slow.
  • Worst Fit: Allocate largest hole. Large leftover (for future use).

Fragmentation Solution:

  • Compaction: Move all processes to one end, creating one large free block. Expensive!
  • Paging/Segmentation: Better — non-contiguous allocation, no external fragmentation.
Conclusion: Memory management ensures efficient and safe use of RAM. Fixed partition is simple but wasteful. Variable partition is efficient but causes external fragmentation. Paging and segmentation provide better solutions.

12M ★★★ Q12 | Sec E Explain paging and segmentation. Differentiate between paging and segmentation.
📝 EXAM ANSWER — Write Exactly This in Copy:

PAGING:

Paging is a non-contiguous memory allocation technique where:

  • Logical memory is divided into fixed-size blocks called PAGES.
  • Physical memory is divided into fixed-size blocks called FRAMES (same size as pages).
  • OS maintains a Page Table for each process mapping page numbers to frame numbers.
  • Pages can be placed in ANY available frame — non-contiguous!
  • No External Fragmentation! Only Internal Fragmentation (last page may not be full).

Address Translation in Paging:

  • Logical Address = Page Number (p) + Page Offset (d)
  • Physical Address = Frame[p] × Frame_Size + d
  • TLB (Translation Lookaside Buffer): Hardware cache for page table entries = fast translation!

Segmentation is a memory management technique where a program is divided into logical variable-size segments:

  • Segments correspond to logical program units: Code, Data, Stack, Heap.
  • Segment Table stores Base address and Limit (size) for each segment.
  • Physical Address = Base[segment_no] + Offset (if offset < Limit)
  • External Fragmentation possible (variable sizes). No Internal Fragmentation!
  • Matches programmer's logical view of memory.

Paging + Segmentation Combined: First segment the program, then page each segment. Best of both worlds — logical organization + no external fragmentation.

12M ★★★ Q13 | Sec E What is virtual memory? Explain demand paging and its advantages.
📝 EXAM ANSWER — Write Exactly This in Copy:

Virtual Memory: A memory management technique that allows processes to execute even if they are not completely loaded in RAM. The remaining pages/segments are stored on disk (secondary storage). Creates an illusion that the computer has more memory than physically available.

Benefits of Virtual Memory:

  • Programs larger than physical RAM can execute.
  • More processes can be kept in memory simultaneously (increased multiprogramming).
  • Less I/O needed — only load what is currently being used.
  • Each process has full address space illusion.

Demand Paging: A virtual memory implementation where pages are loaded into memory ONLY when they are demanded (accessed by the process). NOT all pages are loaded at program start. Pages on disk until referenced.

Working of Demand Paging:

  1. Process starts. Only essential initial pages loaded into RAM.
  2. CPU accesses a page. Check page table — valid bit.
  3. If valid bit = 1: Page is in RAM → access directly (no fault).
  4. If valid bit = 0: PAGE FAULT! OS interrupt occurs.
  5. OS saves current process state.
  6. OS finds a free frame in RAM (or replaces a page).
  7. OS loads required page from disk into free frame.
  8. OS updates page table (valid bit = 1).
  9. Process restarts the faulted instruction.

Page Fault Rate: If p = page fault rate, then:

Effective Access Time (EAT) = (1-p) × memory_access_time + p × page_fault_time

Advantages of Demand Paging:

  • Large programs can run with limited RAM.
  • Faster initial program loading (only load what's needed).
  • Increased degree of multiprogramming.
  • Less physical memory needed per process.
  • Unused code/data never loaded (efficient).

Disadvantages:

  • Page fault handling overhead (disk access is slow).
  • Can lead to thrashing if too many page faults occur.
  • Complex OS implementation required.

Thrashing: When a process spends more time swapping pages than executing. CPU utilization drops drastically. Fix: Working Set Model, Page Fault Frequency algorithm, more RAM.

Conclusion: Virtual memory with demand paging greatly increases the degree of multiprogramming and allows large programs to run on systems with limited RAM. The key is minimizing page faults through good page replacement algorithms.

8M ★★ Q6 | Sec C What is the critical-section problem? Explain its requirements and solutions.
📝 EXAM ANSWER — Write Exactly This in Copy:

Process Synchronization: When multiple processes access shared data concurrently, we must ensure correct execution to maintain data consistency.

Example: P1 reads balance=5000, P2 reads balance=5000. P1 adds 1000→6000. P2 adds 2000→7000. Should be 8000! This is a race condition.

Structure of Critical Section Solution:

ENTRY SECTION        ← Request permission to enter
  CRITICAL SECTION   ← Access shared resource here
EXIT SECTION         ← Release permission
  REMAINDER SECTION  ← Non-critical code

Three Requirements for CS Solution:

  1. Mutual Exclusion: Only one process can be in the critical section at any given time.
  2. Progress: If no process is in the CS, any process requesting entry must be allowed to enter without indefinite delay. Selection cannot be postponed indefinitely.
  3. Bounded Waiting: A limit must exist on the number of times other processes can enter CS after a process has requested entry. No process waits forever.

Solutions:

  • Software Solutions: Peterson's Algorithm — uses two variables (turn, flag[]).
  • Hardware Solutions: test_and_set(), compare_and_swap() instructions.
  • OS Solutions: Semaphores (most important!), Mutex locks, Monitors.
Conclusion: The critical section problem ensures data consistency in concurrent systems. The three requirements (mutual exclusion, progress, bounded waiting) must all be satisfied for a correct solution.

8M ★★ Q7 | Sec C What is a semaphore? Explain binary and counting semaphores with suitable examples.
📝 EXAM ANSWER — Write Exactly This in Copy:

Semaphore: A semaphore is an integer variable used for process synchronization. It supports two atomic operations: wait() and signal().

Operations:

  • wait(S) / P(S): S = S − 1; if S < 0 → block the process (LOCK the resource)
  • signal(S) / V(S): S = S + 1; if S ≤ 0 → wake up one blocked process (UNLOCK)

Both operations must be atomic — cannot be interrupted during execution!

1. Binary Semaphore (Mutex):

  • Value is either 0 (locked) or 1 (unlocked) only.
  • Used for mutual exclusion — ensuring only one process in critical section.
  • Initialized to 1.
mutex = 1   (initially unlocked)
Process P1:  wait(mutex) → mutex=0 → Enter CS → signal(mutex) → mutex=1
Process P2:  wait(mutex) → mutex=-1 → BLOCKED! Waits until P1 signals.
When P1 signals: P2 wakes up → enters CS

2. Counting Semaphore:

  • Value ranges from 0 to N (unrestricted integer).
  • Used when N instances of a resource are available.
  • Tracks count of available resource instances.
Example: Parking lot with 10 spaces. semaphore = 10
Car enters: wait(S) → S decreases (9,8,7...0)
Car leaves: signal(S) → S increases
If S = 0: Next car BLOCKS until someone leaves!

Producer-Consumer Problem using Semaphores:

Semaphores: mutex=1 (critical section), full=0, empty=N (buffer size)
Producer:  wait(empty) → wait(mutex) → ADD item → signal(mutex) → signal(full)
Consumer:  wait(full)  → wait(mutex) → REMOVE item → signal(mutex) → signal(empty)

12M ★★★★ Q8 | Sec D What is deadlock? Explain the four necessary conditions for deadlock with examples.
📝 EXAM ANSWER — Write Exactly This in Copy:

Deadlock: A deadlock is a situation in which a set of processes are permanently blocked because each process holds some resources and waits for resources held by other processes in the same set. No process can proceed — complete standstill!

Simple Example:

Process P1 holds Resource R1 (Printer) and waits for R2 (Scanner).
Process P2 holds Resource R2 (Scanner) and waits for R1 (Printer).
Both wait forever → DEADLOCK!

Four Necessary Conditions for Deadlock (Coffman Conditions, 1971):

ALL FOUR conditions must hold simultaneously for deadlock to occur. Remove ANY ONE → No Deadlock!

1. Mutual Exclusion:

  • At least one resource must be held in a non-sharable mode.
  • Only ONE process can use the resource at a time.
  • Example: Only one person can use a printer at a time. If another wants it, they must wait.

2. Hold and Wait:

  • A process must be holding at least one resource AND waiting to acquire additional resources currently held by other processes.
  • Example: Process holds the Scanner (holds) and is waiting for the Printer (wait).

3. No Preemption:

  • Resources cannot be forcibly taken away from a process holding them.
  • A resource can only be released voluntarily by the process holding it after it completes its task.
  • Example: You cannot snatch a pen from someone who is writing — they must give it up themselves.

4. Circular Wait:

  • A set of processes {P1, P2, ..., Pn} must exist such that P1 waits for P2, P2 waits for P3, ..., Pn waits for P1.
  • A circular chain of waiting is formed!
  • Example: P1 wants R2 (held by P2), P2 wants R3 (held by P3), P3 wants R1 (held by P1) → CYCLE!
Conclusion: Deadlock is a serious problem in concurrent systems. All four Coffman conditions must hold simultaneously for deadlock to occur. Eliminating even one condition prevents deadlock. This forms the basis of deadlock prevention strategies.

12M ★★★ Q9 | Sec D Explain deadlock prevention, avoidance, detection and recovery techniques.
📝 EXAM ANSWER — Write Exactly This in Copy:

Deadlock Handling Methods (4 approaches):

METHOD 1 — DEADLOCK PREVENTION:

Ensure at least one of the four Coffman conditions NEVER holds in the system.

  • Eliminate Mutual Exclusion: Make resources sharable where possible (e.g., use print spooler instead of direct printer access). Not always feasible.
  • Eliminate Hold and Wait: A process must request ALL needed resources at once before starting. OR must release all held resources before requesting more. Leads to low resource utilization.
  • Allow Preemption: If a process holding resources requests another that cannot be immediately allocated, release all currently held resources. Process restarts when all resources available.
  • Eliminate Circular Wait: Assign a total ordering to all resource types. Processes must request resources in strictly increasing order. Breaks the circular chain.

METHOD 2 — DEADLOCK AVOIDANCE (Banker's Algorithm):

  • Before granting a resource request, check if resulting state is a SAFE STATE.
  • Safe State: All processes can eventually finish in some sequence (safe sequence).
  • Need matrix: Need[i][j] = Max[i][j] − Allocation[i][j]
  • Grant request ONLY IF resulting state is safe. Otherwise, make process wait.

METHOD 3 — DEADLOCK DETECTION:

  • Allow deadlock to occur. Detect it using Resource Allocation Graph (RAG).
  • If RAG contains a cycle → Deadlock exists (for single-instance resources).
  • Run detection algorithm periodically (every hour, or when CPU utilization drops).
  • Detection algorithm uses Available, Allocation, and Request matrices.

METHOD 4 — DEADLOCK RECOVERY:

  • Process Termination:
    • Abort all deadlocked processes (expensive — loses work).
    • Abort one process at a time until deadlock cycle broken (less expensive).
  • Resource Preemption:
    • Forcibly take a resource from one process and give it to another.
    • Preempted process is rolled back to a safe earlier state (checkpoint).
    • Same process should not always be the victim (starvation!).

12M ★★★★ Q10 | Sec D Explain the Banker's Algorithm for deadlock avoidance with a suitable example.
📝 EXAM ANSWER — Write Exactly This in Copy:

Banker's Algorithm: Developed by Dijkstra. Used for deadlock avoidance. Before granting any resource request, the OS checks whether the resulting state is a SAFE STATE. If safe → grant. If unsafe → make process wait.

Safe State: A state where there exists at least one safe sequence in which all processes can finish their execution. If no safe sequence exists → Unsafe State (may lead to deadlock).

Data Structures Used:

  • Available[j]: Number of available instances of resource type j.
  • Max[i][j]: Maximum demand of process i for resource type j.
  • Allocation[i][j]: Resources currently allocated to process i.
  • Need[i][j]: Remaining resources needed by process i. Need = Max − Allocation

Safety Algorithm Steps:

  1. Initialize Work = Available, Finish[i] = false for all i.
  2. Find process i where Finish[i]=false AND Need[i] ≤ Work.
  3. If found: Work = Work + Allocation[i]; Finish[i] = true. Go to step 2.
  4. If all Finish[i]=true → Safe State! Otherwise → Unsafe State.

Example:

Resources: A(10), B(5), C(7) | Available: A=3, B=3, C=2

  P2    | 3   0   2  | 9   0   2  | 6   0   0  
  P3    | 2   1   1  | 2   2   2  | 0   1   1  
  P4    | 0   0   2  | 4   3   3  | 4   3   1  

Step 1: P1 runs. Work = (3,3,2) + (2,0,0) = (5,3,2). Finish[1]=true.
Step 2: P3 needs(0,1,1) ≤ Work(5,3,2) ✓ → Run P3. Work=(5,3,2)+(2,1,1)=(7,4,3). Finish[3]=true.
Step 3: P4 needs(4,3,1) ≤ Work(7,4,3) ✓ → Run P4. Work=(7,4,3)+(0,0,2)=(7,4,5). Finish[4]=true.
Step 4: P0 needs(7,4,3) ≤ Work(7,4,5) ✓ → Run P0. Work=(7,5,5). Finish[0]=true.
Step 5: P2 needs(6,0,0) ≤ Work(7,5,5) ✓ → Run P2. Finish[2]=true.

SAFE SEQUENCE: P1 → P3 → P4 → P0 → P2 ✅ SAFE STATE → Grant request!

PAGING:

Paging is a non-contiguous memory allocation technique where:

  • Logical memory is divided into fixed-size blocks called PAGES.
  • Physical memory is divided into fixed-size blocks called FRAMES (same size as pages).
  • OS maintains a Page Table for each process mapping page numbers to frame numbers.

  • External Fragmentation possible (variable sizes). No Internal Fragmentation!
  • Matches programmer's logical view of memory.

Paging + Segmentation Combined: First segment the program, then page each segment. Best of both worlds — logical organization + no external fragmentation.

12M ★★★ Q13 | Sec E What is virtual memory? Explain demand paging and its advantages.
📝 EXAM ANSWER — Write Exactly This in Copy:

Virtual Memory: A memory management technique that allows processes to execute even if they are not completely loaded in RAM. The remaining pages/segments are stored on disk (secondary storage). Creates an illusion that the computer has more memory than physically available.

Benefits of Virtual Memory:

  • Programs larger than physical RAM can execute.
  • More processes can be kept in memory simultaneously (increased multiprogramming).
  • Less I/O needed — only load what is currently being used.
  • Each process has full address space illusion.

Demand Paging: A virtual memory implementation where pages are loaded into memory ONLY when they are demanded (accessed by the process). NOT all pages are loaded at program start. Pages on disk until referenced.

Working of Demand Paging:

  1. Process starts. Only essential initial pages loaded into RAM.
  2. CPU accesses a page. Check page table — valid bit.
  3. If valid bit = 1: Page is in RAM → access directly (no fault).
  4. If valid bit = 0: PAGE FAULT! OS interrupt occurs.
  5. OS saves current process state.
  6. OS finds a free frame in RAM (or replaces a page).
  7. OS loads required page from disk into free frame.
  8. OS updates page table (valid bit = 1).
  9. Process restarts the faulted instruction.

Page Fault Rate: If p = page fault rate, then:

Effective Access Time (EAT) = (1-p) × memory_access_time + p × page_fault_time

Advantages of Demand Paging:

  • Large programs can run with limited RAM.
  • Faster initial program loading (only load what's needed).
  • Increased degree of multiprogramming.
  • Less physical memory needed per process.
  • Unused code/data never loaded (efficient).

Disadvantages:

  • Page fault handling overhead (disk access is slow).
  • Can lead to thrashing if too many page faults occur.
  • Complex OS implementation required.

Thrashing: When a process spends more time swapping pages than executing. CPU utilization drops drastically. Fix: Working Set Model, Page Fault Frequency algorithm, more RAM.

Conclusion: Virtual memory with demand paging greatly increases the degree of multiprogramming and allows large programs to run on systems with limited RAM. The key is minimizing page faults through good page replacement algorithms.

8M ★★ Q17 | Sec G Explain the UNIX file system hierarchy. What are absolute and relative pathnames?
📝 EXAM ANSWER — Write Exactly This in Copy:

UNIX File System Hierarchy: UNIX uses a hierarchical (inverted tree) file system structure with a single root directory /. Everything in UNIX is a file — regular files, directories, devices, pipes.

Important Directories:

  • / → Root — parent of ALL directories. Top of hierarchy.
  • /bin → Essential user command binaries (ls, cp, mv, rm, cat, grep, chmod...)
  • /sbin → System administration binaries (mount, ifconfig, fdisk, fsck)
  • /etc → Configuration files (/etc/passwd, /etc/fstab, /etc/hosts)
  • /home → User home directories (/home/zoha, /home/admin)
  • /var → Variable data — logs (/var/log), mail queues, print spools
  • /usr → User programs (/usr/bin), libraries (/usr/lib), documentation
  • /tmp → Temporary files. Auto-deleted on reboot!
  • /dev → Device files — keyboard (/dev/tty), disk (/dev/sda), USB (/dev/sdb)
  • /lib → Shared libraries for /bin and /sbin commands
  • /boot → Kernel image (vmlinuz), GRUB bootloader configuration
  • /proc → Virtual FS — real-time process info (/proc/cpuinfo, /proc/meminfo)
  • /mnt → Temporary mount point for external drives

ABSOLUTE PATHNAME:

  • Complete path from root directory (/) to the file/directory.
  • Always starts with / (forward slash).
  • Works from ANYWHERE in the file system.
  • Example: /home/zoha/Documents/file.txt

RELATIVE PATHNAME:

  • Path relative to the CURRENT working directory.
  • Does NOT start with /.
  • Shorter, but works only from specific location.
  • Special symbols: . (current directory) | .. (parent directory) | ~ (home directory)
  • Example: If current dir is /home/zoha → Documents/file.txt or ../admin/file.txt
Conclusion: UNIX file system follows a hierarchical tree structure with root (/) at top. Absolute paths start from / and always work. Relative paths are shorter but depend on current location. Key: Everything in UNIX is a file!

10M ★★★ Q19 | Sec H What is I/O redirection and piping in UNIX? Explain >, >>, < and | with examples. Also explain the concept of filters.
📝 EXAM ANSWER — Write Exactly This in Copy:

Standard I/O Streams:

  • stdin (0): Standard input — keyboard by default.
  • stdout (1): Standard output — screen by default.
  • stderr (2): Standard error — screen by default.

I/O Redirection: Changing where input comes from or where output goes.

1. > (Output Redirection — Overwrite):

  • Redirects stdout to a file. Overwrites existing content!
  • ls -l > files.txt → Save ls output to files.txt (overwrites)
  • echo "Hello World" > greeting.txt → Create file with content
  • who > logged_users.txt → Save current users to file

2. >> (Output Redirection — Append):

  • Redirects stdout to a file. APPENDS to existing content (original data safe!).
  • echo "New entry" >> log.txt → Add to end of file
  • date >> log.txt → Append current date/time

3. < (Input Redirection):

  • Takes input from a file instead of keyboard.
  • sort < names.txt → Sort using names.txt as input
  • wc -l < file.txt → Count lines from file
  • mail user < message.txt → Send file content as email

4. 2> (Error Redirection):

  • Redirects stderr to a file. Errors go to file, not screen.
  • command 2> errors.txt → Save error messages
  • find / -name "*.txt" 2> /dev/null → Discard errors

PIPING (|):

  • Connects commands in a pipeline. Output of first command → Input of second command.
  • Syntax: command1 | command2 | command3
  • Examples:
    • ls -l | wc -l → Count files in directory
    • cat /etc/passwd | grep "bash" → Find bash users
    • ps aux | sort -k3 -r | head -5 → Top 5 CPU processes
    • who | wc -l → Count logged-in users

FILTERS: Commands that read from stdin and write to stdout. Designed to work in pipelines.

Common filters: grep (search), sort (sort), wc (count), head (first n lines), tail (last n lines), cut (extract fields), tr (translate characters), uniq (unique lines), sed (stream editor), awk (pattern processing).

Conclusion: I/O redirection and pipes are powerful UNIX features. > overwrites, >> appends, < reads from file, | chains commands. Filters work between pipes to process data streams.

12M ★★★★ Q20 | Sec H Explain the vi editor and UNIX shell. Discuss vi modes, insertion/deletion, yank and put, .exrc, types of shells, shell variables, aliases, history, job control and awk.
📝 EXAM ANSWER — Write Exactly This in Copy:

PART A — vi EDITOR:

vi (Visual Interface): Standard UNIX/Linux text editor. Available on every system. Entirely keyboard-driven. Created by Bill Joy. Modern version: vim (Vi IMproved).

THREE MODES (CIE):

1. Command Mode (Normal Mode — DEFAULT on open):

  • Navigation: h(←) j(↓) k(↑) l(→) | w(next word) b(prev word)
  • G(last line) gg(first line) :n(go to line n) | 0(line start) $(line end)
  • Delete: x(char) dd(line) dw(word) D(to line end) 5dd(5 lines)
  • Yank (Copy): yy(copy line) 5yy(copy 5 lines) yw(copy word)
  • Put (Paste): p(paste below cursor) P(paste above cursor)
  • Undo: u(undo last) U(undo all on line) Ctrl+r(redo)
  • Search: /pattern (forward) ?pattern (backward) n(next) N(previous)

2. Insert Mode: i(before) a(after) o(new line below) O(new line above) I(line start) A(line end) → Press Esc to return

3. Ex Mode (Last Line Mode): Enter by pressing : in Command Mode

  • :w save | :q quit | :wq save+quit ← MOST IMPORTANT!
  • :q! force quit no save | :set nu line numbers
  • :%s/old/new/g replace ALL in file ← EXAM FAVOURITE!
  • :r filename insert another file here

.exrc file: vi configuration file at ~/.exrc. Contains: set nu, set tabstop=4, set autoindent. Read automatically at vi startup to customize settings.

vim vs vi: vim = Vi IMproved. Adds syntax highlighting, multiple undo, split windows, plugins. Default on modern Linux.

PART B — UNIX SHELL:

Shell: Command-line interpreter between user and OS kernel. Reads commands, interprets them, passes to kernel, shows output.

Types of Shell:

  • sh (Bourne Shell, 1979): First UNIX shell. Simple, portable, good for scripting.
  • csh (C Shell): C-like syntax. Aliasing and history features.
  • ksh (Korn Shell, 1983): sh compatible + csh features. Good performance.
  • bash (Bourne Again Shell): DEFAULT on Linux! Free, best features, most popular.
  • zsh (Z Shell): Modern, excellent autocomplete and plugins.

Shell Variables:

  • User-defined: name="Zoha"; echo $name
  • Environment: $HOME, $PATH, $USER, $SHELL, $PWD
  • Export: export VAR=value → makes available to child processes

Aliases:

  • Create shortcuts for commands: alias ll='ls -la'
  • List aliases: alias | Remove: unalias ll
  • Permanent: Add to ~/.bashrc file

History:

  • history → show command history list
  • ↑↓ arrows → navigate history | !! → repeat last command
  • !n → run command number n | Ctrl+R → search history

Job Control:

  • command & → start in background
  • Ctrl+Z → suspend current process
  • bg → resume suspended job in background
  • fg → bring background job to foreground
  • jobs → list all background/suspended jobs

awk — Pattern Processing Tool:

  • awk '{print $1}' file → print first column of each line
  • awk -F: '{print $1}' /etc/passwd → use : delimiter, print usernames
  • awk 'NR==3{print}' file → print only line 3
  • awk '{sum+=$1} END{print sum}' file → sum first column
  • awk '/pattern/{print}' file → print lines matching pattern
  • awk '{if($1>50)print $0}' file → conditional printing
Conclusion: vi editor mastery requires understanding 3 modes: Command, Insert, Ex. Key commands: i(insert), Esc(back), :wq(save+quit), :q!(force quit), :%s/x/y/g(replace all). Shell with variables, aliases, job control and awk makes UNIX extremely powerful for scripting and automation.

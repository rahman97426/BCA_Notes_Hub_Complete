Q3. What is a process? Explain process states and PCB with a suitable diagram.

Process = Cooking using that recipe (active, using gas, pots, ingredients)

📌 Key Points:
5 Process States:
  • 🆕 New → Process just created (like just hired employee, not started yet)
  • ✅ Ready → Loaded in RAM, waiting for CPU (employee at desk, waiting for work)
  • ⚡ Running → CPU is executing it right now! (employee actively working)
  • ⏸️ Waiting/Blocked → Waiting for I/O or event (employee waiting for a file from boss)
  • 🏁 Terminated → Process finished, all memory freed (employee resigned)

OS keeps one PCB for every process. Contains:

4. CPU Registers   5. Memory Info   6. Scheduling Info
7. I/O Status   8. Accounting Info

Q5. What is a thread? Explain types of threads and differentiate between process and thread.
12 Marks
🗣️ In Simple Words:
Process = Whole Restaurant (has its own building, kitchen, staff)
Thread = One Waiter in that restaurant (shares kitchen & building, but does own tasks)
Multiple waiters (threads) in one restaurant (process) serve more customers (tasks) faster!
📌 Key Points:
Thread = Smallest unit of CPU execution.
A thread is a lightweight process INSIDE a process. Threads in same process share:
• Code section   • Data section   • Open files & resources
But each thread has its OWN: Stack + Registers + Program Counter
📌 Key Points:
Types of Threads:
  • User Level Threads (ULT): Managed by user library (not OS). Fast to create. Problem: if one thread blocks → ALL threads block!
  • Kernel Level Threads (KLT): Managed by OS directly. Slower but if one blocks, others continue. Can run on multiple CPUs. (Linux uses this)
  • Hybrid: Mix of both. Multiple ULTs mapped to multiple KLTs. Best of both worlds!

💡 Think of it Like:
Chrome browser = 1 Process. Each Tab = 1 Thread.
All tabs share Chrome's memory (process memory) but each tab runs independently (own stack).
If one tab crashes — sometimes all crash! That's the thread-crash problem.
📝 Write in Exam:
A thread is the smallest unit of CPU execution. It is a lightweight process. Types: 1)User Level Threads — managed by user library, fast but blocking is problem. 2)Kernel Level Threads — managed by OS, slower but true parallelism. 3)Hybrid — maps ULTs to KLTs. Q6
Q6. What is the critical-section problem? Explain requirements and solutions.
12 Marks
🗣️ In Simple Words:
Imagine 2 people editing the same Google Doc at the same time — text gets messed up! This is the Critical Section Problem. The CS is the part of code that accesses shared data. Only ONE process should be in CS at a time. That's the whole problem!
📌 Key Points:
Critical Section (CS) = Code that accesses shared resources (variables, files, printers).
3 Requirements (ALL must be satisfied):
  • ① Mutual Exclusion: Only 1 process in CS at a time (like 1 person in toilet!)
  • ② Progress: If CS is free, selection of next process can't be delayed forever
  • ③ Bounded Waiting: Limit on how long a process waits — no one waits forever!
💡 Think of it Like:
Toilet analogy: Toilet = Critical Section. Lock = Mutual Exclusion. Queue outside = Bounded Waiting. Someone must use it when free = Progress. Perfect!
📌 Key Points:
Solutions:
  • Peterson's Solution (software, 2 processes)
  • Semaphores — most used (wait & signal)
  • Mutex Locks
  • Monitors (high-level)
  • Hardware: Test-and-Set, Compare-and-Swap
📝 Write in Exam:
Critical Section is part of program where shared resources are accessed. Problem: ensure safe access. 3 Requirements: ①Mutual Exclusion — only one process in CS at a time ②Progress — CS selection not postponed indefinitely ③Bounded Waiting — limit on waiting time. Solutions: Semaphores, Peterson's Solution, Mutex Locks, Monitors, Hardware Instructions.
✅ One Line Conclusion:
"CS = shared code zone. Only 1 allowed. MPB = Mutual exclusion, Progress, Bounded waiting!"
⭐ TRICK to Remember: MPB = "Must Pass Boundary"
M=Mutual Exclusion (1 at a time) | P=Progress (no delay if free) | B=Bounded Waiting (no starving)
Toilet Example: Lock(ME) + Queue(BW) + Must use when free(P)

Q7. What is a semaphore? Explain binary and counting semaphores with suitable examples.
12 Marks
🗣️ In Simple Words:
Semaphore = A traffic signal for processes! 🚦
Red = STOP (wait), Green = GO (signal). It's an integer variable that controls how many processes can access a shared resource at the same time.
📌 Key Points:
Operations (ATOMIC — cannot be interrupted):
wait(S) also called P(S): signal(S) also called V(S): while(S <= 0) ; // wait S = S + 1 ; // release S = S - 1 ; // enter
📌 Key Points:
① Binary Semaphore (=Mutex): Value = 0 or 1 ONLY
  • 0 = locked (someone inside) | 1 = unlocked (free)
  • Used for Mutual Exclusion — only 1 process at a time
  • Example: Printer access (only 1 job prints at a time)
mutex = 1; wait(mutex); // lock — enter critical section // critical section (shared code) signal(mutex); // unlock — exit
📌 Key Points:
② Counting Semaphore: Value = 0 to N
  • Controls access to N identical resources
  • S=N means N resources available. S=0 means all busy — WAIT!
  • Example: Parking with 5 slots — Semaphore=5. Each car entering does wait(S). Each car leaving does signal(S). When S=0, next car waits!
BasisBinary SemaphoreCounting Semaphore
Value0 or 1 only0 to N
Also calledMutexGeneral Semaphore
Used forMutual Exclusion (1 at a time)N resources (N at a time)
Real exampleSingle toiletParking with N spaces
💡 Think of it Like:
Binary = Single toilet (1 or 0 — occupied or free)
Counting = Parking lot with N spaces — count down as cars enter, count up as cars leave!
📝 Write in Exam:
Semaphore is an integer synchronization variable. Operations: wait(S) decrements S; if S≤0, process blocks. signal(S) increments S, wakes a blocked process. Binary Semaphore: value 0 or 1, used for mutex. Counting Semaphore: value 0 to N, controls N resource instances. Both operations must be atomic.
✅ One Line Conclusion:
"wait()=enter(lock), signal()=exit(unlock). Binary=1 at a time, Counting=N at a time!"
⭐ TRICK to Remember: wait = P = "Please wait" (decrease S)
signal = V = "You may go" (increase S)
Binary=toilet(0/1) | Counting=parking(0 to N) | Atomic = cannot be interrupted!

Q8
Q8. What is deadlock? Explain the four necessary conditions for deadlock with examples.
12 Marks
🗣️ In Simple Words:
Deadlock = Traffic Jam at an intersection! 🚗
Car A waits for Car B to move. Car B waits for Car C. Car C waits for Car A. Nobody can move — FOREVER! In OS: processes wait for resources held by each other. Result: system hangs.
📌 Key Points:
ALL 4 conditions must hold simultaneously for deadlock:
  • ① Mutual Exclusion: Resource can only be used by 1 process at a time (Printer can only print 1 job)
  • ② Hold & Wait: Process holds 1 resource AND waits for more (P1 has printer, waiting for scanner)
  • ③ No Preemption: Resource can't be forcibly taken away (Can't snatch printer mid-print)
  • ④ Circular Wait: Chain of waiting: P1→P2→P3→P1 (P1 waits for P2, P2 waits for P1)
P1 ──wants──► R2 (held by P2)
↑                         │
R1 (held by P1) ◄──wants── P2
= DEADLOCK! Neither can proceed.
💡 Think of it Like:
Real life: Two people trying to pass on a narrow bridge — each says "You go first!" Neither moves. That's deadlock!
Break ANY ONE condition → NO deadlock!
📝 Write in Exam:
Deadlock is a situation where 2+ processes are permanently waiting for resources held by each other. 4 Necessary Conditions: ①Mutual Exclusion — only 1 process uses resource at a time ②Hold & Wait — process holds resource while waiting for more ③No Preemption — resource released only voluntarily ④Circular Wait — circular chain of processes waiting. ALL 4 must hold simultaneously.
✅ One Line Conclusion:
"Break ANY ONE of MHNC → Deadlock is IMPOSSIBLE!"
⭐ TRICK to Remember: MHNC = "My Hungry Nephew Cries"
M=Mutual Exclusion | H=Hold&Wait | N=No Preemption | C=Circular Wait
ALL 4 = Deadlock | Remove ANY 1 = No Deadlock!
Q9
Q9. Explain deadlock prevention, avoidance, detection and recovery techniques.
12 Marks
🗣️ In Simple Words:
4 ways to handle deadlock:
① Prevent it (remove conditions) → ② Avoid it (be careful) → ③ Detect it (let it happen, then find) → ④ Recover from it (fix after)
📌 Key Points:
① Prevention — Break a condition:
  • No Mutual Exclusion → make resources shareable (spooling)
  • No Hold&Wait → request ALL resources at start OR release before requesting more
  • Allow Preemption → forcibly take resources if needed
  • No Circular Wait → number all resources, always request in order (R1 before R2)
Downside: Low resource utilization
📌 Key Points:
② Avoidance — Banker's Algorithm:
Before giving any resource, CHECK if system stays in "safe state".
Safe State = There exists some order in which ALL processes can finish.
Unsafe State = May lead to deadlock (but not always).
If safe → GRANT. If unsafe → DENY the request.
📌 Key Points:
③ Detection — Find it after it happens:
  • Wait-for Graph: Draw who waits for whom. If cycle exists → DEADLOCK!
  • Resource Allocation Matrix: Run algorithm to find deadlocked processes
📌 Key Points:
④ Recovery — Fix it:
  • Process Termination: Kill deadlocked processes (one by one or all at once)
  • Resource Preemption: Take resources from some process, give to others. Rollback to safe state.
TechniqueWhenHowTrade-off
PreventionBefore deadlockBreak conditionsLow efficiency
AvoidanceBefore deadlockSafe state check (Banker's)Needs max info upfront
DetectionAfter deadlockWait-for GraphDetection overhead
RecoveryAfter detectionKill process / preempt resourceMay lose data
📝 Write in Exam:
Deadlock handling: ①Prevention — break Mutual Exclusion, Hold&Wait, No-Preemption or Circular Wait. ②Avoidance — Banker's Algorithm checks safe state before allocation. ③Detection — Wait-for Graph (cycle=deadlock) or Resource Allocation Matrix. ④Recovery — Process termination (kill all/one at a time) or Resource Preemption (rollback).
✅ One Line Conclusion:
"PADR: Prevention→Avoidance→Detection→Recovery — 4 weapons against deadlock!"
⭐ TRICK to Remember: "Please Avoid Deadly Results" = Prevention, Avoidance, Detection, Recovery
Prevention = BEFORE (remove condition) | Avoidance = BEFORE (check safe state)
Detection = AFTER (find it) | Recovery = AFTER (fix it)

Q10
Q10. Explain the Banker's Algorithm for deadlock avoidance with a suitable example.
12 Marks
🗣️ In Simple Words:
Banker's Algorithm = A bank that only gives loans if it can still pay all customers!
A banker gives loans only if they remain solvent (safe). Similarly, OS gives resources only if system stays in 'safe state'. If granting a resource request leads to unsafe state → DENY!
📌 Key Points:
Data needed:
  • Available = Resources currently free (can be given now)
  • Max = Maximum resources each process will EVER need
  • Allocation = Resources currently given to each process
  • Need = Still needed (Need = Max − Allocation)
Need[i] = Max[i] - Allocation[i] ← KEY FORMULA!
📌 Key Points:
Safety Algorithm (Is system in safe state?):
  • Step 1: Work = Available, Finish[all] = FALSE
  • Step 2: Find process Pi where: Finish[i]=FALSE AND Need[i] ≤ Work
  • Step 3: Work = Work + Allocation[i], Finish[i] = TRUE
  • Step 4: Repeat until no more found
  • Step 5: If ALL Finish=TRUE → SAFE STATE ✓ else UNSAFE ✗
📌 Example — 3 processes, Resources A,B,C:
ProcessMax (A,B,C)AllocationNeedAvailable: (3,3,2)
P07,5,30,1,07,4,3
P13,2,22,0,01,2,2
P29,0,23,0,26,0,0
📌 Key Points:
Finding safe sequence:
  • Work=(3,3,2). P1: Need(1,2,2)≤Work(3,3,2)? ✅ Work=(5,3,2), Finish[P1]=TRUE
  • P0: Need(7,4,3)≤Work(5,3,2)? ❌ Skip. P2: Need(6,0,0)≤(5,3,2)? ❌ Skip
  • Go back... after more steps → Safe Sequence: P1 → P2 → P0 ✅
💡 Think of it Like:
Banker giving loan: Before giving ₹1000 to Customer A, bank checks: if I give this, can I still pay everyone else? YES → give. NO → sorry, wait!
📝 Write in Exam:
Banker's Algorithm is a deadlock avoidance algorithm. It uses Available, Max, Allocation and Need (=Max-Allocation) matrices. For each request, it temporarily allocates and runs Safety Algorithm. Safety: Find process where Need≤Work, execute it, add its allocation to Work. If all Finish=TRUE → safe state, grant request. Else deny.
✅ One Line Conclusion:
"Need=Max-Allocation | Safe State=all can finish | Unsafe=may deadlock!"
⭐ TRICK to Remember: Need = Max - Allocation (Most important formula!)
Safe = Everyone can finish in SOME order | Unsafe = Someone stuck forever
"Banker gives loan only if still solvent after!"

Q11
Q11. Explain memory management and discuss different memory allocation techniques.
12 Marks
🗣️ In Simple Words:
Memory Management = OS as a hotel manager 🏨
Hotel = RAM. Rooms = memory blocks. Guests = processes. Manager (OS) assigns rooms, kicks out guests when done, and keeps track of empty rooms!
📌 Key Points:
Memory Management does:
  • Tracks which parts of RAM are used/free
  • Allocates RAM to new processes
  • Takes back RAM when process finishes
  • Protects one process's memory from another
📌 Key Points:
Allocation Techniques:
① Contiguous Allocation = Process stored in ONE continuous block of RAM:
  • Single Partition: Only 1 process at a time. Simple but wasteful.
  • Multiple Partition (Fixed): RAM divided into fixed slots. Easy but causes Internal Fragmentation.
  • Dynamic Partition: Slots created as needed. Better use but causes External Fragmentation.
Fitting strategies: First Fit (first big enough hole), Best Fit (smallest suitable hole), Worst Fit (largest hole)

② Non-Contiguous Allocation = Process stored in scattered parts of RAM:
  • Paging → fixed-size pages (no external frag)
  • Segmentation → variable-size segments (logical)
💡 Think of it Like:
Fragmentation:
🔴 Internal Fragmentation = You booked a 4-person hotel room but only 2 people came. 2 bed spots wasted INSIDE the room.
🔴 External Fragmentation = Hotel has empty rooms scattered everywhere but no 2 adjacent rooms free for a family of 4. Total space exists but not usable together!
📝 Write in Exam:
Memory Management tracks, allocates and deallocates RAM. Techniques: ①Contiguous: Single Partition, Multiple Partition (Fixed/Variable). Allocation: First Fit, Best Fit, Worst Fit. Problem: Internal frag (fixed) and External frag (variable). ②Non-Contiguous: Paging (fixed pages, no external frag), Segmentation (logical segments).
✅ One Line Conclusion:
"OS = Hotel Manager. RAM = Hotel. Fragmentation = wasted space inside or between rooms!"
⭐ TRICK to Remember: Internal Frag = wasted space INSIDE allocated block (fixed size)
External Frag = wasted space BETWEEN blocks (variable size)
Fix: Compaction (move blocks together) or use Paging!
Q12
Q12. Explain paging and segmentation. Differentiate between them.
12 Marks
🗣️ In Simple Words:
Paging = Cut program into equal-size slices (pages), put them anywhere in RAM (frames)!
Segmentation = Cut program into logical parts (code, data, stack) of different sizes!
Think: Paging = equal pizza slices. Segmentation = different sized food containers.
📌 Key Points:
PAGING:
  • Program divided into fixed-size PAGES (equal size)
  • RAM divided into fixed-size FRAMES (same size as page)
  • Page Table maps each page to a frame number
  • No External Fragmentation! (pages fit anywhere)
  • May have Internal Fragmentation (last page might not be full)
Physical Address = Frame Number × Page Size + Offset Example: Page 2 → Frame 5, Offset=100, Size=1KB PA = 5 × 1024 + 100 = 5220
Logical: Page 0 → [Page Table] → Frame 3 → Physical: Frame 3
Logical: Page 1 → [Page Table] → Frame 7 → Physical: Frame 7
Pages can be in ANY frame — scattered is OK!
📌 Key Points:
SEGMENTATION:
  • Program divided into logical variable-size SEGMENTS (code, data, stack)
  • Segment Table stores Base address + Limit for each segment
  • No Internal Fragmentation (segments exact size needed)
  • May have External Fragmentation

Q13. What is virtual memory? Explain demand paging and its advantages.
12 Marks
🗣️ In Simple Words:
Virtual Memory = Magic trick to run big programs on small RAM! 🎩
Like reading a 1000-page book — you don't carry all 1000 pages. You read 10 pages, put them back, get next 10. OS does same with programs: loads only NEEDED parts into RAM, rest stays on disk!
📌 Key Points:
Virtual Memory:
  • Gives process the ILLUSION of huge memory (even if RAM is small)
  • Uses DISK (HDD/SSD) as extension of RAM
  • Process can be larger than physical RAM
  • Only ACTIVE parts need to be in RAM
📌 Key Points:
Demand Paging = Lazy Loading:
Pages loaded into RAM ONLY when needed (demanded). At program start → NO pages in RAM. As program runs → pages loaded on demand.

Page Fault = When process needs a page that's NOT in RAM:
  • OS traps → finds free frame → loads page from disk → updates page table → restarts instruction
Process accesses page → Check page table → Valid? → Use it ✅
                                          → Invalid → PAGE FAULT! ❌
                                                            → Load from Disk → Update table → Retry
📌 Key Points:
Advantages of Virtual Memory:
  • ✅ Run programs LARGER than physical RAM
  • ✅ More processes run simultaneously (high multiprogramming)
  • ✅ Less I/O — only needed pages loaded
  • ✅ Better response time
  • ✅ No need to load ENTIRE program at start
💡 Think of it Like:
Thrashing = When OS spends more time loading pages than actually running program. Like spending more time finding pages in a book than reading! Happens when RAM is too small for too many processes.
📝 Write in Exam:
Virtual memory allows execution of programs larger than physical RAM using disk as extension. Demand Paging: pages loaded only when needed. Page Fault: page not in RAM → OS loads from disk. Steps: ①page fault trap ②OS saves state ③find free frame ④load page from disk ⑤update page table ⑥restart instruction. Advantages: large programs run, more multiprogramming, less I/O, faster startup, efficient memory use.
✅ One Line Conclusion:
"Virtual Memory = Big RAM illusion using Disk. Demand Paging = Lazy loading!"
⭐ TRICK to Remember: Page Fault = Page not in RAM → Load from Disk → Try again
More page faults = slower system | Thrashing = too many page faults = system stuck
"VM gives you a big library. Demand Paging gets books only when you ask!"
Q14
Q14. Explain page replacement algorithms: FIFO, LRU and Optimal. Give suitable examples.
12 Marks
🗣️ In Simple Words:
When RAM is full and you need a new page, which old page do you kick out?
That's Page Replacement! Like deciding which app to close on your phone when it's full.
Goal: remove the page you'll need LEAST in the future → minimum page faults!
📌 Key Points:
① FIFO (First In First Out) = Oldest page leaves first
Like a queue — first to enter, first to leave. Simple but can be dumb (might remove a frequently used page!).
⚠️ Belady's Anomaly: More frames can cause MORE page faults in FIFO! (weird but true)
📌 Key Points:
② LRU (Least Recently Used) = Remove page NOT used longest in PAST
Smart! If you haven't used it recently, probably won't need soon. No Belady's anomaly.
Implementation: Timestamps or Stack
📌 Key Points:
③ Optimal = Remove page NOT needed longest in FUTURE
BEST result (minimum faults) but NOT practical (can't know future!). Used as benchmark.

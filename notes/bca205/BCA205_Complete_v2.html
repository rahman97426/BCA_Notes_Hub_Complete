Ans:

Introduction: An Operating System (OS) is system software that acts as a link between the user and computer hardware. It manages hardware resources and provides services to programs.

Functions and objectives: The main objectives are convenient use of the computer, efficient use of resources and safe operation. The OS manages the CPU, memory, files and I/O devices. It also controls processes, provides security and detects errors.

Major services: Program execution, I/O operations, file-system manipulation, communication, error detection, resource allocation, accounting and protection/security.

User / Application Programs ↓ OPERATING SYSTEM ↓ CPU • Memory • Files • I/O Devices

Example: Linux manages applications, RAM, CPU time, files and devices.

Conclusion: Thus, an OS makes the computer easy to use and manages hardware resources efficiently.

VVI answer

Ans: CPU scheduling is the process of selecting a process from the ready queue and giving it the CPU for execution.

FCFS: First Come First Serve executes processes in the order in which they arrive. It is simple and normally non-preemptive.

SJF: Shortest Job First selects the process having the smallest CPU burst. It can be preemptive or non-preemptive.

Priority: The process with the highest priority is selected. It may be preemptive or non-preemptive.

Round Robin: Each ready process gets a fixed time quantum. If it does not finish, it goes back to the ready queue.

Ready Queue → CPU Scheduler → CPU ↑ ↓ waiting ← preemption / completion

Conclusion: CPU scheduling improves CPU utilization and system performance. The choice of algorithm depends on the system requirement.

🧠 FCFS = first arrival • SJF = shortest job • Priority = highest priority • RR = fixed time slice.
VVI answer🟠 COLLEGE CLASS-TEST ALERT • 5 MARKS

Ans: CPU scheduling is the selection of a process from the ready queue to run on the CPU. The short-term CPU scheduler makes this decision according to a scheduling algorithm.

Processes waiting for CPU stay in the Ready state. When the scheduler selects one, it moves to Running. If it finishes, it goes to Terminated. If it requests I/O, it moves to Waiting. After I/O completion, it returns to Ready. In a preemptive system, a running process may be moved back to Ready.

dispatch Ready ───────────→ Running ↑ │ │ │ I/O done │ └──→ Terminated │ ↓ └────────────── Waiting (I/O request) Preemption: Running → Ready

Conclusion: The scheduler selects the suitable ready process so that CPU time is used efficiently and response is improved.

🧠 State flow: Ready → Running → Waiting → Ready; finish = Terminated.

Major functions: process management, memory management, file management, device/I/O management, security/protection, error handling and resource allocation.

Types: Batch OS processes jobs in groups; Multiprogramming OS keeps several programs in memory; Multitasking OS runs many tasks apparently together; Time-Sharing OS gives CPU time to users/processes; Real-Time OS gives responses within required deadlines; Distributed OS coordinates networked computers.

Conclusion: Therefore, the OS controls resources and provides useful services to users and applications.

Process Management, Synchronization & Deadlock

Process • PCB • Threads • Critical Section • Semaphores • Deadlock • Banker’s Algorithm
PYQ ALERT: 🔴 Deadlock: verified topic years 2016, 2017, 2019, 2021, 2022, 2023. Critical section/synchronization: 2016, 2017, 2019, 2022, 2023. Process/thread concepts also recur in verified PYQs.
🔴 Must-study / repeated🟠 High priority🟡 VVI / syllabus-linked
Exam writing: Write the answer in the same order: Definition/Introduction → Main Explanation → Points/Example → Diagram/Table → Conclusion. Do not add unrelated theory.
VVI answer

Ans: A process is a program in execution. It has its own current state and resources required for execution.

Process states: New means the process is being created. Ready means it is waiting for CPU. Running means it is executing. Waiting/Blocked means it is waiting for an event such as I/O. Terminated means execution is finished.

New → Ready → Running → Terminated ↑ │ │ ↓ └── Waiting I/O completion ↑

PCB: Process Control Block is the data structure maintained by the OS for a process. It stores process state, process ID, program counter, CPU registers, scheduling information, memory-management information and I/O/accounting information.

Conclusion: The process state shows what a process is doing, while the PCB stores the information needed by the OS to manage it.

🧠 PCB = State + ID + PC + Registers + Schedule + Memory + I/O.
VVI answer

Ans: A thread is the smallest unit of CPU execution within a process. Threads of the same process share its code, data and other resources but have their own execution state.

Types: User-level threads are managed mainly by a user-level library. Kernel-level threads are managed by the operating system kernel.

ProcessThread
Independent program in execution.Execution unit inside a process.
Has its own address space/resources.Shares process resources.
Creation/context switch is generally heavier.Generally lighter and faster.

Conclusion: Threads improve responsiveness and allow concurrent work within a process.

🧠 Process = container; Thread = worker inside the container.
VVI answer

Ans: A critical section is the part of a program where shared data or a shared resource is accessed. The critical-section problem is to design a solution so concurrent processes do not corrupt shared data.

Requirements: Mutual exclusion means only one process can execute its critical section at a time. Progress means selection of the next process should not be postponed unnecessarily. Bounded waiting means a process should not wait forever to enter its critical section.

Entry Section → Critical Section → Exit Section → Remainder Section

Solutions: hardware atomic instructions, locks/mutexes, semaphores and suitable software algorithms.

Conclusion: A correct solution protects shared data while maintaining fairness and progress.

🧠 Requirements = MPB: Mutual exclusion, Progress, Bounded waiting.
VVI answer

Ans: A semaphore is a synchronization variable used to control access to shared resources. Its value is changed only through atomic operations commonly called wait() and signal().

Binary semaphore: It has values such as 0 and 1 and can be used like a lock for mutual exclusion.

Counting semaphore: It can hold a non-negative count and is useful when several identical resources are available.

wait(S) → decrease S / wait if unavailable signal(S) → increase S / wake a waiting process

Example: A counting semaphore initialized to 3 can control access to three identical printers/resources.

Conclusion: Semaphores help processes coordinate and prevent unsafe simultaneous access.

🧠 Binary = one permit; Counting = many permits.
VVI answer🟠 COLLEGE CLASS-TEST ALERT • 5 MARKS

Ans: Deadlock is a situation in which a group of processes waits forever because each process is waiting for a resource held by another process in the group.

Four necessary conditions:

  1. Mutual exclusion: A resource can be used by only one process at a time.
  2. Hold and wait: A process holds at least one resource while waiting for another.
  3. No preemption: A resource cannot be forcibly taken away; it must be released by its holder.
  4. Circular wait: A circular chain exists where each process waits for a resource held by the next process.
P1 holds R1 → waits R2 ↑ ↓ R1 ← P2 holds R2

Conclusion: Deadlock can occur only when all four conditions exist together.

🧠 M-H-N-C = Mutual exclusion, Hold & wait, No preemption, Circular wait.
VVI answer

Ans: Deadlock handling methods try to stop deadlock or recover after it occurs.

Prevention: Design the system so at least one necessary deadlock condition cannot hold, for example by preventing circular wait through an ordering of resources.

Avoidance: Before granting a request, the OS checks whether the resulting state is safe. The Banker’s Algorithm is a common method.

Detection: The OS allows deadlock to occur and periodically checks for a deadlock condition using suitable detection methods.

Recovery: After detection, the OS can terminate selected processes or preempt resources and restore the system to a safe state.

Conclusion: Prevention avoids a condition, avoidance checks safety before allocation, detection finds deadlock, and recovery removes its effects.

🧠 P-A-D-R = Prevent → Avoid → Detect → Recover.
VVI answer

Ans: Banker’s Algorithm is a deadlock-avoidance algorithm. It checks whether granting a resource request keeps the system in a safe state.

Main data: Available shows free resources. Max is the maximum demand of each process. Allocation is the resources currently given. Need is calculated as:

Need = Max − Allocation

Basic steps: Find a process whose Need ≤ Available. Pretend it completes and releases its Allocation. Add the released resources to Available. Repeat. If all processes can finish, the state is safe; otherwise it is unsafe.

Available ↓ Find Need ≤ Available ↓ Assume process finishes ↓ Available = Available + Allocation ↓ Repeat → Safe sequence / Unsafe state

Conclusion: The Banker’s Algorithm grants resources only when the system can remain in a safe state.

🧠 Formula: Need = Max − Allocation. Safe = every process can get its remaining Need in some order.

Memory Management & Virtual Memory

Allocation • Paging • Segmentation • Virtual Memory • Page Replacement
PYQ ALERT: 🔴 Page faults/page replacement: verified topic years 2016, 2017, 2018, 2019, 2021, 2022, 2023. Fragmentation: 2018, 2019, 2022. Paging/segmentation was asked in 2014.
🔴 Must-study / repeated🟠 High priority🟡 VVI / syllabus-linked
Exam writing: Write the answer in the same order: Definition/Introduction → Main Explanation → Points/Example → Diagram/Table → Conclusion. Do not add unrelated theory.
VVI answer

Ans: Memory management is the OS function that manages main memory and allocates memory to processes.

Contiguous allocation: A process is placed in one continuous area of memory. Common methods include fixed/variable partitions and placement methods such as first fit, best fit and worst fit.

Non-contiguous allocation: A process may be divided and placed in different memory locations. Paging and segmentation are important examples.

Goals: efficient memory use, protection, relocation and support for multiple processes.

Main Memory | OS | Process A | Free | Process B | Free |

Conclusion: Good memory management allows more processes to run while using RAM efficiently.

🧠 Allocation = Contiguous (together) vs Non-contiguous (separate).
VVI answer

Ans: Paging and segmentation are non-contiguous memory-management techniques.

Paging: Logical memory is divided into fixed-size pages and physical memory into fixed-size frames. A page table maps page numbers to frame numbers.

Segmentation: A program is divided into logical variable-size segments such as code, data and stack. A segment table maps segment numbers to their memory locations.

PagingSegmentation
Fixed-size pagesVariable-size segments
Based mainly on physical memory unitsMatches logical program units
Uses page tableUses segment table
Paging: Logical Address → Page No. + Offset → Page Table → Frame + Offset

Conclusion: Paging reduces external fragmentation, while segmentation represents the logical structure of a program.

🧠 Page = fixed; Segment = logical + variable.
VVI answer

Ans: Virtual memory is a memory-management technique that allows a process to use an address space larger than the available physical RAM by keeping required parts in secondary storage.

Demand paging: Pages are loaded into memory only when they are needed. If the required page is not in memory, a page fault occurs. The OS brings the page from disk/secondary storage into a free frame and continues execution.

CPU reference → Page in memory? │Yes → continue │No ↓ Page fault ↓ Load page from disk ↓ Update table ↓ Continue

Advantages: better memory utilization, larger logical address space and ability to run programs that do not fit completely in RAM.

Conclusion: Virtual memory improves flexibility by loading only the pages that are required.

🧠 Demand paging = “Load only when needed.”
VVI answer

Ans: When a page fault occurs and all frames are full, the OS must choose a page to remove. This is called page replacement.

FIFO: Replaces the page that entered memory first.

LRU: Replaces the page that has not been used for the longest time.

Optimal: Replaces the page whose next use is farthest in the future. It gives the theoretical minimum number of page faults but needs future knowledge, so it is mainly used as a benchmark.

AlgorithmVictim page
FIFOOldest loaded page
LRULeast recently used
OptimalUsed farthest in future

Conclusion: FIFO is simple, LRU uses recent history, and Optimal is the ideal benchmark.

🧠 FIFO = oldest • LRU = least recent • OPT = farthest future.

VVI answer

Ans: UNIX is a multiuser, multitasking operating system. It provides a command-based environment and manages system resources through the kernel.

Features: multiuser operation, multitasking, portability, security, hierarchical file system, shell interface and strong support for networking/utilities.

Architecture/components: users interact through applications and the shell. The shell interprets commands and communicates with the kernel. The kernel manages CPU/processes, memory, files and devices. Hardware is at the bottom.

Users → Applications / Shell → Kernel → Hardware ↕ File • Memory • Process • Device management

Conclusion: UNIX provides a powerful and organized environment for multiuser and multitasking computing.

🧠 Layer order: User → Shell → Kernel → Hardware.

Ans: UNIX uses a hierarchical file system beginning at the root directory represented by /. Directories can contain files and other directories.

/ ├── home ├── bin ├── etc ├── dev ├── tmp └── var

Absolute pathname: Starts from the root / and gives the complete path, for example /home/user/file.txt.

Relative pathname: Starts from the current directory, for example docs/file.txt. . means current directory and .. means parent directory.

Conclusion: Pathnames tell UNIX exactly where a file or directory is located.

🧠 Absolute = starts /; Relative = starts from current directory.
VVI answer

Ans: UNIX permissions control who can read, write or execute a file.

Permissions are commonly represented for user (u), group (g), others (o). The three basic permissions are r = read, w = write, x = execute.

chmod changes permissions, e.g. chmod 755 file.sh. chown changes file owner, e.g. chown user file.txt. chgrp changes group ownership, e.g. chgrp staff file.txt.

Hard link: another directory entry referring to the same underlying file data/inode. Soft link: a symbolic link that stores a path to another file.

File → permissions: r w x | r w x | r w x user group others

Conclusion: Permissions and links help UNIX provide controlled and flexible file management.

🧠 rwx = 4,2,1; 755 = rwx r-x r-x.

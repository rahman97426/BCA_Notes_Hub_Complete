What is multiprogramming? How does it differ from time-sharing?
▼
📖 Multiprogramming: Keeps several jobs in main memory simultaneously. When running job waits for I/O, CPU immediately switches to another ready job — keeps CPU busy all the time.
📖 Time-Sharing: Extension of multiprogramming. Switching is so rapid (using time quanta/slices) that every user feels they have a dedicated computer.

4M 📌 PYQ 2023 Q1(b) | Syllabus-core
What is I/O buffering? Explain its types.
▼
📖 I/O Buffering: A technique of using a temporary memory area (buffer) to hold data being transferred between a device and a program, smoothing out their speed difference. Devices are much slower than CPUs.
Types of Buffering:
  1. Single Buffering: One buffer between device and process. While process consumes buffer, device cannot write — inefficient.
  2. Double Buffering: Two buffers used alternately. One fills while the other is consumed simultaneously — much faster.
  3. Circular Buffering: Multiple buffers in a circular queue. Used for continuous data streams like audio/video.
💡 Example: Typing in an editor uses a keyboard buffer. Copying a large video reads it in chunks into a disk buffer instead of one byte at a time.
✍️ Conclusion: Buffering is essential because I/O devices are far slower than CPUs. Without buffering, the CPU would waste most of its time waiting for devices.

12M 🔥 PYQ 2019 Q2(a) | 2021 | Repeated 12-mark — MUST PREPARE
What is an Operating System? What are the various services provided by the Operating System? Explain each with examples.
▼
📌 Introduction: An Operating System is the most essential software in a computer. It acts as an intermediary between the hardware and the user, managing all hardware resources and providing a convenient, safe environment for programs and users.
📖 Definition: An Operating System is system software that manages computer hardware resources and provides common services for computer programs. It sits between the hardware layer (CPU, memory, devices) and the application software layer (Word, Chrome, games).
Goals of an Operating System:
  1. Convenience — makes the computer easier to use.
  2. Efficiency — ensures optimum use of hardware resources.
  3. Ability to evolve — new features can be added without disturbing existing services.
Services Provided by OS:
  1. Program Execution: The OS loads a program into memory, runs it, and ends it normally or on error. Example: Double-clicking a game icon — OS loads it and runs it.
  2. I/O Operations: User programs cannot access I/O devices directly for safety. OS performs I/O on their behalf. Example: Printing a document.
  3. File-System Manipulation: Create, delete, open, close, read, and write files and directories. Example: Saving a Word document.
  4. Communication: Exchange of information between processes using shared memory or message passing. Example: Copy-paste between two applications.
  5. Error Detection: Constantly watches for CPU, memory, I/O, and program errors and takes appropriate action. Example: "Application has stopped working" error message.
  6. Resource Allocation: CPU cycles, memory and storage allotted fairly among many users/jobs. Example: Sharing CPU time between Chrome, music player, and antivirus.
  7. Accounting: Keeps track of which user/job uses how much of which resource (important for billing in multi-user systems).
  8. Protection and Security: Controlled access to resources and defence against outside attack. Example: Login password, file permissions.
💡 Real Life Example: When you save a Word document (file-system service), print it (I/O service), and listen to music at the same time (resource allocation) — the OS manages all three simultaneously, invisibly.

✍️ Conclusion: The Operating System is indispensable — without it, no program can run, no file can be saved, and no device can be used safely. It makes the computer usable, safe, and efficient for every user. Modern OS like Windows and Linux provide all eight services simultaneously.
12M 🔥 PYQ 2014 Q3 | 2022 Q3 | 2023 Q7 — MOST REPEATED 12-mark in the entire paper
Explain CPU Scheduling. What are the scheduling criteria? Describe FCFS, SJF, Priority Scheduling and Round Robin algorithms with a solved numerical example.
▼
📌 Introduction: In a multiprogrammed OS, many processes reside in memory but only one can use the CPU at a time on a single core. CPU Scheduling is the process by which the OS decides which ready process gets the CPU next, aiming to maximise efficiency and fairness.
📖 Definition: CPU Scheduling is the activity of the short-term scheduler that selects, from among the processes in the ready queue, which process will get the CPU next. The dispatcher then switches the CPU to that process (context switch).
Scheduling Criteria (Goals to Optimise):
  1. CPU Utilisation — Keep the CPU as busy as possible (MAXIMISE). Target: 40-90%.
  2. Throughput — Number of processes completed per unit time (MAXIMISE).
  3. Turnaround Time (TAT) = Completion Time − Arrival Time (MINIMISE).
  4. Waiting Time (WT) = Turnaround Time − Burst Time (MINIMISE).
  5. Response Time — Time from submission to first response (MINIMISE). Critical for interactive systems.
CPU Scheduling Algorithms:
1. FCFS — First Come First Served
Non-preemptive. Processes run in arrival order (like a queue at a ticket counter).
Problem: Convoy Effect — one long job blocks all shorter jobs behind it, causing high average waiting time.
2. SJF — Shortest Job First
Non-preemptive. Process with the shortest CPU burst time runs next.
Advantage: Gives optimal (minimum) average waiting time.
Problem: Starvation of long jobs. Needs burst time prediction.
3. Priority Scheduling
CPU goes to the highest-priority ready process (smaller number = higher priority usually).
Can be preemptive or non-preemptive.
Problem: Starvation. Solution: Aging — gradually increase priority of waiting processes.
4. Round Robin (RR)
Preemptive. Each process gets a fixed time quantum, then joins the back of the ready queue.
Best for: Time-sharing/interactive systems.
Note: Large quantum → behaves like FCFS. Small quantum → too many context switches (overhead).

12M 🔥 PYQ 2021 Q3 | 2025 Q3 | 12-mark
What are system calls? Describe their types with examples. Also explain storage structures (memory hierarchy).
▼
📌 Introduction: User programs run in 'user mode' and cannot directly access hardware for safety. System calls provide the only safe mechanism for a user program to request OS services.
📖 Definition: A system call is a programmatic interface (API) that allows a user-level program to request a service from the OS kernel. It causes a mode switch from user mode to kernel mode via a TRAP instruction.
How a System Call Works:
  1. User program calls a library function (e.g., fopen())
  2. Library function invokes the system call (e.g., open())
  3. TRAP instruction fires → CPU switches to kernel mode
  4. OS kernel performs the requested service
  5. Result returned → CPU switches back to user mode
Types of System Calls:
  1. Process Control: fork() [create process], exec() [run program], exit() [terminate], wait() [wait for child]. Example: Running a new program from terminal.
  2. File Management: open(), close(), read(), write(), create(), delete(). Example: Opening a text file in a text editor.
  3. Device Management: ioctl() [device control], read(), write() for devices. Example: Reading from keyboard.
  4. Information Maintenance: getpid() [get process ID], time() [get system time], alarm(). Example: A program checking how long it has been running.
  5. Communication: pipe() [create pipe], socket() [network], send(), receive(). Example: Two processes exchanging data via a pipe.

12M 🔥 PYQ 2016 Q1(c) | 2022 Q4 | 2023 Q3 — Repeated every year — MUST PREPARE
What is the critical-section problem? State its three requirements. Explain semaphores and solve the Producer-Consumer problem using semaphores.
▼
📌 Introduction: When multiple processes access shared data concurrently without any control, the result depends on the exact order of execution — this is called a race condition. The critical-section problem is about designing a solution that prevents race conditions.
📖 Critical Section: The segment of code in a process where it accesses shared resources (shared variables, files, buffers) that must not be accessed simultaneously by more than one process.
Three Requirements for a Correct Solution:
  1. Mutual Exclusion: If process Pi is executing in its critical section, no other process can execute in its critical section at the same time. (Only one at a time)
  2. Progress: If no process is in its critical section, and some processes wish to enter, the decision of who enters next cannot be postponed indefinitely.
  3. Bounded Waiting: There must be a bound on the number of times other processes can enter their critical section after a process has made a request — no starvation allowed.
Semaphore Solution:
📖 Semaphore: An integer variable accessed only through two atomic operations:
  • wait(S) / P() / down(): Decrements S. If S becomes negative, the process blocks.
  • signal(S) / V() / up(): Increments S. If S was negative (processes waiting), wakes one up.
Types: Binary semaphore (mutex) — value 0 or 1. Counting semaphore — any integer value.
Classical Problem: Producer-Consumer (Bounded Buffer)
Setup: Producer adds items to a bounded buffer. Consumer removes items. Buffer has N slots.

Three Semaphores:
• mutex = 1 (binary — mutual exclusion for buffer access)
• empty = N (counting — number of empty slots)
• full = 0 (counting — number of filled slots)

Producer code:
wait(empty); // wait if no empty slot
wait(mutex); // enter critical section
// add item to buffer
signal(mutex); // exit critical section
signal(full); // signal that one more slot is filled

Consumer code:
wait(full); // wait if no item to consume
wait(mutex); // enter critical section
// remove item from buffer
signal(mutex); // exit critical section
signal(empty); // signal that one more slot is free
Other Classical Synchronization Problems:
  1. Readers-Writers Problem: Multiple readers can read simultaneously, but writers need exclusive access. Solved using reader count + mutex + write semaphore.
  2. Dining Philosophers Problem: 5 philosophers, 5 forks between them. Need both neighbouring forks to eat. Naive solution → deadlock (all pick left fork). Fix: Allow at most 4 to sit, or asymmetric rule (odd picks left first, even picks right first).
💡 Real Example: A print spooler is a producer-consumer system. Applications (producers) add print jobs. The printer driver (consumer) removes and prints them. Semaphores ensure no two apps corrupt the job queue simultaneously.
✍️ Conclusion: Semaphores are the standard, simple tool operating systems use to guarantee mutual exclusion, progress and bounded waiting. The three requirements — Mutual Exclusion, Progress, Bounded Waiting — must ALL be satisfied for a correct critical-section solution. These three terms must be written in every exam answer on this topic.
12M 🔥 PYQ 2016 Q2(d) | 2019 Q2(b) | 2021 Q5 | 2022 Q5 | 2023 Q4 — 5 years repeated
What are the necessary conditions for deadlock? Explain deadlock prevention. Describe the Banker's Algorithm with a solved example.
▼
📌 Introduction: A deadlock is one of the most serious problems in multiprogrammed systems. It is a situation where processes permanently block each other, wasting all their allocated resources without making any progress.
📖 Definition: A deadlock is a state in which each process in a set is waiting for an event (typically resource release) that can only be caused by another process in the same set. Result: no process in the set can ever proceed.
Four Necessary Conditions for Deadlock (Coffman Conditions):
  1. Mutual Exclusion: At least one resource must be held in non-shareable mode. (Only one process can use it at a time.)
  2. Hold and Wait: A process holding at least one resource is waiting to acquire additional resources held by other processes.
  3. No Preemption: Resources cannot be forcibly taken from a process. They can only be released voluntarily.
  4. Circular Wait: A circular chain exists: P0 waits for a resource held by P1, P1 waits for P2's resource, ..., Pn waits for P0's resource.
⚠️ KEY EXAM POINT: ALL FOUR conditions must hold simultaneously for deadlock to occur. Remove ANY ONE condition → no deadlock possible.
Deadlock Prevention (Remove one condition):
  1. Break Mutual Exclusion: Make resources shareable where possible (not always practical — printers cannot be shared mid-job).
  2. Break Hold and Wait: Require process to request ALL resources before it starts. OR: release all resources before making a new request.
  3. Break No Preemption: If a process holding resources requests one unavailable, take away all its current resources. Restart when all resources available.
  4. Break Circular Wait: Impose a strict total ordering on resource types. Require each process to request resources ONLY in increasing order of their type number.
Deadlock Avoidance — Banker's Algorithm:
📖 Concept: The OS acts like a bank manager — grant a loan (resource) only if after granting it, the system remains in a SAFE STATE (all processes can still eventually finish).

Key Formula: Need = Max − Allocation

Safe State: A state is safe if there exists a sequence (safe sequence) in which all processes can finish, each getting its maximum need met.
Banker's Algorithm — Solved Example:

Deadlock Recovery:
  1. Process Termination: Abort all deadlocked processes at once (drastic), or abort one at a time until cycle breaks.
  2. Resource Preemption: Forcibly take resources from a victim process, roll it back, restart later. Ensure same process is not always victim (to avoid starvation).
✍️ Conclusion: Deadlock prevention removes one of the four conditions structurally but may reduce resource utilisation. The Banker's Algorithm avoids deadlock at runtime by only granting safe requests. In AKU exams, always write all four Coffman conditions by name and always write the safety sequence when solving Banker's Algorithm.

4M 📌 PYQ 2016/17 | 2025 Q5 | 4-mark
Explain swapping and contiguous memory allocation. What is the difference between logical and physical address?
▼
📖 Logical Address: Generated by the CPU during execution. Also called virtual address. The address the program "thinks" it is using.
📖 Physical Address: Actual address in the RAM seen by the memory hardware. The MMU (Memory Management Unit) translates logical to physical address.
Swapping: Temporarily moving a process OUT of main memory to backing store (disk), and bringing it back later to continue execution.
  • Increases degree of multiprogramming without more RAM.
  • Tools: swap partition or swap file on disk.
Contiguous Allocation: Each process placed in one single continuous block of memory.
  • Fixed Partitioning: Pre-divided into fixed sizes. Simple but causes internal fragmentation.
  • Variable Partitioning: Partition sized exactly for process. Causes external fragmentation over time.
  • Algorithms: First-fit (first block big enough), Best-fit (smallest fitting block), Worst-fit (largest block).
✍️ Logical-physical address separation allows the OS to relocate processes freely in RAM without the program knowing — making virtual memory and process isolation possible.

12M 🔥 PYQ 2014 Q4 | 2021 Q6 | 2016/17 Q2(a) | 2023 Q2(c) — Combined 12-mark
Explain paging in detail. What is the need for a page table and TLB? Explain virtual memory and demand paging with page fault handling steps.
▼
📌 Introduction: Contiguous memory allocation wastes memory through fragmentation and limits program size to physical RAM. Paging and virtual memory together solve both problems — eliminating external fragmentation and letting programs larger than RAM run.
📖 Paging: A non-contiguous memory management scheme that divides physical memory into fixed-size blocks called frames and logical memory into blocks of the same size called pages. Pages can be loaded into any available frames — no contiguity needed.
How Paging Works:
  1. Logical address = page number (p) + page offset (d)
  2. Page table maps: page number → frame number
  3. Physical address = frame number + offset d (offset stays unchanged)
ConceptExplanation
PageFixed-size block of logical memory
FrameFixed-size block of physical memory (same size as page)
Page TableMaps each page number to its frame number in RAM

Need for Page Table: Without a page table, the CPU cannot translate logical (virtual) addresses generated by programs to actual physical addresses in RAM. Each process has its own separate page table. TLB (Translation Lookaside Buffer):
📖 Looking up the full page table in RAM for every memory access requires TWO memory accesses — too slow! The TLB is a small, extremely fast hardware associative cache that stores the most recently used page → frame mappings.
  • TLB HIT: Frame number found instantly — only 1 memory access total.
  • TLB MISS: Go to page table in RAM, then update TLB. 2 memory accesses.
  • Modern CPUs achieve >98% TLB hit rate → paging overhead becomes negligible.
Virtual Memory:
📖 Virtual memory allows a process to execute even when it is not completely loaded in physical memory. The logical address space can be MUCH LARGER than physical RAM.
Demand Paging: Load a page into memory ONLY when it is actually referenced — not in advance. Uses a valid-invalid bit in the page table:
  • Valid (1): Page is currently in a RAM frame.
  • Invalid (0): Page is NOT in RAM → causes a PAGE FAULT.
Page Fault Handling Steps:
  1. Process references a page; valid-invalid bit = 0 → PAGE FAULT TRAP fires.
  2. OS checks: is this a legal address for this process? If illegal → abort process.
  3. Find a free frame in RAM (or select a victim using page replacement algorithm).
  4. Schedule a disk read to bring the required page into the free frame.
  5. Update page table: set frame number, set valid bit = 1.
  6. Restart the instruction that caused the page fault.
💡 Real Example: Opening a 2 GB video editor does NOT load all 2 GB at once. Only the pages you actually use — current menus, current video frame — are loaded on demand. This is why startup is faster and more programs can run simultaneously.
✍️ Conclusion: Paging eliminates external fragmentation and enables virtual memory. The TLB makes paging fast. Demand paging allows programs much larger than physical RAM to run, increases the degree of multiprogramming, and reduces startup time — at the cost of occasional page-fault delays. These are the most important memory management techniques in modern operating systems.

Explain the page replacement algorithms FIFO, LRU and Optimal. Solve: reference string 7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1 using LRU with 3 frames.
▼
📌 Introduction: When a page fault occurs and no free frame is available, the OS must choose an existing page to remove (victim page) to make room for the new page. The algorithm used to select the victim is the page replacement algorithm.
1. FIFO — First In First Out:
Replace the page that has been in memory the LONGEST (loaded first, removed first). Implemented using a simple queue.
Problem: Belady's Anomaly — adding MORE frames can actually INCREASE page faults with FIFO. This is a unique, counter-intuitive flaw.
2. Optimal (MIN) Algorithm:
Replace the page that will NOT BE USED for the LONGEST TIME in the future.
Advantage: Gives minimum possible page faults (theoretical best).
Problem: Impossible to implement in practice — needs to know future references. Used ONLY as a benchmark for comparison.
3. LRU — Least Recently Used:
Replace the page that has NOT BEEN USED for the LONGEST TIME in the PAST. A practical, excellent approximation of Optimal.
No Belady's Anomaly. Implementation: use a counter or a stack of page references.

What is shell? How many types of shell are used in UNIX? Describe each type in detail.

📌 Introduction: Without a shell, a user would need raw system calls to talk to the OS kernel — impractical for humans. The shell is the command-line interface that makes the OS usable. It has been asked as a full 12-mark question in 5 consecutive years (2014-2019), making it the single most reliably repeated question in the entire BCA-205 paper.
📖 Definition: A shell is a program that provides a command-line interface between the user and the operating system kernel. It reads commands typed by the user, interprets them, and instructs the kernel to carry them out. The shell is both a command interpreter and a programming language (shell scripting).
Role of Shell in OS:
USER → types command → SHELL (interprets) → KERNEL (executes) → HARDWARE
Types of Shell in UNIX/Linux:
1. Bourne Shell (sh)
• Developed by Stephen Bourne at Bell Labs, AT&T, 1977.
• The FIRST UNIX shell (always asked in MCQ/fill-in!).
• Simple, fast, highly portable — works on every UNIX system.
• Forms the basis of ALL shell scripting syntax still used today.
• Prompt: $
• Limitation: no command history, no aliases.
2. C Shell (csh)
• Developed by Bill Joy at UC Berkeley.
• Uses C-like syntax — familiar to C programmers.
• Introduced: command history (!!, !n), aliases, job control.
• Prompt: %
• Problem: scripting is less powerful than Bourne shell.
3. Korn Shell (ksh)
• Developed by David Korn at Bell Labs.
• Combines the best of Bourne + C shells.
• Supports: command history, aliases, arrays, better scripting, floating-point arithmetic.
• Prompt: $
• Upward compatible with Bourne shell (sh scripts run in ksh).
4. Bash (Bourne Again Shell)
• Developed by Brian Fox for GNU Project, 1989.
• Default shell on almost all modern Linux systems (Ubuntu, CentOS, etc.).
• A SUPERSET of Bourne shell — all sh scripts run in bash.
• Features: command-line editing, command history, tab completion, job control, arrays, arithmetic.
• Prompt: $
• Most powerful and widely used shell today.

Discuss the features, advantages, disadvantages and components of Linux. Explain Linux Process and Thread Management.
▼
📌 Introduction: Linux is an open-source, UNIX-like operating system kernel first developed by Linus Torvalds in 1991. A complete Linux system (called a distribution, e.g. Ubuntu) combines the kernel with shells, file systems, libraries, utilities, and desktop applications.
Features of Linux:
  1. Multiuser: Multiple users can log in and work simultaneously with complete isolation. Each user has their own home directory and permissions.
  2. Multitasking: Many processes run concurrently on the same hardware. CPU scheduler distributes time among all running processes.
  3. Open Source: Full source code is publicly available at kernel.org. Anyone can study, modify, and redistribute it under the GPL licence.
  4. Portable: Runs on virtually any hardware — from tiny embedded microcontrollers to the world's fastest supercomputers.
  5. Secure: Strong permission model, file ownership system, and rapid community security patching within hours of vulnerability discovery.
  6. Hierarchical File System: Everything — files, devices, network connections — appears under one root (/) directory tree.
  7. Networking: Built-in TCP/IP networking stack, internet-ready from the first installation.
Advantages of Linux:
  1. Free of cost — no licence fee, unlike Windows.
  2. Stable and reliable — Linux servers run for years without rebooting.
  3. Highly customisable — users can modify and rebuild the kernel itself.
  4. Huge community support — millions of developers, vast free documentation.
  5. Runs on old hardware that Windows cannot support.
Disadvantages / Drawbacks of Linux:
  1. Steeper learning curve for users coming from Windows.
  2. Some proprietary hardware lacks Linux drivers (e.g. certain graphics cards, printers).
  3. Fewer commercial games and professional applications compared to Windows.
  4. Fragmentation — hundreds of different distributions (Ubuntu, Fedora, Arch) can confuse beginners.
5 Components of Linux:

Linux Process Management:
  1. Every process has a unique PID (Process ID) and a PPID (Parent PID).
  2. init/systemd (PID 1) is the ancestor of EVERY other process on the system.
  3. fork() — creates a near-identical copy (child process) of the parent.
  4. exec() — loads a new program into the child process created by fork().
  5. CFS (Completely Fair Scheduler) — Linux's default CPU scheduling policy, giving each process a fair share of CPU time.
  6. ps, top, kill — everyday commands to view and manage running processes.
Linux Thread Management:
  1. Linux threads are created using the clone() system call.
  2. Clone() creates a process that can share the parent's memory space, file descriptors, and other resources — making threads very lightweight.
  3. POSIX Pthreads library provides a standard API for creating and managing threads in C programs.
  4. Threads are much cheaper to create and switch between than full processes, since they share the same address space.
💡 Example: When you type ls in a terminal, the shell (bash) calls fork() to create a child process, then exec() to load the ls program into that child. The child runs ls, prints the output, and exits. The parent (bash) waits and then shows the next prompt.
✍️ Conclusion: Linux dominates servers, cloud infrastructure, Android smartphones, and supercomputers because of its stability, security, zero cost, and open-source nature. DifferentialAll files changed since LAST FULL BACKUPMediumEasy — need only full + latest differential
Common Backup Tools:
  • tar — archive and compress: tar -czf backup.tar.gz /home
  • rsync — efficient, copies only changed files
  • cpio — copy files to/from archives
💡 Best practice: Full backup every Sunday + Incremental every other day. ⚠️ Golden Rule: ALWAYS test that your backup can actually be restored. An untested backup is NOT a backup!
✍️ A disciplined backup and restoration plan is the final safety net of system administration. Differential gives the best balance of speed and ease of restoration.

12M 🔥 PYQ 2016 Q7(c) | 2017 Q7(c) | 2022 Q7 — EXACT SAME QUESTION THREE TIMES
Discuss the role of the UNIX System Administrator in detail. What are the main responsibilities? Also explain the process of installing Linux.
▼
📌 Introduction: A UNIX/Linux System Administrator (sysadmin) is the person responsible for managing, maintaining, securing, and optimising the operating system and all services running on it. The sysadmin has root (superuser) access — they have complete control over the entire system.
📖 Definition: A UNIX System Administrator is a trained professional who installs, configures, and maintains UNIX/Linux operating systems and their associated software, ensuring continuous, secure, and reliable operation for all users.
Main Responsibilities of a UNIX System Administrator: 1. User Account Management:
  • Create, modify, delete user accounts and groups.
  • Commands: useradd username, usermod -aG group user, userdel -r user, passwd username.
  • Config files: /etc/passwd (user accounts), /etc/group (group membership), /etc/shadow (encrypted passwords).
2. Software Management:
  • Install, update, and remove software packages.
  • Commands: apt install package, apt remove package, apt update && apt upgrade.
3. File System Management:
  • Create partitions, format, mount and unmount storage devices.
  • Monitor disk space and health.
  • Commands: mkfs.ext4 /dev/sdb1, mount /dev/sdb1 /mnt, umount /mnt, df -h, du -sh.
  • Config: /etc/fstab — lists auto-mount configuration for every boot.
4. System Monitoring:
  • Monitor CPU, memory, disk, and network usage.
  • Monitor running processes and kill misbehaving ones.
  • Check system logs for errors and intrusion attempts.
  • Commands: top, ps -ef, free -h, dmesg, journalctl.
5. Backup and Restoration:
  • Plan, schedule, and execute regular backups of critical data.
  • Test that backups can actually be restored (vital!).
  • Types: Full (all data), Incremental (since last backup), Differential (since last full backup).
  • Tools: tar, rsync, cpio.
6. Network Configuration:
  • Set up network interfaces, IP addresses, DNS servers, default gateway.
  • Configure and manage firewall rules (iptables, firewalld, ufw).
7. Security Management:
  • Enforce strong password policies.
  • Manage file and directory permissions (chmod, chown, chgrp).
  • Monitor for unauthorised access and intrusion attempts.
  • Keep the system patched — apply security updates promptly.
  • Disable unnecessary services and ports.
8. Boot Management:
  • Configure and manage the bootloader (GRUB).
  • Understand the boot sequence for troubleshooting.
Boot Sequence of Linux:
Step 1 — BIOS/UEFI: Hardware self-test (POST), finds bootable device.
Step 2 — GRUB Bootloader: Presents boot menu, loads selected kernel.
Step 3 — Linux Kernel: Initialises hardware, mounts root filesystem.
Step 4 — init/systemd (PID 1): Starts all system services in correct order.
Step 5 — Login Prompt: System ready for user login.
Installing Linux — Step-by-Step Process:
  1. Choose Installation Method: Bootable USB drive, DVD, or network install (PXE boot over LAN).
  2. Choose Installation Class: Minimal (server, no GUI), Full Desktop (with GNOME/KDE), or Custom (select packages manually).
  3. Pre-installation Checks: Verify hardware compatibility, check available disk space (minimum 20 GB recommended), BACK UP all existing important data.
  4. Installation: Boot from installation media, partition the disk (/ root partition + swap partition + /home), format partitions, select software packages, configure timezone and language.
  5. Booting: Install GRUB bootloader on the MBR/EFI partition. Set boot order in BIOS. System will boot to Linux on next restart.
💡 Real Example: A college lab administrator's daily tasks: creating student accounts at the start of semester (useradd), running weekly tar backups of /home, checking auth.log for failed login attempts, and applying security patches when notified by the Linux security team.
✍️ Conclusion: The UNIX System Administrator is the most critical role in any Linux environment. Their work spans user management, software, monitoring, security, backup, and networking. Without a skilled sysadmin, even the best hardware and software will fail.
